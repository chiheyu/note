## 一、操作系统的概念、功能与特征（“宏观全景”）

### 1. 操作系统的概念与本质
操作系统（Operating System, OS）是指控制和管理整个计算机系统的硬件和软件资源，并合理地组织调度计算机的工作和资源的分配，以提供给用户和其他软件方便的接口和环境，它是计算机系统中最基本的**系统软件**。
* **硬件视角的本质：** 操作系统是硬件资源的**大管家**（自下而上），负责管理 CPU、内存、文件、设备等，让硬件高效运转。
* **用户视角的本质：** 操作系统是为用户和应用程序提供**服务和接口**的平台（自上而下），隐藏了底层的硬件复杂性，提供了一台“裸机”之上的虚拟机。

### 2. 操作系统的三大功能（作为“大管家”和“服务员”）
1. **作为系统资源的管理者：**
   * **处理机管理：** 核心内容包括进程控制、进程同步、进程通信、死锁处理、处理机调度。（决定哪个程序使用 CPU）
   * **存储器管理：** 核心功能包括内存分配与回收、地址转换（逻辑地址到物理地址）、内存保护和内存扩充（虚拟内存）。
   * **文件管理：** 核心功能包括文件存储空间的管理、目录管理、文件读写管理和保护。
   * **设备管理：** 核心功能是完成用户的 I/O 请求，包括缓冲管理、设备分配、设备处理（驱动）和虚拟设备功能。
2. **作为用户和计算机硬件之间的接口：**
   * **命令接口：** 分为联机命令接口（如 Windows 的 cmd，交互式）和脱机命令接口（如批处理系统中的 `.bat` 文件，非交互式）。
   * **程序接口：** 由一组**系统调用（System Call，也称广义指令）**组成，供用户程序在执行中调用操作系统的服务。
   * **图形用户界面（GUI）：** 现代操作系统普遍提供的直观操作界面。
3. **作为扩充机器：** 将没有任何软件支持的物理计算机（裸机）改造成功能强大、使用方便的虚拟机。

### 3. 操作系统的四个基本特征（408高频核心考点）
* **并发（Concurrency）：** 两个或多个事件在**同一时间间隔内**发生。宏观上多个程序同时运行，微观上交替执行。（**易错：并行 Parallelism** 是指两个或多个事件在**同一时刻**发生，通常需要多核 CPU）。
* **共享（Sharing）：** 系统中的资源可供内存中多个并发执行的进程共同使用。
  * **互斥共享：** 资源在一段时间内只允许一个进程访问（如摄像头、打印机、临界区变量）。
  * **同时访问：** 允许在一段时间内由多个进程“宏观上同时、微观上交替”访问（如磁盘、可重入代码）。
  * *(注：**并发和共享**是操作系统最基本的两个特征，两者互为存在条件。)*
* **虚拟（Virtual）：** 把一个物理上的实体变为若干个逻辑上的对应物。
  * **时分复用：** 如虚拟处理器（多道程序设计），让每个用户感觉自己独占 CPU。
  * **空分复用：** 如虚拟存储器（虚拟内存），让程序以为自己拥有比实际物理内存大得多的空间。
* **异步（Asynchrony）：** 在多道程序环境下，允许多个程序并发执行，但由于资源有限，进程的执行不是一贯到底的，而是走走停停的，以不可预知的速度向前推进。

## 二、操作系统的发展与分类

### 1. 手工操作阶段
* 用户独占全机，CPU 等待人工操作（纸带打孔），**人机矛盾尖锐，CPU 资源利用率极低**。

### 2. 批处理系统阶段
* **单道批处理系统：** 引入脱机输入/输出技术。每次主机内存中仅存放一道作业，运行结束后才能调入下一道。**特征：** 自动性、顺序性、单道性。**缺点：** CPU 依然有大量时间在等待 I/O，利用率不高。
* **多道批处理系统（操作系统的正式诞生）：** 允许多个程序同时进入内存并允许它们在 CPU 中交替运行。当一道程序等待 I/O 时，CPU 立即转去执行另一道程序。
  * **优点：** 资源利用率极高，系统吞吐量大。
  * **缺点：** 用户响应时间长，**不提供人机交互能力**。

### 3. 分时操作系统
* 把处理机的运行时间分成很短的时间片，按时间片轮流把处理机分配给各联机作业使用。
* **特征：** * **同时性：** 多人同时使用。
  * **交互性：** 用户可以通过终端与系统交互（解决了多道批处理的痛点）。
  * **独立性：** 用户彼此独立，感觉独占机器。
  * **及时性：** 用户请求能在很短时间内获得响应。

### 4. 实时操作系统
* 系统能及时响应外部事件的请求，在**规定的严格时间内**完成对该事件的处理。
* **硬实时系统：** 必须在绝对严格的规定时间内完成处理（如导弹控制、航空航天）。
* **软实时系统：** 能够接受偶尔违反时间规定（如视频订票系统、视频播放）。

## 三、操作系统的运行环境（核心重灾区）

### 1. CPU 的运行模式：用户态与内核态
* **内核态（核心态、管态）：** 操作系统内核运行的状态，拥有最高权限，可以执行所有指令（包括特权指令），可以访问所有物理内存和设备。
* **用户态（目态）：** 应用程序运行的状态，权限受限。不能执行特权指令，只能访问分配给该程序的内存。
* **特权指令 vs 非特权指令：**
  * **特权指令：** 只能在内核态下执行的指令，如：清内存、设置时钟、分配系统资源、修改 PSW（程序状态字寄存器）、执行 I/O 指令。
  * **非特权指令：** 算术运算、普通的访存指令、条件转移指令等。
* **状态切换：**
  * **内核态 $\to$ 用户态：** 执行一条**特权指令**（修改 PSW），将 CPU 状态设为用户态。这是操作系统主动让出 CPU。
  * **用户态 $\to$ 内核态：** **唯一途径是发生中断或异常！** 硬件自动完成状态切换（不可由软件自行完成，否则不安全）。

### 2. 中断与异常机制（内/外中断）
引入中断的目的是为了支持多道程序并发执行，并在遇到问题或需要 OS 服务时夺回 CPU 控制权。
* **中断（外中断 / 硬件中断）：** 来自 CPU 执行指令**外部**的事件，通常与当前执行的指令无关。
  * 例如：I/O 设备完成中断、时钟中断（用于时间片轮转）、外部信号中断。
* **异常（内中断 / 软件中断 / 陷入）：** 来自 CPU 执行指令**内部**的事件，与当前执行的指令有关。
  * **陷入 (Trap)：** 有意而为之的异常，主要用于**系统调用**（汇编指令 `int` 或 `trap`）。执行完毕后返回下一条指令。
  * **故障 (Fault)：** 错误条件引起的，**可能被故障处理程序修复**。如：缺页中断（Page Fault）。修复后返回发生故障的**当前指令**重新执行。
  * **终止 (Abort)：** 发生了不可恢复的致命错误（如除数为零、非法操作码）。直接终止进程，不返回。

### 3. 系统调用 (System Call)
系统调用是应用程序请求操作系统内核服务的唯一方式。凡是与共享资源有关的操作（如文件读写、设备分配、进程控制）都必须通过系统调用来实现。
* **执行过程（必须掌握）：**
  1. 用户程序在用户态将参数压栈或放入寄存器。
  2. 执行**陷入指令（Trap/Int指令）**，引发内中断。（注意：陷入指令是在**用户态**执行的）。
  3. 硬件自动将 CPU 切换到**内核态**，保存现场。
  4. 操作系统根据系统调用号执行相应的内核服务程序。
  5. 恢复现场，将 CPU 切回用户态，返回用户程序。
* **库函数与系统调用的区别：** 库函数（如 C 语言的 `printf`）是高级语言提供的，它在底层通常会封装一个或多个系统调用（如 `write`），但并非所有库函数都会引起系统调用（如 `abs()` 求绝对值只在用户态执行）。

### 4. 程序的链接与装入
* **链接 (Linking)：** 将编译后形成的目标模块及所需的库函数连接在一起，形成完整的可执行程序。
  * 静态链接：运行前完整链接。
  * 装入时动态链接：边装入边链接。
  * 运行时动态链接：执行到所需模块时才进行链接（便于代码共享和更新）。
* **装入 (Loading)：** 将程序装入内存。
  * 绝对装入：编译时确定绝对地址（只适用于单道程序）。
  * 可重定位装入（静态重定位）：装入时修改地址，装入后不能在内存中移动。
  * **动态运行时装入（动态重定位）：** 现代 OS 常用，利用**重定位寄存器**，在指令真正执行时才将逻辑地址转换为物理地址。允许程序在内存中移动。

## 四、操作系统的体系结构

### 1. 宏内核 (Monolithic Kernel) vs 微内核 (Microkernel)

| 比较维度 | 宏内核 (Macrokernel/Monolithic) | 微内核 (Microkernel) |
| :--- | :--- | :--- |
| **包含功能** | 进程调度、内存管理、文件系统、设备驱动等全部放入内核 | 内核仅保留最核心功能（时钟管理、中断、基本进程/内存调度），其他均在用户态作为服务进程运行 |
| **性能** | **极高**（内部调用直接共享内存，无状态切换开销） | **较低**（服务间通信需借助内核消息传递，频繁切换用户态/内核态） |
| **可靠性/安全性**| **较低**（一个驱动崩溃可能导致整个系统崩溃） | **极高**（一个服务崩溃不影响内核及其他服务） |
| **可扩展性** | 较差，修改内核需重新编译整体 | 极好，只需增加或替换对应的用户态服务进程 |
| **典型代表** | Linux, UNIX | 鸿蒙 OS (HarmonyOS), Minix, 早期 Windows NT |

### 2. 分层结构与模块化结构
* **分层结构：** 自下而上逐层构建，每一层只能调用其紧邻的下层提供的服务。优点：易于调试和验证。缺点：效率低下（调用层层嵌套）。
* **模块化结构：** 将 OS 按功能划分为若干具有一定独立性的模块。优点：开发快。缺点：模块间依赖关系复杂，可能出现循环依赖。

### 3. 外核 (Exokernel)
内核不提供传统操作系统的硬件抽象，而是**分配物理硬件资源的访问权限**，将资源管理和硬件抽象的任务交给了运行在用户态的库操作系统（LibOS）。优点：极致的应用性能定制。缺点：设计极度复杂。

## 五、操作系统引导 (Booting)

计算机开机加电后的启动过程是一个“拔靴带（Bootstrapping）”的过程，即小段代码拉起大段代码：
1. **执行 ROM 中的 BIOS 固件程序：** 完成硬件自检（POST），并初始化部分基本硬件设备。
2. **加载主引导记录 (MBR)：** BIOS 根据启动顺序查找启动盘，读取其第一个扇区（MBR，包含磁盘引导程序和分区表）进入内存。
3. **加载引导记录 (PBR/VBR)：** MBR 根据分区表找到**活动分区（如 C 盘）**，读取该分区的引导扇区（存放有引导加载程序 Bootloader，如 GRUB/NTLDR）。
4. **加载操作系统内核：** Bootloader 负责在文件系统中定位操作系统内核文件，将其完整读入内存并启动。
5. **操作系统初始化：** 内核接管计算机，初始化各类数据结构，创建首个进程，提供各种系统服务。

## 六、虚拟机 (Virtual Machine)

通过软件模拟硬件的执行环境，提供一种“虚拟化”的计算机系统。

| 特性 | 第一类虚拟机管理程序 (Type 1 / 裸机型) | 第二类虚拟机管理程序 (Type 2 / 宿主型) |
| :--- | :--- | :--- |
| **运行位置** | **直接运行在物理硬件之上** | 运行在**宿主操作系统 (Host OS)** 之上 |
| **资源分配** | VMM 直接管理分配硬件资源 | VMM 作为宿主 OS 的一个应用程序请求资源 |
| **性能** | **极高**，接近物理机（适合企业级服务器） | 较低，有宿主 OS 的中间开销（适合个人PC） |
| **举例** | VMware ESXi, Xen | VMware Workstation, VirtualBox |

## 七、408 考研高频易错点与防坑指南

1. **陷阱：所有应用程序都可以进行系统调用吗？**
   * **正解：** 是的，系统调用是 OS 向应用程序开放的唯一合法资源申请入口。
2. **概念辨析：特权指令 vs 广义指令**
   * **特权指令：** 硬件层面的机器指令，只能在内核态执行（如关中断）。
   * **广义指令：** 就是系统调用，它是软件层面的概念。调用广义指令的代码在用户态，但其底层执行逻辑在内核态。**（执行陷入指令在用户态，陷入后的服务在内核态）**。
3. **陷阱：只要发生异常或中断，就一定会切换到内核态吗？**
   * **正解：** **绝对一定！** 中断和异常是触发状态切换的唯一硬件机制。中断隐指令（硬件电路）会自动将 CPU 状态字改为内核态。
4. **陷阱：缺页中断属于哪种异常？发生缺页中断时，原指令直接作废吗？**
   * **正解：** 缺页中断属于**故障 (Fault)**。它发生在指令**执行期间**（而不是指令周期结束时）。操作系统调页成功后，**必须返回原指令重新执行**，而不是执行下一条指令。
5. **判断题常考：“操作系统是系统软件，不依赖于特定硬件。”**
   * **错！** 操作系统是最底层依赖硬件的软件。它必须针对特定的指令集架构（ISA，如 x86, ARM）进行编译和适配。
6. **逻辑梳理：陷入指令（Trap）是谁发出的？**
   * **正解：** 陷入指令是用户态程序在代码中**主动**写好的（或者编译器封装好的），它的执行是在**用户态**，执行完毕瞬间硬件介入，强行切换至内核态。

## 八、本章核心结论清单总结

* **OS 双重身份：** 硬件的管理者，用户的服务者。
* **两大最基本特征：** 并发、共享。
* **态的转换：** 用户态到内核态靠**中断/异常**（硬件自动完成），内核态到用户态靠**特权指令**（OS主动让权）。
* **中断分类：** 外中断（时钟、I/O，与指令无关），内中断（陷入、故障、终止，与当前指令强相关）。
* **核心架构差异：** 宏内核性能无敌但庞大易崩，微内核安全可靠但通信开销大。
* **库函数与系统调用：** 库函数 $\ge$ 系统调用。涉及内核资源申请的库函数底层必定封装了系统调用。
