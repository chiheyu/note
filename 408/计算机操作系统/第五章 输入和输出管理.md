## 一、I/O 管理的基本概念与功能（“宏观全景”）

### 1. I/O 管理在解决什么问题
外部设备种类繁多、处理速度慢、控制方式各异。操作系统通过 I/O 系统（I/O 子系统）来管理这些设备，其核心目标是：
* **掩盖物理设备的细节：** 向上层提供统一、标准的操作接口（如 `read`, `write`）。
* **协调处理机与外设的极大的速度差异：** 采用缓冲技术、中断技术、DMA 技术等，提高系统资源的并发度和利用率。
* **设备的分配与回收：** 按某种策略将共享设备分配给请求的进程。

### 2. I/O 设备的分类
* **按信息交换单位（核心分类）：**
  * **块设备 (Block Device)：** 数据传输以“数据块”为单位（如磁盘、SSD）。传输速率较高，**通常支持可寻址（随机访问）**。
  * **字符设备 (Character Device)：** 数据传输以“字符”为单位（如键盘、鼠标、打印机）。传输速率较慢，**通常不可寻址（只能顺序访问）**，常采用中断驱动方式。
* **按设备共享属性：**
  * **独占设备：** 一段时间内仅允许一个进程使用的设备（如打印机）。
  * **共享设备：** 一段时间内允许多个进程“宏观上同时、微观上交替”使用的设备（如磁盘）。
  * **虚拟设备：** 通过 SPOOLing 技术将独占设备改造为逻辑上的共享设备。

### 3. I/O 接口（设备控制器）

- **基本概念**：CPU 与外设之间的桥梁，位于系统总线与外部设备之间，负责协调主机与外设间的数据传输与控制。
- **主要功能**：
  - **接收和识别 CPU 命令**：具有控制寄存器与命令译码器，CPU 写入控制命令后控制外设执行。
  - **向 CPU 反映设备状态**：具有状态寄存器，记录外设的“忙”、“就绪”、“错误”等状态供 CPU 读取。
  - **数据交换与缓冲**：通过内部**数据缓冲寄存器 (DBR)** 暂存数据，缓解高速 CPU 与低速外设间的速度不匹配。
  - **地址识别**：利用地址译码器识别 CPU 发出的寄存器地址，使得 CPU 能精确访问控制器中的指定端口。
  - **数据格式转换与差错控制**：负责串-并转换、电平转换及校验码校验（如 CRC/奇偶校验）。
- **组成结构**：
  - **与 CPU 的接口**：包括数据线（双向传输数据/状态/命令）、地址线（选择端口）、控制线（读/写/中断请求信号）。
  - **I/O 逻辑**：实现地址译码及控制逻辑，负责处理 CPU 指令并控制外设。
  - **与设备的接口**：包括数据传输线、状态信号线与控制信号线。
![](assets/第五章%20输入和输出管理/file-20260907.png)

### 4. I/O 接口的类型

- **按数据传输方式分类**：
  - **并行接口**：多位（如 8 位、16 位）数据同时传输，传输速率高，适合近距离传输（如打印机并口）。
  - **串行接口**：按位一位一位依次传输，连线少、抗干扰强，适合长距离传输（如 USB、SATA）。
- **按主机访问控制方式分类**：
  - **程序查询型接口**：无中断能力，CPU 需通过轮询读取状态端口以确认设备是否就绪。
  - **中断控制型接口**：设备就绪后主动向 CPU 发送中断请求信号，省去 CPU 轮询开销。
  - **DMA 控制型接口**：接口内集成 DMA 控制器，可直接与主存批量交换整块数据，无需 CPU 逐字搬运。
- **按功能灵活性分类**：
  - **可编程接口**：工作模式与中断属性可通过写入控制字动态配置（如可编程中断控制器 8259A、并行接口 8255）。
  - **不可编程接口**：内部逻辑固化，功能与传输模式固定。

### 5. I/O 端口及其编址方式

- **I/O 端口的概念**：I/O 接口内**能被 CPU 直接读写的各类寄存器**。
  - **数据端口**：存放从外设输入或待输出到外设的数据（CPU 可读可写）。
  - **状态端口**：存放外设当前的运行状态标志（CPU 仅读）。
  - **控制端口**：存放 CPU 控制外设操作的命令参数（CPU 仅写）。
- **两类编址方式（408 极高频必考）**：
  - **统一编址（存储器映射 I/O / Memory-Mapped I/O）**：
    - **原理**：将 I/O 端口地址视为物理内存地址空间的一部分，与主存统一编排地址。
    - **访问指令**：使用统一的**常规访存指令**（如 `MOV`、`LOAD`、`STORE`），无需专门的 I/O 指令。
    - **优点**：寻址灵活、指令集统一，CPU 硬件无需单独的 I/O 控制引脚。
    - **缺点**：占用主存物理地址空间；由于译码电路需覆盖整个内存空间，访问速度较慢。
    - **典型架构**：ARM、RISC-V、MIPS。
  - **独立编址（端口映射 I/O / Isolated I/O）**：
    - **原理**：I/O 端口拥有完全独立的地址空间，与主存地址空间物理隔离，两者的地址数值可以完全重叠。
    - **访问指令**：必须使用**专门的 I/O 指令**（如 x86 的 `IN`、`OUT` 指令）。
    - **优点**：不占用主存地址空间；I/O 地址线少，译码电路简单、寻址速度快；程序可读性好。
    - **缺点**：I/O 指令功能单一，寻址方式贫乏；CPU 必须提供专门的区分访存与访 I/O 的控制引脚（如 $\text{M}/\overline{\text{IO}}$ 信号线）。
    - **典型架构**：Intel x86。

## 二、I/O 控制方式（408极高频演进史）

I/O 控制方式的演进，本质上是**不断减少 CPU 对 I/O 操作的干预，将 CPU 从繁重的 I/O 等待中解放出来**的过程。

### 1. 程序直接控制方式（轮询 / 忙等）
* **机制：** CPU 发出 I/O 指令后，**不断地循环测试**设备的状态寄存器，直到设备准备好。
* **数据传送单位：** 每次读写一个字。
* **优缺点：** 极简单；但 CPU 利用率极低（长期处于“忙等”状态），CPU 与外设只能串行工作。

### 2. 中断驱动方式
* **机制：** 允许 I/O 设备主动打断 CPU。CPU 发出 I/O 命令后可转去执行其他进程。设备完成一次数据传输准备后，向 CPU 发出中断请求，CPU 暂停当前工作，转去执行中断服务程序。
* **数据传送单位：** 每次读写一个字。
* **优缺点：** CPU 与外设可并行工作；但如果外设速度很快，每传一个字就中断一次 CPU，CPU 依然会被频繁打断。

### 3. DMA (直接存储器存取) 方式
* **机制：** 在外设和主存之间开辟一条直接数据通路。**数据传送完全由硬件（DMA 控制器）控制，不需要 CPU 介入计算和数据搬运。**
* **基本特征（必考点）：**
  1. 数据传输的基本单位是**数据块**。
  2. 数据是从设备**直接送入主存**（或者相反）。
  3. 仅在传送一个或多个数据块的**开始和结束**时，才需要 CPU 干预。
* **周期窃取（窃取 CPU 访存周期）：** 当 DMA 和 CPU 同时争用主存总线时，通常 DMA 优先级更高，CPU 暂停一个存取周期让给 DMA。
![](assets/第五章%20输入和输出管理/file-20260907%201.png)
### 4. 通道控制方式（I/O 处理机）（了解即可）
* **机制：** 通道是一种硬件，是**弱化版的 CPU**（只有少数与 I/O 相关的指令）。CPU 向通道发出 I/O 指令（指明通道程序在内存的位置、操作的外设），通道接管后独立执行通道程序，控制多次 I/O 操作。
* **数据传送单位：** 一组数据块。
* **与 DMA 的区别：** DMA 每次只能执行一条 I/O 指令，只能控制一台设备与内存的数据交换；通道可以执行通道程序，控制多台设备。

## 三、I/O 软件层次结构（自上而下考点映射）

操作系统的 I/O 软件通常划分为四个层次，每一层利用其下层提供的服务，完成特定功能并向上层提供接口。

| 层次 | 核心功能与负责组件 | 408 考点体现 |
| :--- | :--- | :--- |
| **4. 用户层 I/O 软件** | 库函数（如 `printf`），SPOOLing 系统（假脱机）。 | SPOOLing 技术是在用户层实现的。 |
| **3. 设备独立性软件** | 向上层提供统一接口；设备的命名（逻辑设备名 $\to$ 物理设备名，利用 LUT 逻辑设备表）；设备的分配与回收；缓冲管理。 | 是 I/O 系统的核心枢纽，屏蔽了底层的各种硬件差异。 |
| **2. 设备驱动程序** | 与特定硬件密切相关。负责将上层发出的命令转化为设备能识别的寄存器控制指令；检查设备状态。 | 不同厂家、不同型号的设备必须配备对应的驱动程序。 |
| **1. 中断处理程序** | 保护被中断进程的 CPU 环境，执行中断处理逻辑，唤醒等待 I/O 的进程，恢复现场。 | 位于 I/O 系统的最底层，最接近硬件。 |

*(注：硬件设备不在软件层次内。下三层统称为 I/O 核心子系统。)*

## 四、缓冲管理（必考计算题核心）

### 1. 缓冲的作用
* 缓和 CPU 与外设之间速度不匹配的矛盾。
* 减少对 CPU 的中断频率。
* 解决数据粒度不匹配的问题（如外设按字符输出，CPU 按块处理）。
* 提高CPU和I/O设备之间的并行性。

### 2. 单缓冲与双缓冲的时间计算模型（重中之重）
假设数据块输入缓冲区的时间为 $T$，缓冲区数据传送到工作区的时间为 $M$，CPU 处理工作区数据的时间为 $C$。
* **单缓冲：** 
  * 流程：输入 $\to$ 传送 $\to$ 处理。且输入缓冲区 $T$ 与传送 $M$ 不能同时进行，处理 $C$ 可以与输入 $T$ 并行。
  * 处理一块数据的平均时间：$\max(C, T) + M$
  * ![](assets/第五章%20输入和输出管理/file-20260907%203.png)
* **双缓冲：**
  * 流程：两个缓冲区交替工作。当缓冲区 1 正在往工作区传送或 CPU 正在处理时，外设可以向缓冲区 2 输入数据。
  * 处理一块数据的平均时间：$\max(C+M, T)$
  * *(注：如果题目给出具体数字 $C, M, T$，通常 $M$ 很小，双缓冲的时间就是取 $C$ 和 $T$ 的较大者。)*
  * ![](assets/第五章%20输入和输出管理/file-20260907%204.png)

### 3. 循环缓冲与缓冲池
* **循环缓冲：** 多个大小相等的缓冲区链成一个环形队列（包含空缓冲区指针$in$和满缓冲区指针$out$）。
* ![](assets/第五章%20输入和输出管理/file-20260907%205.png)
* **缓冲池 (Buffer Pool)：** 统一管理公共缓冲区块。包含：空缓冲队列、输入队列、输出队列；以及用于收容输入、提取输入、收容输出、提取输出的四种工作缓冲区。
* ![](assets/第五章%20输入和输出管理/file-20260907%206.png)

## 五、设备分配与回收

### 1. 设备分配所需的数据结构
系统按自顶向下的层级维护这四个表，构成了寻址链路：
* **SDT (系统设备表)：** 记录全系统所有设备的情况。
* **DCT (设备控制表)：** 每个设备一张。
* ![](assets/第五章%20输入和输出管理/file-20260907%208.png)
* **COCT (控制器控制表)：** 每个设备控制器一张。
* **CHCT (通道控制表)：** 每个通道一张。
![](assets/第五章%20输入和输出管理/file-20260907%209.png)

### 2. 分配原则与逻辑设备名映射
* **安全性：** 必须防止死锁。
* **LUT (逻辑设备表)：** 存放逻辑设备名到物理设备名的映射。
  * 全系统一张 LUT：不能有重名的逻辑设备。
  * 每个用户一张 LUT：允许不同用户有重名的逻辑设备（如不同用户的程序都可以把打印机叫做 `printer`）。

## 六、SPOOLing 技术（假脱机技术）

核心思想：**空间换时间，将独占设备改造为共享的虚拟设备**。

### 1. 系统的构成模块
* **输入井和输出井：** 位于**磁盘**上，用于暂时存放输入输出数据。
* **输入缓冲区和输出缓冲区：** 位于**内存**中，暂存数据，然后转移到井中或设备中。
* **输入进程和输出进程：** 模拟脱机 I/O 时的外围控制机，负责实际的读写操作。
* ![](assets/第五章%20输入和输出管理/file-20260907%2011.png)

### 2. 经典实例：共享打印机
当多个进程请求打印时：
1. 系统并不把物理打印机分配给进程。
2. 而是在**磁盘输出井**中为进程分配一段空闲区，将待打印数据写入。
3. 为用户进程申请一张空白的**用户请求打印表**，填入信息并挂到假脱机文件队列上。
4. 此时进程认为打印已完成，继续执行后续代码。真正的打印操作由打印机空闲时，输出进程按队列顺序独立完成。

> SPOOLing 技术是一种以空间换时间的技术。它通过开辟磁盘空间作为输入井和输出井，牺牲了存储空间，但显著节省了时间。磁盘是一种高速设备，其与内存交换数据的速度远高于打印机等低速设备。若无 SPOOLing 技术，CPU 向打印机输出数据时，必须等待缓慢的打印操作完成，才能继续后续工作，造成 CPU 时间的浪费。而在 SPOOLing 技术下，CPU 可将待打印数据快速写入磁盘输出井(该过程由输出进程控制)，随即继续执行其他任务。若打印机正被占用，SPOOLing系统会将该打印请求挂到等待队列上，待打印机空闲时再按序输出。由于向磁盘写入数据的速度远快于直接驱动打印机，整体 I/O 效率得以提升，CPU 与 I/O 设备实现了并行工作。

## 七、I/O 操作举例（以 scanf 为例）

### 1. 核心前置概念：双重缓冲区
- **内核缓冲区 (Kernel Buffer)**：位于内核空间，存放 OS 核心代码与数据，由所有进程共享。
- **用户缓冲区 (User Buffer)**：位于用户空间，由 C 标准库管理（如 `buf`）。
- **设置双缓冲的原因**：用户空间与内核空间地址隔离。系统调用在内核态执行，无法直接跨空间安全访问，必须先将 I/O 设备数据读入**内核缓冲区**，在系统调用返回前再复制到**用户缓冲区**。

### 2. 函数执行的两个阶段
- **第一阶段（C 标准库完成 · 用户态）**：
  - 检查关联的用户缓冲区 `buf`：若已有数据则直接读取；若为空，准备发起 `read` 系统调用。
  - 传入 3 个关键系统调用参数：
    - `fd`（文件描述符）：标识输入设备（标准输入 `stdin` 对应 `fd = 0`）。
    - `buf`（用户缓冲区指针）：用于接收从内核复制出的数据。
    - `count`（最大读取字节数）：期望读取的最大长度。
- **第二阶段（系统调用完成 · 内核态）**：
  - 执行陷入指令（如 `trap` / `int 0x80` / `syscall`），CPU 从用户态转入内核态，执行 `read` 对应的系统调用服务例程。

![](assets/第五章%20输入和输出管理/file-20260907%2012.png)

### 3. 中断驱动下的完整执行流程（以键盘输入为例）
1. **初始化并阻塞**：系统调用服务例程设置 I/O 参数，发起 I/O 的**进程 P 进入阻塞态**，CPU 调度其他就绪进程运行。
2. **字符输入**：用户敲击键盘，按键编码送入**键盘 I/O 接口的数据端口**。
3. **发出中断**：键盘 I/O 接口向 CPU 发出**硬件中断请求**。
4. **中断处理**：CPU 响应中断，转入键盘中断处理程序，从 I/O 端口读取字符并写入**内核缓冲区**。
5. **唤醒进程**：数据就绪后，**进程 P 被唤醒**，状态由阻塞态变为**就绪态**，挂入就绪队列等待调度。
6. **内核向用户拷贝**：进程 P 再次被调度获得 CPU，系统调用服务例程将数据从**内核缓冲区复制到用户缓冲区**。
7. **返回与解析**：从系统调用返回用户态，`scanf()` 对用户缓冲区中的字符进行格式解析，最终存入变量 `d`。
![](assets/第五章%20输入和输出管理/file-20260907%2013.png)

### 4. 软件层次与数据流动（408 核心考点）
- **数据流向一：I/O 端口 $\to$ 内核缓冲区**
  - **实现层次**：**设备驱动程序**（Device Driver）。
  - **原因**：直接读写具体的 I/O 硬件端口寄存器，具有强硬件相关性。
- **数据流向二：内核缓冲区 $\to$ 用户缓冲区**
  - **实现层次**：**设备独立性软件**（Device-Independent Software）。
  - **原因**：单纯的内存数据复制与缓冲区管理，与具体底层硬件细节完全无关。

![](assets/第五章%20输入和输出管理/file-20260907%2014.png)

## 八、磁盘与固态硬盘 (SSD) 管理（大题重灾区）

### 1. 磁盘的物理结构与读写时间
数据存储在同心圆的磁道上，磁道又被划分为扇区。所有的读写操作都要经历：
* **寻道时间 ($T_s$)：** 磁头移动到目标磁道（柱面）所需的时间。**耗时最长，是磁盘调度的核心优化目标**。
  $$T_s = m \times n + s$$
  （$n$ 为跨越的磁道数，$m$ 为常数，$s$ 为磁臂启动时间）。
* **旋转延迟时间 ($T_r$)：** 磁头等待目标扇区旋转到磁头下方的时间。平均值为磁盘旋转一周时间的一半。若转速为 $r$ 转/秒，则平均旋转延迟 $T_r = \frac{1}{2r}$。
* **传输时间 ($T_t$)：** 读写数据经历的时间。若每次读写 $b$ 字节，每个磁道容量为 $N$ 字节，则 $T_t = \frac{b}{rN}$。
* **总时间：** $$T_{total} = T_s + T_r + T_t$$
### 2. 磁盘调度算法（只优化寻道时间 $T_s$）
* **FCFS (先来先服务)：** 按请求顺序。公平，但寻道时间极长。
* **SSTF (最短寻道时间优先)：** 优先处理离当前磁头最近的请求。**缺点：可能导致远处的请求“饥饿”**。
* **SCAN (扫描算法 / 电梯算法)：** 磁头必须走到最边缘（如 0 或最外层）才能掉头，在途中响应请求。
* **C-SCAN (循环扫描)：** 磁头走到最边缘后，**直接快速飞回起点，返回途中不响应任何请求**。目的：让各个位置的响应时间更加均衡。
* **LOOK 与 C-LOOK：** SCAN 和 C-SCAN 的优化版。磁头只要走到**最远的那个请求位置**就可以掉头/飞回，不需要死板地走到物理边界。
* *若无特别说明，实际系统中所称的SCAN和C-SCAN算法通常指LOOK调度和C-LOOK调度。*

* **磁臂黏着 (Arm Stickiness) 现象**：
  - **概念**：在 SSTF、SCAN 等算法中，若一个或多个进程对某磁道（或相邻磁道）有持续高频的访问请求，磁盘调度会优先连续服务这些就近请求，导致磁臂长时间停留在该处“黏住不动”。
  - **危害**：使得位于远端磁道的其他进程请求被严重推迟，造成实质上的“**饥饿**”现象。
- **N-Step-SCAN (N步SCAN 算法)**：
  - **机制**：将磁盘请求队列划分为若干个长度为 $N$ 的子队列，按 **FCFS** 顺序依次处理各个子队列；而在每个子队列内部，则采用 **SCAN** 算法进行调度。
  - **防黏着原理**：在处理当前子队列的 $N$ 个请求时，新到达的 I/O 请求必须排入后续子队列中，**当前扫描过程不再响应新请求**，从而彻底消除磁臂黏着。
  - **极端特性**：
    - 当 $N=1$ 时：退化为普通的 **FCFS** 算法；
    - 当 $N \to \infty$（$N$ 很大）时：退化为普通的 **SCAN** 算法。
- **FSCAN (分步SCAN 算法)**：
  - **机制**：N-Step-SCAN 的典型双队列简化版本。仅维护两个子队列：
    1. **当前队列**：存放当前扫描轮次需要处理的所有请求，按 **SCAN** 算法执行。
    2. **等待队列**：在本次扫描处理期间新到达的所有请求均直接进入该队列，留待下一轮扫描处理。
  - **特点**：实现开销比 N-Step-SCAN 更低，兼顾 SCAN 的高吞吐量与 FCFS 的防饥饿特性。


### 3. 减少旋转延迟的物理优化
连续读取同一磁道上的逻辑连续扇区时，由于读完一个扇区后磁盘控制器需要一定时间处理数据，这期间盘片仍在旋转，可能导致错过下一个扇区。
* **交替编号（交叉因子）：** 对扇区进行交替编号（如 0, 2, 4, 1, 3, 5），给系统留出处理时间。
* **错位命名：** 对不同盘面（同柱面）的同一扇区编号进行错位，保证在跨盘面读写时，磁头电子切换的瞬间，下一个扇区刚好转到磁头下。

### 4. 固态硬盘 (SSD)
基于闪存 (Flash Memory) 技术，没有机械结构。
* **读写特性：** 随机访问速度极快。**数据写入前必须先擦除（Erase）**。
* **粒度不对称：** **以页 (Page) 为单位读写**（通常 4KB），但**以块 (Block) 为单位擦除**（一个块包含若干页）。因此，修改极小的数据也会引起“读出整个块 $\to$ 修改 $\to$ 擦除原块 $\to$ 写入新块”的巨大开销。
* **磨损均衡 (Wear Leveling)：** 闪存有擦写寿命限制。闪存翻译层 (FTL) 通过算法让擦除操作平均分布在各个块上。
  * **动态磨损均衡：** 写入新数据时，挑比较新的空闲块。
  * **静态磨损均衡（更优）：** 在后台主动把不常更新的“冷数据”搬到旧块里，把新块腾出来给频繁更新的“热数据”用。

## 九、首轮复习高频陷阱防范

1. **陷阱：DMA 完全不需要 CPU 干预吗？**
   * **错！** CPU 必须负责发送 I/O 开始指令（初始化外存地址、内存地址、传输字节数），并在结束时处理 DMA 发生的中断。
2. **陷阱：设备独立性软件负责将逻辑地址映射为物理地址吗？**
   * **错！** 那是内存管理干的事。设备独立性软件负责的是**逻辑设备名映射为物理设备名**。
3. **概念辨析：单缓冲 vs 双缓冲的应用场景**
   * 考试常问“设备向内存输入数据极快，但 CPU 处理数据很慢，双缓冲有用吗？”
   * **正解：不管谁快谁慢，双缓冲都能掩盖一部分时间，必定有用。** 只是它无法彻底解决生产消费速度不均衡造成的阻塞（那是缓冲池解决的问题）。
4. **陷阱：SSTF 算法和 SJF (短作业优先) 一样，是最优算法吗？**
   * **错！** SSTF 只能保证每一次寻道最优（局部最优），不能保证全局总寻道时间最短，且会导致极严重的“饥饿”现象。
5. **SSD 的核心考法：** 牢记 SSD “按页读写，按块擦除”，以及“写慢读快，写前必擦除”的特性。

## 十、本章核心结论清单总结

* **I/O 演进核心：** 轮询 (全靠 CPU) $\to$ 中断 (按字中断) $\to$ DMA (按块传输，首尾干预) $\to$ 通道 (执行程序，完全独立)。
* **层次划分：** 与具体硬件相关的全在**设备驱动程序**层，统一接口全在**设备独立性**层。
* **假脱机 SPOOLing：** 利用磁盘作为井，通过软件模拟外围机，把独占设备变成虚拟共享设备。
* **磁盘时间计算：** 寻道时间 (硬件机械移动) 占绝对大头，是各种调度算法（SCAN/LOOK等）唯一能优化的指标。
* **SSD 寿命护航：** 依靠 FTL 层的磨损均衡（静态最优）来解决局部单元频繁擦写致死的问题。
