## 一、总线的基本概念与结构（“信息的高速公路”）

### 1. 为什么需要总线
早期计算机采用**分散连接**（各部件之间有单独连线），导致线路极其复杂、扩展困难。
引入**总线 (Bus)** 后，可以*提升带宽、降低延迟、打破通信瓶颈*，多个部件共享一组公共信息传输线路。
* **分时性：** 同一时刻只能有一个部件向总线发送信息。
* **共享性：** 总线上的所有部件都可以从总线上接收信息。

### 2. 总线的分类
* **按数据传输格式：**
  * **串行总线：** 一次传输一位，抗干扰能力强，适合长距离、高速传输（如 USB, PCIe）。
  * **并行总线：** 一次传输多位，受限于信号串扰，通常只用于近距离传输（如传统 PCI）。
* **按功能与连接位置：**
  * **片内总线：** CPU 内部寄存器与 ALU 之间的连线。
  * **系统总线：** 计算机三大核心部件（CPU、主存、I/O 接口）之间的连线。又分为**数据总线 (DB)**、**地址总线 (AB)**、**控制总线 (CB)**。
  * **通信总线（外部总线）：** 计算机系统之间或与外部设备之间的总线（如 RS-232, USB）。

### 3. 多总线结构演进
* **单总线结构：** CPU、主存、I/O 全挂在一条总线上。极易形成瓶颈。
* ![](assets/第六章%20总线和输入输出系统/file-20260810.jpg)
* **双总线结构：** 增加了一条 CPU 和主存之间的**主存总线**，减轻系统总线负担。
* ![](assets/第六章%20总线和输入输出系统/file-20260810.png)
* **三总线结构：** 引入了**DMA总线**或**局部总线**。
* ![](assets/第六章%20总线和输入输出系统/file-20260810%201.png)
* **多总线架构（现代核心）：** 引入**桥接器 (Bridge)** 的概念。桥接器既是总线转换的枢纽，也具有数据缓冲功能。（如北桥连高速设备，南桥连低速外设）。
* ![](assets/第六章%20总线和输入输出系统/file-20260810%201.jpg)
   1) **北桥芯片（Memory Controller Hub，MCH）** 作为高速枢纽，连接CPU、主存和显卡，负责高带宽数据传输。
   2) **南桥芯片（I/O Controller Hub，ICH）** 是一个I/O控制器集线器，负责管理USB、SATA、以太网等低速I/O接口，并提供扩展槽支持。
* **现代集成化总线结构：**
  自 Intel Core i7 处理器起，总线结构迎来新的转变：北桥芯片的核心功能（如内存控制器）被集成到 CPU 内部，传统北桥随之消失，系统互连方式转向片上集成与点对点互连。
* ![](assets/第六章%20总线和输入输出系统/file-20260810%202.png)
  这一转变带来三大重要优势：
    * *内存访问路径缩短*。CPU 可通过片上存储器控制器直接访问主存，无须经过北桥中转。同时，普遍支持多通道 DDR 内存（如双通道、三通道），各通道并行工作，理论带宽近似为单通道的整数倍数。例如，三通道 DDR3‑1333 的峰值带宽可达单通道的3倍。
    * *处理器间高速互连*。多核 CPU 内核之间、多 CPU 芯片之间通过 QPI（QuickPath Interconnect）等点对点高速串行链路实现数据交换。QPI 不仅用于 CPU 间通信，还用于连接 CPU 与 IOH（输入/输出集线器，类似于早期的南桥），大幅提升了互连效率。
    * *I/O 通路直连*。高速外设（如显卡、SSD）通过 PCIe 通道直接接入 CPU，绕过南桥；低速设备则由集成度更高的 PCH（Platform Controller Hub，新一代南桥）统一管理。

## 二、总线性能指标与计算（必考核心）

### 1. 时钟频率与传输周期
* **总线时钟频率：** 即总线基础时钟信号的频率，是总线时钟周期的倒数。早期总线的时钟与CPU时钟同频，随着CPU的快速发展，现代总线的时钟通常独立于CPU时钟。
* **总线传输周期：** 完成一次完整的总线操作（申请、寻址、传输、结束）所需的时间。一个总线周期通常包含若干个时钟周期。

### 2. 带宽计算公式体系
* **总线宽度 (W)：** 数据总线的根数（如 32 位、64 位）。
* **总线工作频率 (f)：** 总线工作频率指总线每秒能进行的有效数据传输次数。若每个时钟周期传输 $N$ 次数据（如 DDR 内存上升下降沿均传输，则 $N=2$），工作频率 $f = N \times 时钟频率$。
* **总线带宽 (BW)：** 单位时间内总线上传输数据的最大字节数。
  $$BW = \frac{W}{8} \times f$$
* **总线寻址能力：** 由地址线的位数决定，表示CPU能访问的最大地址空间。例如，16位地址线可寻址2¹⁶=65536个存储单元；若每个单元为1B，则最大寻址空间为64KB。

### 3. 突发传送 (Burst Transfer)
* 正常传送：传一个地址，送一个数据。
* **突发传送：** 只需要给出第一个数据的地址，随后总线会自动传输一块连续的数据。极大提高了连续访存的效率（如 Cache 块替换）。

### 4. 串行传输和并行传输
- **并行传输**：
  - **机制**：数据的各个位在多条数据线上同时进行传输。
  - **优点**：逻辑实现简单，在低频或短距离下可以实现较高的数据传输率（一个时钟周期能传输多个数据位）。
  - **缺点**：需要占用大量引脚和数据线，成本较高；在**高频或长距离**传输时，各数据线之间容易产生**严重的电磁干扰（信号串扰）**以及信号同步问题，导致时钟频率难以进一步提升。
- **串行传输**：
  - **机制**：数据在单条数据线（或一对差分信号线）上，按位（bit）依次顺序传输。根据收发双方同步方式的不同，主要细分为以下两种：
    - **同步串行传输**：收发双方受同一时钟信号控制，数据以**数据块（帧）**为单位连续不断地发送。由于数据块内部不需要附加额外的同步位，传输效率高，适合高速传输，但控制逻辑和硬件要求较高。
    - **异步串行传输**：没有统一的同步时钟，数据以独立的**字符（通常为一个字节）**为单位进行发送。每个字符在发送时必须加上**起始位**和**停止位**（有时还包括奇偶校验位）来让接收端实现同步。实现简单，但由于附加位较多，传输开销大，有效传输率较低。
  - **总体优点**：需要的引脚和线缆极少，成本低；**抗干扰能力强**（不存在并行传输中的线间串扰），因此**工作时钟频率可以提得非常高**；非常适合长距离传输。
  - **总体缺点**：收发两端需要有额外的硬件接口进行串-并/并-串的数据格式转换。
- **408 重点注意 (发展趋势)**：
  - 早期系统内部总线（如早期内存总线、PCI等）多采用并行传输，但随着系统频率的飞速发展，并行总线的时钟偏移和串扰问题成为瓶颈。现代高速总线（如 PCIe、SATA、USB 等）已普遍采用**高速串行传输**技术来取代传统的并行传输，利用极高的时钟频率和差分信号技术来弥补单次只传1位的劣势，从而获得比并行传输大得多的总带宽。

## 三、总线仲裁（408 重点补全区）

由于同一时刻只能有一个主设备控制总线，必须有仲裁机制解决冲突。
### 1. 集中仲裁方式（由总线控制器统一管理）
* **链式查询 (Daisy Chain)：** 
  * 控制线：3 根（BR请求、BS忙、BG同意）。
  * 机制：BG 信号像串联电路一样逐个往下传。离总线控制器**越近的设备优先级越高**。
  * 优点：线少，易扩充。缺点：对电路故障极其敏感，优先级低的设备易“饿死”。
* **计数器定时查询：**
  * 控制线：增加了一组设备地址线，去掉了 BG 线。
  * 机制：控制器内部有计数器，轮询设备地址。计数器可从 0 开始（固定优先级），也可从上次终点开始（循环轮转，公平）。
* **独立请求方式：**
  * 控制线：每个设备都有一对独立的 BR 和 BG 线连到控制器。
  * 机制：控制器内部有排队器，直接决定给谁。
  * 优点：**响应速度最快**，优先级控制极灵活。缺点：控制线最多，硬件极复杂。

### 2. 分布式仲裁
没有中央仲裁器，每个潜在的主设备都有自己的仲裁号和仲裁器（如 CAN 总线），通过总线上的信号竞争决定。

## 四、总线操作与定时控制

### 1. 总线事务的五个阶段
**总线事务:** 在总线上，主设备（如 CPU、DMA 控制器）与从设备（如主存、I/O 设备）之间完成一次完整的信息交换过程，称为一个总线事务。总线事务的类型由操作性质决定，典型的包括存储器读（从主存取数据至处理器）、存储器写（向主存写入数据）、I/O 读/写、中断响应等。
*理论：* 请求阶段 $\to$ 仲裁阶段 $\to$ 寻址阶段 $\to$ 传输阶段 $\to$ 结束阶段。
每个总线事务通常包含三个基本阶段（依据历年真题）：
* **地址传送阶段：** 主设备将目标地址和操作类型（读/写）通过总线传送给从设备。
* **从设备响应阶段（也称数据准备阶段）：** 从设备根据地址准备数据（该阶段的耗时由设备特性决定，若题中未明确提及，则通常可忽略）。
* **数据传送阶段：** 完成实际数据在总线上的传输。
### 2. 总线定时方式（主从设备如何协同）
* **同步通信：** 统一时钟控制。规定在特定的时钟节拍完成特定的操作。适合**速度差异小、距离近**的设备。
* **异步通信（握手协议）：** 没有统一时钟，靠请求 (REQ) 和应答 (ACK) 信号协调。
  * **不互锁：** 主设备发 REQ，不管从设备收没收到，过一会儿就撤销。
  * **半互锁：** 主设备必须收到 ACK 才撤销 REQ；但从设备发出 ACK 后自己定时撤销。
  * **全互锁：** 严格的一问一答，双方互相确认后才撤销信号。（最可靠，速度最慢）。
  * ![](assets/第六章%20总线和输入输出系统/file-20260810%202.jpg)
* **半同步通信：** 在同步时钟的基础上，增加一条 `WAIT` 响应线。允许从设备要求主设备多等几个周期。
 > [!NOTE] 上述三种定时方式均采用*独占式事务模型*
 > 从主设备发起请求到传送结束，总线全程被该事务占用。然而，在从设备准备数据阶段，总线虽被占用却处于空闲状态，造成资源浪费。

* **分离式通信：** 将一个总线周期分为两个子周期：请求周期和应答周期。主设备发完请求后**立即释放总线**，从设备准备好数据后自己去申请总线并发送。**总线利用率最高**。

## 五、I/O 接口与端口编址

### 1. I/O 接口的内部结构
I/O 接口是 CPU 和外设之间的缓冲站。内部包含三类核心寄存器（统称 I/O 端口，端口是接口内部可寻址的寄存器）：
* **数据端口：** 缓冲数据，匹配速度。
* **状态端口：** 记录外设是否准备好、是否报错。
* **控制端口：** 接收 CPU 的控制命令（如启动、停止）。

### 2. I/O 端口的编址方式
* **统一编址 (Memory Mapped I/O)：**
  * 把 I/O 端口当作普通的内存单元来分配地址，将部分主存地址空间分配给I/O端口。
  * 优点：不需要专门的 I/O 指令，可以用所有访存指令（如 MOV, ADD）操作外设，极其灵活；不需要专门的控制线。
  * 缺点：占用内存地址空间，译码电路复杂，执行速度稍慢。
* **独立编址 (Isolated I/O)：**
  * I/O 端口有独立的地址空间（如 x86 架构）。
  * 优点：I/O 指令与访存指令有明显区别，程序清晰；不占用内存空间。
  * 缺点：需要专门的 I/O 指令（如 `IN`, `OUT`），指令类型少，必须增加控制信号线来区分是访存还是访 I/O。

## 六、I/O 控制方式（重中之重）

随着计算机发展，I/O 控制的核心目标是：**尽量解放 CPU**。

### 1. 程序查询方式（独占与定时）
* **机制：** CPU 发出 I/O 命令后，不断循环读取状态寄存器，直到外设准备就绪。
* **特点：** CPU 与外设完全**串行工作**，极度浪费 CPU 时间（“踏步”等待）。

### 2. 程序中断方式 (Interrupt)
* **机制：** CPU 发出命令后继续做自己的事。外设准备好数据后，向 CPU 发出**中断请求**。CPU 暂停当前程序，执行中断服务程序，将数据从外设读入 CPU，再写入内存。
* **特点：** CPU 与外设**部分并行**。消除了查询等待，但**数据的搬运依然要耗费 CPU 的时间和寄存器**。
* **多重中断与中断屏蔽：** 允许高优先级中断打断低优先级中断的服务程序。通过修改**中断屏蔽字 (Mask)**，可以灵活改变中断处理的优先级。

* ![](assets/第六章%20总线和输入输出系统/file-20260815%201.jpg)

### 3. DMA 方式 (Direct Memory Access)
* **机制：** 硬件级别的直接内存访问。在外设和主存之间开辟直接数据通路。DMA 控制器负责产生地址、控制总线，完全接管数据的传输。
* **CPU 参与度：** CPU 仅在**预处理**（告诉 DMA 起始地址、数据量）和**后处理**（DMA 发中断告知传完了）时参与，如校验数据完整性，若出错则转入诊断程序。**传输过程中 CPU 可以并行做其他事**。
* ![](assets/第六章%20总线和输入输出系统/file-20260815%202.jpg)

#### DMA 与主存冲突的解决方式（窃取策略）
当 CPU 和 DMA 同时要访问主存时，通常优先让给 DMA。
* **停止 CPU 访存：** DMA 传输整块数据期间，CPU 完全不能用主存（适合极高速设备）。
* **周期挪用（周期窃取）：** DMA 每次只借用一个**主存周期**传一个字，传完就还给 CPU。
* **交替访存：** 把 CPU 的一个工作周期分成两半，前半个周期 CPU 访存，后半个周期 DMA 访存。不需要申请和归还总线（适合 CPU 时钟比主存慢很多的情况）。

## 七、DMA 与中断方式的深度辨析（大题与选择题常客）

| 对比维度 | 程序中断方式 | DMA 方式 |
| :--- | :--- | :--- |
| **数据传输的通道** | 外设 $\to$ CPU $\to$ 主存 | 外设 $\to$ 主存 (不经过 CPU) |
| **响应时机** | **一条指令执行结束时** | **一个机器周期结束时** (只要总线空闲即可) |
| **异常处理** | 可以处理突发异常事件 | 只能完成单纯的数据传输 |
| **现场保护** | 必须保存 PC 和通用寄存器 | 不需要保护现场 (因为没改变 CPU 内部状态) |
| **优先级** | 相对较低 | **DMA 优先级高于中断** (防数据丢失) |
| **适用场景** | 慢速、中速设备，键盘/鼠标 | 高速设备，磁盘读写/网卡收发 |

## 八、408 高频坑点与计算雷区

1. **带宽计算坑：** 题目常说“某总线在一个时钟周期内传输 2 次数据”，必须记得把总线频率乘 2 再计算带宽。
2. **总线复用：** 地址线和数据线物理上共用同一组引脚（如 DRAM 芯片，或早期的 PCI 总线），以减少引脚数，但会降低传输速度（需分时复用）。
3. **周期挪用的本质：** DMA 挪用的不是“指令周期”，而是“主存存取周期”（机器周期）。而且，如果 DMA 挪用周期时 CPU 恰好不需要访存（比如正在执行内部乘法计算），则 CPU 实际上并未被拖慢。
4. **DMA 的中断含义：** DMA 也会发中断，但它的中断不是为了“传输数据”，而是为了告诉 CPU “报告长官，数据一整块都搬完了，请进行后续校验和处理”。
5. **通道控制方式（扩展了解）：** 通道是比 DMA 更高级的独立处理器。DMA 只能执行一条预设命令；通道有自己的指令系统（通道程序），可以一次执行多条 I/O 指令，管理多台外设（常用于大型机）。
