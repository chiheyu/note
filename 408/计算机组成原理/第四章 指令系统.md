## 一、指令系统与指令集体系结构 (ISA)

### 1. 指令集体系结构 (ISA)
指令系统不仅仅是机器指令的集合，它定义了**软件和硬件之间的接口**。
* **ISA 规定的内容：** 指令格式、操作码、寻址方式、通用寄存器的个数与位宽、存储空间的大小与编址方式、控制寄存器（如 PC、PSW）的定义等。
* **ISA 的意义：** 不同的硬件物理实现（微架构）只要遵循相同的 ISA（如 x86、ARM），就能运行相同的机器语言程序。

### 2. 指令的基本格式
一条指令通常由**操作码 (Opcode)** 和**地址码 (Address)** 组成。
* **定长指令字结构：** 所有指令长度相等。优点是控制简单，取指速度快；缺点是浪费存储空间。
* **变长指令字结构：** 指令长度随功能不同而不同。优点是节省空间；缺点是硬件控制复杂，可能需要多次访存才能取完一条指令。

### 3. 按地址码数量分类
* **零地址指令：** 只有操作码，没有地址码。
  * 用途 1：不需要操作数的指令（如空操作 `NOP`、停机 `HLT`）。
  * 用途 2：堆栈计算机中的运算指令（如 `ADD`，操作数隐式地来自栈顶和次栈顶）。
* **一地址指令：** `OP A1`
  * 用途 1：单操作数指令（如加 1 `INC`、取反 `NOT`）。
  * 用途 2：隐含使用累加器 (ACC) 的双操作数指令：$(ACC) \text{ OP } (A_1) \to ACC$。
* **二地址指令：** `OP A1, A2`（最常见）
  * $A_1$ 为目的地址，$A_2$ 为源地址。完成操作：$(A_1) \text{ OP } (A_2) \to A_1$。
* **三地址/四地址指令：** 提供两个源操作数、一个目的操作数，甚至提供下一条指令的地址（四地址）。现代计算机通常用 PC 自动寻找下一条指令，极少使用四地址。

## 二、扩展操作码技术（408 高频必考计算）

在指令字长固定的情况下，为了既能表示丰富的指令种类，又能支持较长的地址码，通常采用**扩展操作码技术**：操作码的长度随地址码数量的减少而增加。

### 核心规则与设计原则
* **“留一手”原则：** 在设计短操作码时，**不能将所有可能的状态都用完**，==必须至少保留一个状态作为扩展标志，用于指示后面存在更长的操作码==。
![](assets/第四章%20指令系统/file-20260629.jpg)
* 假设指令字长 16 位，地址码 4 位。
  * **三地址指令：** 操作码 4 位。最多只能分配 $2^4 - 1 = 15$ 条三地址指令（假设保留 `1111` 作为二地址的扩展标志）。
  * **二地址指令：** 操作码 8 位。由于前 4 位必须是 `1111`，所以可用范围是 `1111 0000` 到 `1111 1110`（共 15 条，保留 `1111 1111` 作为一地址的扩展标志）。

**公式化计算：** 设 $n_i$ 为 $i$ 地址指令的条数，$n_{i-1}$ 为 $i-1$ 地址指令的条数，每个地址段长 $k$ 位：
$$n_{i-1} = (2^k - n_i) \times 2^k$$

## 三、寻址方式（“操作数在哪”的艺术）

寻址方式分为**指令寻址**（找下一条执行的指令）和**数据寻址**（找当前指令的操作数）。

### 1. 指令寻址
* **顺序寻址：** 通过程序计数器 PC 自动加 1（这里的“1”是指 1 个指令字长）。
* **跳跃寻址：** 通过转移类指令实现，由指令本身给出目标地址，直接修改 PC 的值。

### 2. 数据寻址（设形式地址为 $A$，有效真实物理地址为 $EA$）
* **隐含寻址：** 指令中不明显给出操作数地址，而是隐含在某个寄存器（如 ACC）中。
* **立即寻址：** $EA = \text{无}$。形式地址 $A$ 本身就是操作数（即立即数，通常补码表示）。执行极快，但数值范围受限。
* **直接寻址：** $EA = A$。指令字中的形式地址就是真正的内存地址。只需访存 1 次。
* **间接寻址：** $EA = (A)$。形式地址 $A$ 指向的主存单元中存放的才是真实的地址。
  * 优点：可扩大寻址范围。
  * 缺点：一次间接寻址需要访存 2 次（取真实地址 1 次，取真实数据 1 次）。
* **寄存器寻址：** $EA = R_i$。操作数在寄存器中。速度最快，不访存。
* **寄存器间接寻址：** $EA = (R_i)$。寄存器中存放的是操作数在主存中的地址。比普通间接寻址快，因为取真实地址不需要访存。

### 3. 三大偏移寻址（核心易混点）
* **基址寻址 (Base Addressing)：** $EA = (BR) + A$
  * **用途：** 面向**操作系统**，用于程序的浮动重定位和多道程序设计。
  * **特点：** 基址寄存器 (BR) 的内容由操作系统管理，**对用户透明**。用户只能改变偏移量 $A$。
* **变址寻址 (Indexed Addressing)：** $EA = (IX) + A$
  * **用途：** 面向**用户**，主要用于处理数组和循环程序。
  * **特点：** 变址寄存器 (IX) 的内容由用户控制（通常作为循环变量），形式地址 $A$ 保持不变（作为数组首地址）。
* **相对寻址 (Relative Addressing)：** $EA = (PC) + A$
  * **用途：** 广泛用于**条件转移指令**，实现程序内部的跳转，位置无关代码。
  * **大坑预警：** 在计算相对寻址的目标地址时，**PC 的值已经是当前指令的下一条指令的地址**。即 $EA = (当前PC + 指令长度) + A$。

## 四、CISC 与 RISC 对比

| 对比维度      | CISC (复杂指令集，如 x86) | RISC (精简指令集，如 ARM, MIPS)           |
| :-------- | :----------------- | :--------------------------------- |
| **指令系统**  | 庞大复杂，指令条数多，长短不一    | 简单精简，指令条数少，定长格式                    |
| **执行时间**  | 差异很大，有些指令需多个周期     | 绝大多数指令在一个时钟周期内完成                   |
| **访存限制**  | 许多指令都可以直接访问内存      | **只有 Load / Store(取数/存数) 指令能访问内存** |
| **寄存器数量** | 较少                 | 非常多                                |
| **控制方式**  | 主要采用**微程序**控制      | 主要采用**硬布线**控制（组合逻辑）                |
| **流水线**   | 难以实现高效流水线          | 极度适合流水线优化                          |
| **编译器设计** | 编译器设计较简单           | 编译器设计复杂（需深度优化排程）                   |

## 五、高级语言的机器级表示 (x86 汇编基础)

408 经常给出一段 C 语言代码及其对应的 x86 汇编，要求分析其功能。

### 1. 通用寄存器 (32位)
* **EAX, EBX, ECX, EDX：** 存放一般数据。EAX 常用于保存函数返回值，ECX 常作循环计数器。
	* 为向后兼容早期的 16 位和 8 位架构，EAX、EBX、ECX 和 EDX 的低 16 位可作为独立寄存器使用（分别记为 AX、BX、CX、DX），而每个 16 位寄存器又可进一步拆分为两个 8 位寄存器（如 AX 分为 AH 和 AL）。其中，E 表示 Extended，用于标识 32 位寄存器。
![](assets/第四章%20指令系统/file-20260629%201.jpg)
* **ESI, EDI：** 变址寄存器，常用于字符串或数组的内存指针。
* **EBP (基址指针)：** 永远指向当前函数**栈帧的底部**。
* **ESP (栈指针)：** 永远指向当前函数**栈帧的顶部**。（注意：栈是向低地址方向生长的）。

### 2. 常见汇编指令（入门详解版）
> **💡 写在前面的基础知识（重要）：**
> 汇编语言本质上就是直接指挥 CPU 干活的命令。这里我们以 **Intel 语法** 为例。
> 
> **1. 基本格式：**
> 指令通常长这样：`指令名称 目的操作数, 源操作数`  （简记为：`OP 目的, 源`）
> * **OP (操作码)**：动词，告诉 CPU 要做什么（比如加减乘除、移动数据）。
> * **目的 (Destination)**：动作的承受者，通常也是**保存结果**的地方。
> * **源 (Source)**：数据的来源。
> * *白话理解*：把“源”拿来，经过“OP”处理，放到“目的”里。
> 
> **2. 常见符号约定：**
> * `<reg>`：$Register$，**寄存器**。相当于 CPU 内部极速的“小变量”（如 `eax`, `ebx`, `ecx` 等）。
> * `<mem>`：$Memory$，**内存**。表示数据存在内存地址中，通常用中括号括起来（如 `[var]`, `[ebp-4]`）。
> * `<con>`：$Constant$，**常数/立即数**。就是一个普通的数字（如 `10`, `5`），`<con8>`就表示8位常数。
> * `dword ptr`：表示操作的内存大小是 4 个字节（$Double Word$）。

#### 2.1 数据传送指令（相当于高级语言中的“变量赋值”）

数据传送指令是最常用的指令，负责在寄存器和内存之间搬运数据。

**1. `mov`（Move）—— 赋值/复制**
* **功能**：将“源”的值复制给“目的”。相当于高级语言中的 `=`。
* **规则**：不能直接把数据从一个内存地址 `mov` 到另一个内存地址（必须用寄存器中转）。
* **例子**：
  
```assembly
  mov eax, ebx       ; 将 ebx 寄存器里的值复制给 eax。 (相当于 eax = ebx)
  mov eax, 5         ; 将常数 5 存入 eax 寄存器。 (相当于 eax = 5)
  mov dword ptr [ebp-4], eax  ; 将 eax 的值存入局部变量 [ebp-4] 所在的内存中
```
**2. push 和 pop —— 压栈与出栈**
 * **功能**：用于操作“栈”（一种后进先出的内存空间），常用于函数调用或临时保存数据。
 * **例子**：
   ```assembly
   push eax           ; 把 eax 里的值压入栈顶（保存起来）。
   pop ebx            ; 把栈顶的值弹出来，并存入 ebx 寄存器（取出来）。
   ```
#### 2.2 算术和逻辑运算指令（相当于高级语言中的“数学计算”）
这类指令执行完后，**结果默认保存在第一个操作数（目的）中**。
**1. add（加法）与 sub（减法）**
 * **例子**：
   ```assembly
   add eax, 10        ; 将 eax 的值加上 10，结果存回 eax。 (相当于 eax = eax + 10)
   sub eax, ebx       ; 将 eax 的值减去 ebx 的值，结果存回 eax。 (相当于 eax = eax - ebx)
   ```

**2. inc（自增）与 dec（自减）**
 * **功能**：相当于高级语言的 ++ 和 --。
 * **例子**：
   ```assembly
   inc eax            ; eax 的值加 1。 (相当于 eax++)
   dec dword ptr [var]; 内存地址 var 处的数值减 1。 (相当于 var--)
   ```

**3. imul（乘法）与 idiv（除法）**

|运算类型|有符号指令 (带负数)|无符号指令 (只有正数/零)|助记符/词根含义|
|:---:|:---:|:---:|:---:|
|乘法 (Multiply)|imul|mul|mul = Multiply<br>imul = Integer Multiply|
|除法 (Divide)|idiv|div|div = Divide<br>idiv = Integer Divide|

 * **例子**：
   ```assembly
   imul eax, ebx      ; 有符号乘法：eax = eax * ebx。
   idiv ebx           ; 有符号除法：仅指定除数。
   ```

**4. 逻辑运算：and (与)、or (或)、xor (异或)、not (取反)**
 * **功能**：按位进行逻辑计算，常用于清零或状态位操作。
 * **例子**：
   ```assembly
   xor edx, edx       ; 异或自己。任何数异或自己都等于0，这是汇编中极常见的“将 edx 清零”的技巧。 (相当于 edx = 0)
   ```
#### 2.3 控制流指令（相当于高级语言的 if-else、for/while 和 函数调用）
程序默认是从上往下顺序执行的，控制流指令可以打破这个顺序，让程序“跳”到别的地方执行。
**1. cmp（Compare）—— 比较指令**
 * **功能**：比较两个操作数的大小。**它的本质是做隐式减法（目的 - 源），但不保存减法的结果，只修改状态标志位**（如 ZF 零标志、SF 符号标志等）。
 * **说明**：cmp 本身不会导致跳转，它只是在“做铺垫”，通常紧跟着会写一条条件跳转指令（如 je、jg）。
 * **例子**：
   ```assembly
   cmp eax, ebx       ; 比较 eax 和 ebx 的大小。CPU 内部默默计算 eax - ebx，并记住结果是正、负还是零。
   ```
   
**2. 跳转指令（搭配 cmp 使用实现 if-else）**
汇编中没有 if 和 else 的关键字，全靠**比较（cmp）+ 条件跳转（j 系列）**来实现。
 * jmp (Jump)：**无条件跳转**。不管三七二十一，直接跳到指定标签。

| 比较关系 | 有符号数 (带负数) 对应的指令 | 无符号数 (只有正数/零) 对应的指令 |
|:---:|:---:|:---:|
| **== (等于)** | je (Equal) | je (Equal) |
| **!= (不等于)** | jne (Not Equal) | jne (Not Equal) |
| **> (大于)** | jg (Greater) | ja (Above) |
| **>= (大于等于)** | jge (Greater or Equal) | jae (Above or Equal) |
| **< (小于)** | jl (Less) | jb (Below) |
| **<= (小于等于)** | **jle (Less or Equal)** | **jbe (Below or Equal)** |
> **一句话记忆法：** 
> 带有 **G (Greater) / L (Less)** 的是有符号数（对应普通整数）；
> 带有 **A (Above) / B (Below)** 的是无符号数（对应地址、无符号整数）。



 * **实战场景：实现一个简单的 if (eax == ebx) 逻辑**
   ```assembly
       cmp eax, ebx     ; 先比较 eax 和 ebx
       je Label_Equal   ; 如果相等 (eax == ebx)，则跳转到 Label_Equal 处执行
       ; 如果不相等，程序不会跳转，而是顺着往下继续走 (相当于 else 分支)
       mov ecx, 1       
       jmp Label_End    ; else 分支执行完，无条件跳过下面的代码，结束逻辑
       
	Label_Equal:        ; 这是一个代码标签，标记跳转的目的地
       mov ecx, 2       ; 如果执行到了这里，说明刚才相等
	Label_End:          ; 整个条件判断结束的地方
   ```
   
**3. call 和 ret —— 函数的调用与返回**
 * **功能**：相当于高级语言中调用一个函数，并在函数执行完毕后 return 回来。
 * **例子**：
   ```assembly
   call MyFunction    ; 把下一条指令的地址压入栈中（记下回家的路），然后跳到 MyFunction 去执行。
   ; ...
   ret                ; (写在子程序的末尾) 从栈中弹出地址，回到当初 call 指令的下一条继续执行。
   ```

### 3. 选择与循环语句的机器级表示（底层控制流）

> **💡 核心思想：**
> 在汇编语言中，没有 `if`、`else`、`while`、`for`。所有的逻辑分支和循环，都是通过 **条件测试（如 `cmp`、`test`） + 跳转指令（如 `je`、`jg`、`jmp`）** 像搭积木一样拼出来的。
> 为了方便理解，我们可以先把高级语言转换成带 `goto` 的伪代码，这样就和汇编的思维一模一样了。

---

#### 3.1 选择语句（if-else）的机器级表示

高级语言中的 `if-else` 是两条路选一条走，但在汇编里，代码是线性排列的。我们需要通过跳转来“跳过”不该执行的分支。

**1. 逻辑转换（C语言 -> goto伪代码）**

假设我们有这样的 C 语言代码：
```c
if (条件为真) {
    执行 A 计划 (then_statement)
} else {
    执行 B 计划 (else_statement)
}
```

编译器会把它转换成类似这样的底层逻辑：
```c
    // 1. 判断条件是不是假的
    t = 评估条件;
    if (!t) goto false_label;  // 如果条件为假，直接跳到 B 计划处

    // 2. 如果没跳，说明条件为真，执行 A 计划
    执行 A 计划;
    goto done_label;           // A 计划执行完后，必须跳过 B 计划，直接去结尾！

false_label:                   // 这是一个标签（对应汇编里的地址）
    // 3. 执行 B 计划
    执行 B 计划;

done_label:
    // 4. if-else 结束，继续往后执行
```

**2. 汇编实战分析**
比较两个指针 p1 和 p2，返回较大的那个指针：
```assembly
# 假设此时 p1 在 eax 寄存器，p2 在 edx 寄存器
    cmp eax, edx       # 比较 p1 和 p2 (内部做减法)
    jbe .L1            # jbe 意思是 Jump if Below or Equal (如果 p1 <= p2，跳转到 .L1)
    
    # 【相当于 if 分支：p1 > p2 的情况】
    # ... 取 p2 作为返回值的逻辑 ...
    jmp .L2            # 无条件跳转到 .L2，跳过 else 分支！

.L1: 
    # 【相当于 else 分支：p1 <= p2 的情况】
    # ... 取 p1 作为返回值的逻辑 ...

.L2:
    # 结束
```

#### 3.2 循环语句的机器级表示
循环的本质，就是执行完一段代码后，**往回跳**。
##### 1. do-while 循环（最简单的循环）
do-while 是“先上车后补票”（后测试循环），不管三七二十一先执行一次循环体，然后再判断要不要继续。**这和汇编的顺逻辑最契合。**
 * **goto 逻辑：**
   ```c
   loop_start:
       执行循环体;
       t = 判断条件;
       if (t为真) goto loop_start;  // 条件满足，就往回跳，再来一次
   
   ```
##### 2. while 循环（前测试循环）
while 循环是“先判断，再执行”。如果一开始条件就不满足，循环体可能一次都不执行。
 * **编译器的优化翻译策略（转换为 do-while 思路）：**
   现代编译器通常会把 while 翻译成一个“带初始条件判断的 do-while”。
   ```c
       t = 初始条件判断;
       if (t为假) goto done_label;  // 如果一开始就不满足，直接跳到大结局
   
   loop_start:
       执行循环体;
       t = 重新判断条件;
       if (t为真) goto loop_start;  // 如果满足，继续循环
   
   done_label:
       // 循环结束
   
   ```
##### 3. for 循环（语法最紧凑的循环）
for 循环看起来复杂 for(初始; 条件; 更新)，但在编译器眼里，它**完全等价于 while 循环**。
 * **对应的 while 结构：**
   ```c
   初始化 (init_expr);
   while (条件判断 test_expr) {
       循环体 (body_statement);
       更新操作 (update_expr);
   }
   ```
 
 * **汇编实战分析（从 1 累加到 n 的经典例子）：**
   ```c
   int result = 0;
   for (int i = 1; i <= n; i++) {
       result += i;
   }
   ```
  
   翻译成底层的 goto/汇编逻辑，一步步拆解如下：
   ```assembly
   # 假设参数 n 存放在 ecx 寄存器中
   
       # 【1. 初始化阶段 (int i = 1, result = 0)】
       mov eax, 0         # eax 当作 result 变量，初始化为 0
       mov edx, 1         # edx 当作 i 变量，初始化为 1
   
       # 【2. 初始条件判断 (i <= n?)】
       cmp edx, ecx       # 比较 i(edx) 和 n(ecx)
       jg .L2             # jg 代表 Jump if Greater。如果 i > n，直接跳到循环结束 (.L2)
   
   .L1: # 【3. 循环体入口标签】
       # 执行 result += i
       add eax, edx       # eax = eax + edx  (result = result + i)
   
       # 【4. 更新操作 (i++)】
       add edx, 1         # edx = edx + 1    (i++)
   
       # 【5. 再次条件判断 (i <= n?)】
       cmp edx, ecx       # 再次比较 i(edx) 和 n(ecx)
       jle .L1            # jle 代表 Jump if Less or Equal。如果 i <= n，跳回循环开头 (.L1) 继续
   
   .L2: # 【6. 循环结束点】
       # 此时 eax 里面保存的就是最终的 result 累加结果
   ```
> **总结：** 
> 看汇编循环代码时，不要害怕。先找**标签（如 .L1、.L2）**，再找**条件跳转指令（如 jg、jle）**。画个箭头把它们连起来，你就能清晰地看到代码是怎样“跳来跳去”形成循环的了！

### 4. 过程调用 (函数调用) 机制
函数 `A` 调用函数 `B`，栈帧的变化流程：
1. **传参：** `A` 将传递给 `B` 的参数按相反顺序（通常从右到左）`push` 入栈。
2. **保存返回地址：** 执行 `call` 指令，硬件自动将 PC 的当前值（即 `call` 的下一条指令地址）压入栈中。
3. **建立新栈帧(控制转移)：** ==这一步主要靠函数`A`将函数`B`的入口地址写入PC来实现。==进入 `B` 函数，首先执行：
   ```assembly
   push ebp       ; 保存上一个栈帧的底部
   mov ebp, esp   ; 设置当前 B 函数的栈帧底部
   sub esp, 40H   ; 为 B 函数的局部变量分配空间
   ```
4. **恢复与返回：** `B` 执行完毕，执行 `leave`（等价于 `mov esp, ebp; pop ebp`）恢复 `A` 的栈帧，最后执行 `ret` 弹出返回地址到 PC。

## 六、数据对齐与大小端（易错边界）

### 1. 边界对齐 (Alignment)

为了提高 CPU 访存效率，数据存放的起始地址应是其大小的整数倍。

- `char` (1 字节) 可以放在任意地址。
- `short` (2 字节) 必须放在偶数地址（最低位地址线为 0）。
- `int` / `float` (4 字节) 必须放在 4 的倍数地址（最低两位地址线为 00）。
- **结构体对齐：** 在 C 语言中，结构体的大小不仅是各成员大小之和，还会因为内部对齐补齐空字节（Padding），且结构体总大小必须是其最大对齐要求成员大小的整数倍。

### 2. 大端 (Big-Endian) 与小端 (Little-Endian)

对于==多字节基本数据类型==（如 `int a = 0x12345678`）：

- **大端模式：** 高有效字节 (`0x12`) 存放在低地址。符合人类阅读习惯（字符串顺序）。
- **小端模式：** 低有效字节 (`0x78`) 存放在低地址。符合机器处理习惯（如 x86 架构）。

## 七、408 首轮复习经典大题陷阱

### 1. 相对寻址计算偏移量

- 题目：当前指令地址为 `2000H`，指令长度为 3 字节。要跳转的目标地址为 `2008H`，求相对寻址的位移量 $A$。
- **陷阱解析：** 计算 EA 时，PC 已经加过了。
    - `PC = 2000H + 3 = 2003H`。
        
    - `EA = (PC) + A` $\to$ `2008H = 2003H + A`。
        
    - 所以位移量 $A = 05H$。

### 2. 数组遍历的汇编理解

- 在汇编中看到 `mov eax, [ebx + ecx*4]` 这种格式，极大概率是在遍历 `int` 数组。`ebx` 是数组首地址（基址寻址），`ecx` 是索引 $i$（变址寻址），乘 4 是因为一个 `int` 占 4 字节（比例变址）。

## 八、核心结论清单

- **指令设计两极：** CISC 走复杂路线（微程序为主），RISC 走极简路线（硬布线为主，适合流水线）。
- **扩展操作码公式：** $(2^k - 剩余操作码个数) \times 2^k$ 决定了下一级地址的指令数。
- **寻址方式辨析：** 
	* 间接寻址 = 多访存。
    - 寄存器间接寻址 = 靠指针操作。
    - 基址寻址 = OS 用来搬运程序。
    - 变址寻址 = 程序员用来遍历数组。
    - 相对寻址 = 程序员用来写 `if/while` 跳转。
- **函数调用铁律：** `call` 指令隐式包含 `push eip`，`ret` 指令隐式包含 `pop eip`；局部变量总是通过 `[ebp - 偏移量]` 来访问，传入参数总是通过 `[ebp + 偏移量]` 来访问。
