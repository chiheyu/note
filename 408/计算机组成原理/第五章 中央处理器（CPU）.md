## 一、CPU 的功能与基本结构

### 1. CPU 的五大基本功能
* **指令控制：** 控制程序的顺序执行（通过 PC 实现）。
* **操作控制：** 将指令译码后，产生一系列控制信号送往各个部件。
* **时间控制：** 对各种操作加以时间上的控制（通过时钟信号和节拍实现）。
* **数据加工：** 对数据进行算术和逻辑运算（ALU 的核心功能）。
* **中断处理：** 对运行过程中出现的异常情况和特殊请求进行处理。

### 2. CPU 的内部核心寄存器分类（高频考点：可见性）
**对汇编程序员可见的寄存器（可以被机器指令直接修改）：**
* **PC (程序计数器)：** 存放下一条指令的地址。具有自动加 1 功能。
* **PSW (程序状态字)：** 存放运算结果的状态标志（如 ZF, CF, OF, SF）以及系统的运行状态（如中断允许标志 IF，特权模式标志）。==PSW可以被指令影响，如add、sub等指令会改变PSW中标志位的值，但对用户只读，即程序员不能随意修改PSW中各控制类状态位的值==
* **ACC (累加器) / GPRs (通用寄存器)：** 存放操作数和运算结果（如 eax, ebx）。

**对汇编程序员透明（不可见）的寄存器（由硬件自动控制）：**
* **IR (指令寄存器)：** 存放当前正在执行的指令代码。
* **MAR (存储器地址寄存器)：** 存放欲访问的物理内存地址。
* **MDR (存储器数据寄存器)：** 存放从内存读出或准备写入内存的数据。

## 二、指令周期与数据流（408 核心流程图）

### 1. 周期的层级关系
* **指令周期：** CPU 取出并执行一条指令所需的全部时间，指令周期不是人为的逻辑划分，在 CPU 内部是有明确的硬件（如触发器或状态寄存器）来存储和确认当前所处状态的。
* **机器周期（CPU 周期）：** 通常将一条指令的执行过程划分为若干阶段（如取指、间址、执行、中断），每个阶段所需的时间称为一个机器周期。通常以**主存的存取周期**作为一个机器周期。
* **时钟周期（节拍 / T周期）：** CPU 工作的最小时间单位。一个机器周期包含若干个时钟周期。

### 2. 四个工作周期的详细数据流（必须烂熟于心）

#### ① 取指周期 (Fetch Cycle)
目的：根据 PC 获取指令放入 IR，并更新 PC。
1. `(PC) -> MAR`：将下一条指令地址送入 MAR。
2. `1 -> R`：发出读主存控制信号。
3. `M(MAR) -> MDR`：从主存中取出指令放到 MDR。
4. `(MDR) -> IR`：将指令送入指令寄存器。
5. `(PC) + 1 -> PC`：PC 指向下一条指令（1 指一个指令字长）。

#### ② 间址周期 (Indirect Cycle)
目的：针对间接寻址指令，将形式地址转换为有效地址。
1. `Ad(IR) -> MAR`：将指令中的地址码送入 MAR。
2. `1 -> R`：发出读信号。
3. `M(MAR) -> MDR`：取出有效地址放到 MDR。
4. `(MDR) -> Ad(IR)`：将有效地址写回 IR 的地址段（或通用寄存器）。

#### ③ 执行周期 (Execute Cycle)
目的：根据 IR 中的操作码完成相应动作。不同指令数据流完全不同。

#### ④ 中断周期 (Interrupt Cycle)
目的：在指令执行结束前，若有中断请求，则保存断点（PC）并跳转到中断服务程序。
1. `a -> MAR`：将保存断点的内存地址（通常是栈顶指针 SP 减 1）送入 MAR。
2. `1 -> W`：发出写主存控制信号。
3. `(PC) -> MDR`：将当前断点存入 MDR。
4. `(MDR) -> M(MAR)`：将断点压入内存栈。
5. `向量地址 -> PC`：将中断服务程序的入口地址送入 PC，准备下一指令周期。

## 三、 数据通路的功能和基本结构
### 1. 数据通路的功能
随着技术的发展，越来越多的功能逻辑被集成到 CPU 芯片中，但不论 CPU 内部结构多么复杂，它都可视作由**数据通路 (Data Path)** 和 **控制部件 (Control Unit)** 两大部分组成。

* **数据通路**是指指令执行过程中，数据所经过的路径及其路径上的部件（如 ALU、通用寄存器、状态寄存器、总线等）。
它描述了数据从何处开始、中间经过哪些部件，最终被传送到哪里。整个数据通路在控制部件产生的控制信号的驱动下，完成指定操作。

### 2.数据通路的组成
数据通路的基本构成元件可分为**组合逻辑元件**和**时序逻辑元件**两大类。
* **组合逻辑元件**：主要用于执行数据运算与路径选择，也称操作元件。其特征是：任意时刻的输出仅由当前输入决定，不依赖历史状态；内部不含记忆单元，不受时钟控制，且无输出到输入的反馈通路，因而具有确定性和即时响应性。数据通路中常用的组合逻辑元件包括*加法器、算术逻辑单元（ALU）、译码器、多路选择器（MUX）和三态门等*。
* **时序逻辑元件**：时序逻辑元件输出不仅取决于当前输入，还依赖于电路的历史状态，因此其内部必然包含用于存储信息的记忆单元。此外，这类元件必须在时钟的同步控制下工作。常见的时序逻辑元件包括各类寄存器和存储器，例如*通用寄存器组、程序计数器（PC）、状态/暂存寄存器等。*

## 四、 数据通路的组织与分类

数据通路可以根据其**内部部件的连接方式**和**指令执行的时序组织方式**进行分类。

### 1. 按部件连接方式划分

#### (1) 总线式数据通路
总线式数据通路将通用寄存器、ALU 和内部寄存器等主要部件连接至一条或多条 CPU 内部总线（片内总线）。根据总线数量的不同，可分为：

*   **单总线结构**：所有寄存器和 ALU 都连接到同一条公共总线上。ALU 的输入与输出均通过该总线分时传送。
    *   **优点**：硬件结构简单，连线少，易于扩展。
    *   **缺点**：同一时刻总线上只能传输一组数据，存在严重的结构冒险（总线竞争问题），导致指令执行速度较慢。ALU 通常需要配备暂存寄存器配合工作。
![](assets/第五章%20中央处理器（CPU）/file-20260704.jpg)
*   **多总线结构**（如双总线、三总线）：提供多条独立总线，例如分别用于两个源操作数和一个结果写回。
    *   **特点**：支持更高的并行度，可以在多条总线上同时传输不同的数据，提高效率。

#### (2) 专用数据通路
根据指令执行过程需要，采用点对点专用连线连接寄存器、ALU等部件，而**不使用共享总线**。常使用多路选择器 (MUX) 来控制数据流向。
各数据通路可并行传输，避免了总线冲突。

*   **优点**：并发度极高，数据传输效率高、延迟低。现代 CPU 流水线均采用此方式。
*   **缺点**：硬件布线极其复杂，扩展性差，成本较高。

#### 附：总线式与专用数据通路的特点对比 (表5.1)

| 对比维度 | 总线式数据通路 | 专用数据通路 |
| :--- | :--- | :--- |
| **结构复杂度** | 简单，部件共享总线，连线少 | 复杂，需要大量点对点专用连线 |
| **扩展灵活性** | 强，新增部件只需要挂接总线 | 弱，新增部件需要重新布线 |
| **数据传输效率**| 低，同一时刻仅支持一组数据传输 | 高，多组数据可并行传输 |
| **硬件成本** | 低 | 高 |
| **性能瓶颈** | 总线带宽受限，部件增多时延迟增加 | 无总线瓶颈，性能随并行度提升 |
| **典型应用场景**| 教学模型、嵌入式微控制器 | 高性能通用处理器 (如 RISC) |

### 2. 按时序组织方式划分

#### (1) 单周期数据通路
每条指令的所有操作（取指、译码、执行、访存、写回等）都在**一个时钟周期**内完成。时钟周期长度由最慢的指令（通常是访存指令）决定。
* **特点**：控制简单，资源利用率低，可基于总线式或专用通路实现。
* **缺点**：单周期CPU在遇到简单指令时，存在大量的硬件闲置和时间浪费，极大的限制了CPU主频的提升。
![](assets/第五章%20中央处理器（CPU）/file-20260704%201.jpg)
> **⚠️ 注意：**
> 单周期处理器 (CPI = 1) **不能**采用单总线结构的数据通路。因为单总线将所有寄存器都连接到一条公共总线上，一个时钟周期内只允许一次操作，无法在一个周期内完成一条指令所需的所有操作（如取指和数据访存）。

#### (2) 多周期数据通路(按需分配，拒绝干等)
将一条指令的执行划分为多个阶段，例如给复杂的`Load`指令分配5个时钟周期，而简单的`Add`指令不需要访存，那么就为它分配4个时钟周期。每个阶段在**一个时钟周期**内完成。典型阶段包括：取指、译码与读寄存器、执行/地址计算、访存、写回等。
*   **特点**：各阶段的结果在时钟边沿被锁存到寄存器中；时钟周期长度通常以一次存储器访问时间为基准；相比单周期设计，提高了硬件复用率，缩短了时钟周期。

#### (3) 流水线数据通路(时间重叠，压榨硬件)
将指令执行过程分解为若干独立、可重叠的阶段，**不同指令在不同阶段并发推进**。每个阶段由专用功能部件完成，并通过流水段寄存器隔离和传递中间结果。
* 流水段寄存器，又叫流水线寄存器。如果把指令流水线比作一条“汽车组装流水线”，那么各个执行阶段（如取指、译码、执行等）就是“工作车间”，而==流水段寄存器就是连接两个车间之间的“传送带上的置物篮”，它负责将当前阶段的输出结果“锁住”并保存下来，作为下一个时钟周期下一阶段的输入数据。==
*   **特点**：时钟周期长度由最长阶段决定；理想情况下，每个周期可以完成一条指令。

## 五、控制器的功能和工作原理

### 5.1 控制器的结构和功能

在计算机硬件系统中，主要由执行部件、主存储器、输入/输出设备及**控制器**组成

![](assets/第五章%20中央处理器（CPU）/file-20260705.jpg)

**各部件的主要连接与数据流向：**
* **执行部件**经由数据总线与主存及 I/O 设备交换数据。
* **输入/输出设备**通过接口电路接入系统总线。
* **主存及 I/O 设备**根据地址总线判断是否被选中，并依据控制总线上的读/写等控制信号完成数据传输。
* **控制器**通过地址总线发送指令地址（PC 的值）访问主存，将获取的指令送入指令寄存器（IR），随后解析并控制执行。

**控制器的三大核心职责（计算机的“指挥中心”）：**
1. 取出待执行的指令并计算下一条指令的位置（更新 PC）。
2. 对指令的操作码进行解码，产生对应的时序信号和控制信号。
3. 协调管理 CPU、主存和 I/O 设备间的数据流向及时序。

> **💡 核心分类：**
> 依据微操作控制信号生成方式的不同，控制器主要分为**硬布线控制器**和**微程序控制器**。两者均包含 PC 和 IR，但在控制信号生成机制上有本质区别。

---

### 5.2 硬布线控制器

**本质：** 由复杂的组合逻辑电路和触发器构成，也称组合逻辑控制器。它直接根据指令操作码、时序和状态，按时间顺序生成**微操作控制信号**。

![](assets/第五章%20中央处理器（CPU）/file-20260705%201.jpg)

**控制单元 (CU) 的三大输入信号：**
1. **指令译码信息：** IR 中的 $n$ 位操作码经译码电路转换为 $2^n$ 个输出信号，决定控制单元的行为。
2. **时钟脉冲（节拍信号）：** 依据机器主频划分节拍，确保不同控制信号 $C_i$ 按序发出。
3. **状态标志：** 执行单元反馈的状态（如条件转移指令依赖此标志动态调整逻辑）。

* **优点：** 硬件电路直接响应，**执行速度极快**。
* **缺点：** 灵活性极差，修改或新增指令需重新设计电路，导致电路规模庞大且调试困难。

---

### 5.3 微程序控制器

**核心思想：** 采用**存储逻辑**实现。将控制信号组织为微指令，存入专用的高速存储器中，运行时依次读取微指令以完成控制操作。

#### 1. 微程序控制的基本概念

* **层次映射关系：** `一条机器指令` $\to$ `一个微程序` $\to$ `若干微指令` $\to$ `若干微命令` $\to$ `若干微操作`。

![](assets/第五章%20中央处理器（CPU）/file-20260705%202.jpg)

**关键术语辨析：**
* **微命令 vs 微操作：** 微命令是控制部件发出的**最小控制单位**；微操作是执行部件接收微命令后的**具体动作**（二者一一对应）。
  * *相容性微命令：* 可同时有效。
  * *互斥性微命令：* 不允许同时有效。
* **微指令：** 包含**操作控制字段**（产生控制信号）和**顺序控制字段**（决定下址）的集合。执行一次的时间称为微周期。
* **存储器对比：**
  * 主存储器 (RAM)：在 CPU 外，存程序/数据。
  * 控制存储器 CM (ROM)：在 CPU 内，存微程序。

> **注意：** 微程序对程序员而言是**完全透明**的，它本质是机器指令的硬件级解释逻辑。

#### 2. 微程序控制器的组成和工作过程

![](assets/第五章%20中央处理器（CPU）/file-20260705%208.jpg)

**核心部件：**
* **控制存储器 (CM)：** 存放所有机器指令对应的微程序。
* **微地址形成部件：** 根据机器指令操作码生成微程序入口地址。
* **μPC (微指令地址寄存器)：** 接收微地址，作为 CM 的读地址。
* **μIR (微指令寄存器)：** 暂存从 CM 读出的当前微指令。

**工作过程 (取指 $\to$ 寻址 $\to$ 执行循环)：**
1. 将取指微程序的入口地址送入 μPC，从 CM 读出微指令，把机器指令取入 IR。
2. 根据 IR 操作码生成对应微程序首地址送入 μPC。
3. 逐条读取并执行该微程序直至结束。
4. 返回取指微程序入口，处理下一条机器指令。

> **💡 常考计算：**
> **控制存储器中微程序总数 = 机器指令条数 + 公共微程序数（如取指、间址、中断等）**。

#### 3. 微指令的编码方式（“如何压缩微指令字长”）

（1）**直接编码方式**
![](assets/第五章%20中央处理器（CPU）/file-20260705%204.jpg)
* **特点：** 操作控制字段中每一位直接对应一个微命令（置 1 有效，置 0 无效）。
* **优缺：** 无须译码，并行度高、**速度最快**；但会导致**微指令字长过长**，极大消耗 CM 容量。

（2）**字段直接编码方式**
![](assets/第五章%20中央处理器（CPU）/file-20260705%205.jpg)
* **规则：** 将**互斥**的微命令归入同一字段，**相容**的分布在不同字段。各字段独立译码发出控制信号。
* **陷阱预警：** 每个字段必须预留一个状态表示**“本字段无操作”**（例如 3 位字段最多只能表示 7 个互斥微命令，而非 8 个）。
* **优缺：** 显著缩短字长；但增加译码延迟，速度稍慢。

（3）**字段间接编码方式**
![](assets/第五章%20中央处理器（CPU）/file-20260705%203.jpg)
* **特点：** 一个字段的实际含义需结合另一个字段的编码共同决定（如类型字段指示其是 ALU 还是主存操作）。
* **优缺：** 进一步压缩字长，但译码最复杂，耗时最长。

#### 4. 微指令的地址形成方式

1. **增量方式：** `μPC + 1`，用于微程序内部无转移的顺序执行段。
2. **断定方式（下址字段方式）：** 显式地将下条微地址写入当前微指令的顺序控制字段中。
3. **硬件生成：** 如入口地址，通过指令操作码结合微地址形成部件直接产生。

#### 5. 微指令的格式

（1）**水平型微指令（多操作并行）**
![](assets/第五章%20中央处理器（CPU）/file-20260705%206.jpg)
* 包含直接编码、字段直接/间接编码等。
* **特点：** 一条指令并行完成多个微操作。**执行效率高，微程序短；但指令字长极长**。

（2）**垂直型微指令（单操作串行）**
![](assets/第五章%20中央处理器（CPU）/file-20260705%207.jpg)
* 采用类似机器指令的结构设置操作码。
* **特点：** 一条指令通常仅定义一个微操作。**字长短、规整易编写；但微程序长，执行速度慢**。

#### 6. 硬布线控制器 vs 微程序控制器综合对比

| 对比维度 | 微程序控制器 | 硬布线控制器 |
| :--- | :--- | :--- |
| **工作原理** | 微操作信号以程序形式固化在 ROM（CM）中，按序读出执行 | 纯逻辑门电路，根据状态、时序和指令码即时产生信号 |
| **执行速度** | 慢（需要频繁访问控制存储器） | **快**（纯硬件级延迟） |
| **规整性** | 较规整（软件化思想） | 烦琐、不规整 |
| **应用场合** | **CISC CPU**（复杂指令集更需灵活维护） | **RISC CPU**（追求极致单周期效率） |
| **易扩充性** | **易扩充修改**（只需修改微程序） | 扩充修改极困难 |

## 六、异常与中断机制（系统的“神经反射”）

### 1. 分类辨析：异常 vs 中断
* **异常 (Exception / 内中断)：** 来自 CPU **内部**的事件，与当前执行的指令**有关**。
  * **故障 (Fault)：** 引起异常的指令可能被修复（如**缺页中断**、除数为 0、非法操作码、地址越界），修复后回到**当前指令**重新执行。
  * **陷阱 (Trap)：** 有意为之的异常（如系统调用 `syscall`、断点），处理后返回**下一条指令**。
  * **终止 (Abort)：** 发生了不可恢复的致命硬件错误（**主存校验错**、控制存储器校验错、系统总线错误），直接终止程序。
  * *异常和故障属于程序性异常（软件中断），终止属于硬件中断。*
* **中断 (Interrupt / 外中断)：** 来自 CPU **外部**设备的事件，与当前执行的指令**无关**（如键盘输入、定时器到期）。处理后返回**下一条指令**。
  * **可屏蔽中断 (Maskable Interrupt, INTR)**：
      * 通过 CPU 的 **INTR** 引脚请求，**受中断允许标志位（IF / IE）控制**；
      * 可以在 CPU 处于关中断状态时被屏蔽或推迟响应；
      * 绝大多数常规外部 I/O 设务（如键盘、打印机、网卡中断、定时器等）均属于这类中断。
  * **不可屏蔽中断 (Non-maskable Interrupt, NMI)**：
      * 通过 CPU 的 **NMI** 引脚请求，**不受中断允许标志位控制**，CPU **不能屏蔽**且必须立刻无条件响应；
      * 通常对应极其紧急和严重的系统级硬件错误（如电源掉电故障、总线奇偶校验错、内存严重错误等）。

#### 1.2【补充】核心概念：中断向量 (Interrupt Vector) 与相关辨析

在中断或异常触发后，CPU 需快速找到对应处理程序的入口地址，这一硬件引导机制依赖于**中断向量**系列概念：

* **中断类型号（中断向量号 / Vector Number）**：
  * 每个中断源或异常类型的**唯一编号**（整数索引），由中断控制器（如 8259A）在中断响应（INTA）阶段发送给 CPU，或由内部异常自动生成。
* **中断向量 (Interrupt Vector)**：
  * **中断服务程序（ISR）的入口地址**（包括段基址和偏移地址 / 程序的起始 PC 值）。
  * *易错提示：中断向量是**处理程序的地址**，而不是服务程序本身，也不是向量表的地址。*
* **中断向量地址 (Interrupt Vector Address)**：
  * **保存“中断向量”的内存单元物理地址**（即该地址中存放的**内容**是中断服务程序的入口地址）。
  * **计算公式（以常见 8086 体系为例）**：若每个向量占 4 字节，则 `中断向量地址 = 中断类型号 × 4`。
* **中断向量表 (Interrupt Vector Table, IVT)**：
  * 系统在内存特定区域（通常为零地址 / 低地址空间）分配的连续表项，用于存放系统中所有**中断向量**的集中映射表。
  * **寻址与跳转过程**：`中断事件触发 -> 获取中断类型号 -> 索引中断向量表（向量地址） -> 读出中断向量（ISR 入口地址） -> 将其加载入 PC / CS:IP 执行中断服务程序`。

### 2. 中断处理流程（硬件与软件的分工，必考）
**硬件自动完成的工作（中断隐指令，不可见的硬件逻辑）：**
1. 关中断（设置 IF=0，防止被新的中断打断）。
2. 保存断点（将 PC 和 PSW 压栈）。
3. 引出中断服务程序（根据中断号查找中断向量表，将入口地址送入 PC）。

**软件完成的工作（操作系统中的中断服务程序）：**
1. 保护现场（用汇编 `push` 保存通用寄存器的值）。
2. 处理中断事件（执行真正的设备处理逻辑）。
3. 恢复现场（用 `pop` 恢复通用寄存器的值）。
4. 开中断并返回（执行 `IRET` 指令，恢复 PC 和 PSW）。

## 七、指令流水线（必考计算与大题）

### 1. 流水线的本质
将指令执行划分为多个阶段（如 IF-取指, ID-译码/读寄存器, EX-执行/计算地址, MEM-访存, WB-写回）。在每一个时钟周期，都有一条新指令进入流水线。
* 流水线**不能缩短单条指令的执行时间**（有时甚至因为锁存器延迟还会略微增加），但能极大提高整体的**吞吐率**。
> [!NOTE] 示例：
   某条指令的各阶段延迟如下：① 取指 200ps；② 译码 100ps；③ 执行 150ps；④ 访存 200ps；⑤ 写回 100ps，该指令在单周期处理器中的总执行时间为 750ps。按流水线设计原则，时钟周期需要取各段的最大延迟，即 200ps。因此，每条指令从进入流水线到流出需经历 5 个周期，总延迟为 1000ps，大于单周期实现的 750ps。这表明：*流水线并不能缩短单条指令的执行延迟*。然而，对于包含 N 条指令的程序，单周期处理器总耗时为 $N\times750\mathrm{ps}$，而流水线处理器总耗时为 $(N+4)\times200\mathrm{ps}$。当 N 较大时，流水线的吞吐率显著更高，整体执行效率大幅提升。

![](assets/第五章%20中央处理器（CPU）/file-20260801.jpg)

### 2. 性能计算公式（设 $n$ 个任务，每个阶段用时 $\Delta t$，共 $k$ 个阶段）
* **理论总执行时间：** $$T = (k + n - 1) \times \Delta t$$
  （含义：第一条指令需要 $k$ 个周期填满流水线，剩下的 $n-1$ 条指令每条只需 1 个周期排出）。
* **吞吐率 (TP)：** 单位时间内完成的指令数。$TP = \frac{n}{T}$。最大吞吐率为 $\frac{1}{\Delta t}$。
* **加速比 (S)：** $S = \frac{顺序执行总时间}{流水线执行总时间} = \frac{n \times k \times \Delta t}{(k+n-1) \times \Delta t}$。

### 3. 三大流水线冒险 (Hazards) 与解决方案（大题核心）

> [!NOTE] 核心概念辨析：什么是“气泡 (Bubble) / Stall”与“NOP 指令”？
> 两者均用于“延迟流水线”，让后序有关联的指令停下来等待前面的操作完成，但**实现机制**与**所属层次**不同（408常考概念辨析）：
> * **暂停 (Stall) / 插入气泡 (Bubble) —— 硬件级动态控制**
>   * **概念**：**Stall** 是指硬件检测到冲突后，使流水线前端（如 PC 和 IF/ID 寄存器）冻结在当前状态；而 **Bubble（气泡）** 是 Stall 产生的结果——流水线控制逻辑会在冲突部件所在段写入全 `0` 的控制信号（使所有写入操作失能），让这个“空载操作”像气泡一样向后流动。
>   * **特点**：**由硬件动态自动产生**，不需要编译器修改程序代码，不占用程序存储空间。
> * **NOP 指令 (No-Operation) —— 软件级静态控制**
>   * **概念**：**NOP** 是汇编语言中的一种真实存在的指令（如 MIPS 中的 `sll $0, $0, 0`），其语义为“什么都不做，仅仅消耗一个时钟周期”。
>   * **特点**：**由编译器在静态编译时显式插入**到汇编代码 sequence 中，以填补时间间隔。它会真正**占用指令存储空间**和流水线资源。


1️⃣ **结构冒险 (Structural Hazard / 资源冲突)**
多条指令在同一时刻争用同一个硬件资源（如同时要访问内存的指令区和数据区）。
* **解决**：
  1. **暂停（气泡 Stall）**：硬件自动冻结发送冲突的后一条指令，让流水线产生一个周期的空转。
  2. **硬件独立**：采用指令 Cache 和数据 Cache 的分离（哈佛架构），使取指与访存各自独立使用不同存储空间。

2️⃣ **数据冒险 (Data Hazard / 数据相关)**
下一条指令需要用到上一条指令尚未写回的结果。
* **类型**：
  * **RAW (Read After Write / 写后读 / 真相关 - True Dependency)**：【408最常考，标准五段流水线中唯一会发生的冒险】
    * **含义**：后一条指令试图**读取**一个尚未被前一条指令**写入**（更新）的寄存器。
    * **示例**：`ADD R1, R2, R3`（写 R1）后紧跟 `SUB R4, R1, R5`（读 R1）。
    * ![](assets/第五章%20中央处理器（CPU）/file-20260801%201.jpg)
  * **WAW (Write After Write / 写后写 / 输出相关 - Output Dependency)**：
    * **含义**：两条指令先后都要**写入**同一个寄存器。若后一条指令先写回、前一条指令后写回，导致该寄存器最终留下了旧值。
    * **考点**：标准顺序五段流水线（按序写回）不会出现，仅在**乱序执行 (Out-of-Order)** 或多功能部件允许乱序写回时产生。
  * **WAR (Write After Read / 读后写 / 抗相关 - Anti-Dependency)**：
    * **含义**：前一条指令准备**读取**某一旧值，但后一条指令抢先将其**写入**覆盖，导致前一条指令误读到了新值。
    * **考点**：同样仅在**乱序执行**流水线中可能出现（硬件中常用“寄存器重命名 Register Renaming”技术解决 WAW 和 WAR）。
* **解决**：
  1. **暂停（插入 NOP 指令 / 气泡 Stall）**：编译器插入若干条 NOP 指令，或硬件直接阻塞流水线。
  2. **数据旁路技术 (Forwarding / Bypassing)**：【核心技术】不等结果写回通用寄存器，直接把 ALU 的输出端通过特殊的数据通路短路连接到下一条指令的 ALU 输入端。
  3. **编译优化**：指令调度，由编译器合理调整互不相关指令的执行顺序以填补等待周期。

3️⃣ **控制冒险 (Control Hazard / 分支冒险)**
遇到转移指令（如 `Branch`, `Jump`）时，无法确定下一条指令的正确地址，导致流水线取错了指令。
* **解决**：
  1. **分支预测**：
     * **静态预测**：默认不跳转（或默认跳转）。
     * **动态预测**：根据历史跳转分支记录（分支历史表 BHT、分支目标缓冲 BTB）实时预测。若预测失败，必须清空已经进入流水线的错误指令（Flush）。
  2. **延迟分支 (Delayed Branch)**：在分支转移指令后面插入一些无关的、无论分支成功与否**一定会执行的有效指令**（该位置称为“分支延迟槽 Branch Delay Slot”），化废为宝。

### 4. 高级流水线技术
* **超标量 (Superscalar)：** 每个时钟周期并发发出多条独立指令（需要多个独立功能部件，空间换时间）。
  * ![](assets/第五章%20中央处理器（CPU）/file-20260801%202.jpg)
* **超流水线 (Superpipeline)：** 将一个时钟周期再细分，提高主频（时间换时间）。
* **超长指令字 (VLIW)：** 由编译器在软件层面将多条独立指令拼接成一条超长指令执行。

## 八、多处理器基本概念

### 1. Flynn 分类法
* **SISD (单指令单数据流)：** 传统的单核单体 CPU。
* **SIMD (单指令多数据流)：** 一条指令同时对多个数据进行相同操作。典型代表：向量处理器，显卡 GPU。适合大规模矩阵/图像处理。
* **MISD (多指令单数据流)：** 实际不存在这种商业产品。
* **MIMD (多指令多数据流)：** 现代多核处理器的主流架构。
  * **SMP (对称多处理器)：** 各核心地位平等，共享同一主存空间，任意处理器访问主存的时间相同（UMA 架构）。

### 2. 硬件多线程技术
在一颗物理核心内部，提供多个线程上下文（PC 和寄存器组），以便在发生长延迟操作（如 Cache Miss）时极速切换线程，掩盖延迟。
* **细粒度多线程：** 每个时钟周期轮换执行不同线程的指令。
* **粗粒度多线程：** 只有发生较长延迟事件时才切换线程。
* **同时多线程 (SMT / 超线程)：** 在超标量架构下，同一个时钟周期内，同时发射多个不同线程的指令到不同的执行部件（Intel Hyper-Threading 的本质）。

## 九、408 高频坑点与易错题型总结

1. **流水线周期木桶效应：** 题目如果给定了 5 个阶段的时间不同（如 20ns, 10ns, 30ns, 10ns, 20ns），那么流水线的时钟周期必须取**最长阶段的时间**（即 30ns）。
2. **条件转移指令的数据冒险：** 条件转移指令要在 EX 阶段（甚至之前）才能算出目标地址和判断条件。如果发生分支预测错误，不仅要改 PC，还要“冲刷”掉取错的后续指令。
3. **中断与异常的断点保存：** 中断保存的 PC 是下一条指令地址；而如果是“故障”异常（如 Page Fault），为了能重新执行该指令，保存的 PC 是当前故障指令自身的地址。
4. **透明性判断：** 凡是汇编代码里不能直接写名字操作的部件（如 MAR, MDR, IR，以及 Cache），对程序员都是透明的；PC 和 PSW 是可见的。
5. **微指令下址字段：** 在微程序控制中，决定下一条微指令地址的最重要依据是**当前微指令的下址字段**，其次才是根据机器指令的操作码映射。
