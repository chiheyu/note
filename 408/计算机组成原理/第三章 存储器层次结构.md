## 一、存储系统的多级层次结构（“速度、容量、成本的权衡”）

### 1. 为什么要有存储层次
理想的存储器应该具备：速度极快、容量极大、价格极低。但现实物理限制中，这三者是矛盾的（速度越快通常单位成本越高，容量越小）。
因此，现代计算机采用**多级存储体系**。

### 2. 存储层次的全景图
从快到慢、从小到大、从贵到便宜：
$$CPU内部寄存器 \to L1/L2/L3\ Cache \to 主存(内存) \to 辅存(磁盘/SSD)$$

### 3. 两个核心层次（408常考抽象）
* **Cache - 主存层次：** 主要解决 CPU 和主存**速度不匹配**的问题。由于 Cache 和主存都在主机内，该层次对**所有程序员完全透明**（硬件自动完成）。
* **主存 - 辅存层次（虚拟存储器）：** 主要解决存储系统**容量不够**的问题。该层次对**应用程序员透明**，但对**系统程序员（OS开发者）不透明**。

### 4. 局部性原理（Cache 存在的灵魂）
* **时间局部性：** 最近被访问过的数据或指令，短时间内很有可能再次被访问（如：循环控制变量、循环体内的指令）。
* **空间局部性：** 某个地址被访问后，其相邻的地址也很可能即将被访问（如：数组的顺序遍历、顺序执行的指令）。

## 二、主存储器与半导体存储器

### 1. RAM (随机存取存储器) - 易失性
断电后数据丢失，主要分两类（核心对比考点）：

| 对比维度 | SRAM (静态 RAM) | DRAM (动态 RAM) |
| :--- | :--- | :--- |
| **存储原理** | 触发器 (双稳态电路) | 电容充放电 (有电为1，没电为0) |
| **运行速度** | 快 | 慢 |
| **集成度/容量**| 低 (体积大) | 高 (体积小，适合做大容量主存) |
| **发热/功耗** | 大 | 小 |
| **是否需刷新** | **不需要** | **需要** (电容会漏电) |
| **破坏性读出** | 否 | **是** (读出后需重写/再生) |
| **地址引脚** | 正常引脚数 | **地址线复用** (引脚数减半，分行/列两次传送) |
| **主要用途** | Cache | 主存 (内存条) |

**DRAM的刷新方式（必考）：**
* 刷新单位是**行**。刷新操作本身类似于一次读操作，但不输出数据。
* **集中刷新：** 在一个刷新周期内，集中安排时间刷新所有行。存在**死区**（此时CPU无法访存）。
* **分散刷新：** 每次读写操作后紧接着刷新一行。无死区，但增加了系统的存取周期。
* **异步刷新（最常用）：** 将刷新周期平均分配到每一行，每隔一段时间产生一次刷新请求。

### 2. ROM (只读存储器) - 非易失性
断电后数据不丢失。
* **MROM (掩膜 ROM)：** 厂家写好，不可更改。
* **PROM (可编程 ROM)：** 用户只能写一次。
* **EPROM (可擦除可编程 ROM)：** 可用紫外线(UVEPROM)或电(EEPROM)擦除并重写。
* **Flash Memory (闪存)：** 如 U盘、SSD。在 EEPROM 基础上发展而来，**按块擦除，按字节写**。由于闪存写之前必须擦除，故**写速度比读速度慢很多**。

## 三、主存容量的扩展与并行主存（高频计算）

### 1. 主存容量扩展（芯片拼接）
单块存储芯片容量有限，需组合使用：
* **位扩展法（加宽数据线）：** 将多片芯片的数据线并联。例如，用 8 片 $8K \times 1$ 位的芯片组成 $8K \times 8$ 位的存储器。所有芯片的片选信号 $\overline{CS}$ 连接在一起。
* **字扩展法（加宽地址线）：** 增加存储单元数量。例如，用 4 片 $16K \times 8$ 位的芯片组成 $64K \times 8$ 位的存储器。需要使用**译码器**将高位地址转化为各个芯片的片选信号 $\overline{CS}$。
* **字位同时扩展：** 先进行位扩展构成模块，再用字扩展将模块组合。

### 2. 双端口 RAM 与 多模块交叉存储器
为了提高主存带宽，除了使用更快的芯片，还可以改变架构：
* **高位交叉编址（顺序方式）：** 连续地址分布在同一个存储体中。无法提高单次连续访问的带宽，主要用于容量扩展。
* **低位交叉编址（交叉方式）（重点计算）：** 连续地址交叉分布在相邻的存储体中。采用**流水线**方式存取。
  * 设存储体数量为 $m$，单个体存取周期为 $T$，总线传输周期为 $\tau$。
  * 为了实现流水线不中断，必须满足：$m \ge T / \tau$。
  * 连续读取 $n$ 个字的耗时：$t = T + (n-1)\tau$。

## 四、Cache 工作原理与映射方式（核心大题）

### 1. Cache 的基本单位与命中率
* Cache 与主存的数据交换是以**块 (Block / Line)** 为单位的（利用空间局部性）。
* **命中率 (H)：** $H = N_c / (N_c + N_m)$，其中 $N_c$ 为命中次数，$N_m$ 为未命中次数。
* **平均访问时间 (AMAT)：** $T = H \times t_c + (1-H) \times t_m$ （如果未命中时是同时访问 Cache 和主存，则公式如此；如果未命中时是先查 Cache 再查主存，则 $T = t_c + (1-H) \times t_m$）。

### 2. Cache 映射方式与地址拆分（408 必考重灾区）
主存地址被划分为几个字段，取决于映射方式。假设主存块大小为 $2^b$ 字节，Cache 有 $2^c$ 行，主存地址总位数为 $A$。

* **直接映射 (Direct Mapping)：** * 主存块只能存放在固定的 Cache 行中：`Cache行号 = 主存块号 % Cache总行数`。
  * 优点：查找速度最快；缺点：冲突率最高，空间利用率低。
  * **主存地址划分：** `[ 主存字块标记 Tag | Cache 行号 Index (c位) | 块内偏移 Offset (b位) ]`

* **全相联映射 (Fully Associative)：**
  * 主存块可以放在 Cache 的任意一行。
  * 优点：冲突率最低，空间利用率高；缺点：查找需用相联存储器比较所有 Tag，硬件复杂，速度慢。
  * **主存地址划分：** `[ 主存字块标记 Tag (A-b位) | 块内偏移 Offset (b位) ]`

* **组相联映射 (Set Associative)：**
  * 将 Cache 分为 $2^q$ 组，每组包含 $r$ 行（称为 $r$ 路组相联）。主存块固定映射到某一组，但在组内可以随便放。
  * `组号 = 主存块号 % 组数`。是直接映射和全相联的折中。
  * **主存地址划分：** `[ 主存字块标记 Tag | 组号 Index (q位) | 块内偏移 Offset (b位) ]`

## 五、Cache 替换算法与写策略

### 1. 替换算法 (全相联和组相联适用)
* **RAND (随机替换)：** 随便换，未利用局部性。
* **FIFO (先进先出)：** 替换最早调入的块。未利用局部性，可能出现 Belady 异常。
* **LRU (最近最少使用)：** 替换最久未被访问的块。基于局部性原理，**命中率最高**。
  * *硬件实现考点：* 每行设置一个计数器。命中时，命中行清零，比它小的计数器加 1；未命中时，替换计数器最大（最旧）的行，其余加 1。
* **LFU (最不经常使用)：** 替换访问次数最少的块。

### 2. Cache 写策略 (一致性问题)
* **命中时的写策略：**
  * **全写法 (Write-Through)：** 写命中时，同时写入 Cache 和主存。一般配合**写缓冲 (Write Buffer)** 使用。
  * **写回法 (Write-Back)：** 写命中时，只修改 Cache 不修改主存，并设置**脏位 (Dirty Bit/修改位)**。只有当该块被替换出 Cache 时，才写回主存。
* **未命中时的写策略：**
  * **写分配法 (Write-Allocate)：** 未命中时，将主存块调入 Cache 再修改。通常搭配**写回法**。
  * **非写分配法 (Not-Write-Allocate)：** 未命中时，直接写入主存，不调入 Cache。通常搭配**全写法**。

## 六、虚拟存储器 (大题究极考点)

### 1. 基本思想与实现
利用辅存（磁盘）扩展主存。CPU 发出的是**逻辑地址（虚拟地址）**，需要通过硬件（MMU）转化为**物理地址**后才能访问主存。

### 2. 虚拟存储器的三种组织方式
* **页式虚拟存储器：**
  * 将虚存和主存划分为大小相等的**页 (Page)**。
  * 虚拟地址 = `[ 虚页号 | 页内偏移 ]`。物理地址 = `[ 物理页框号 | 页内偏移 ]`。
  * 通过**页表**将虚页号映射为物理页框号。存在**内部碎片**。
* **段式虚拟存储器：**
  * 按程序的逻辑结构划分段，每段大小可变。
  * 虚拟地址 = `[ 段号 | 段内偏移 ]`。存在**外部碎片**。
* **段页式虚拟存储器：**
  * 先分段，段内再分页。虚拟地址 = `[ 段号 | 段内页号 | 页内偏移 ]`。

### 3. TLB (Translation Lookaside Buffer / 快表)
* 页表存放在主存中，每次地址转换都要访问一次主存，太慢。
* TLB 是位于 CPU 内部的专用 Cache（常采用全相联或组相联），用来存放**最近访问过的页表项**。
* **黄金逻辑链条：**
  * CPU 生成虚拟地址 -> 查 TLB。
  * 如果 TLB 命中，直接得到物理页框号，拼接偏移量访存。**（此时页表一定命中，因为 TLB 是页表的子集）**
  * 如果 TLB 未命中 -> 查主存中的页表（慢表）。
  * 拿到物理地址后 -> 去查 Cache。如果 Cache 也未命中 -> 查主存。

## 七、经典大题模型：地址计算与容量拆解

### 题目模型
某 32 位计算机，按字节编址。主存容量为 4GB。Cache 容量为 64KB，采用 4 路组相联映射，块大小为 32B。求主存地址字段的划分。

### 解答拆解
1. **分析地址总长度：** 4GB = $2^{32}$B，按字节编址，故主存地址为 **32位**。
2. **分析块内偏移 (Offset)：** 块大小为 32B = $2^5$B，故块内偏移占 **5位**。
3. **分析 Cache 组号 (Index)：**
   * Cache 总块数（行数） = Cache容量 / 块大小 = 64KB / 32B = $2^{16} / 2^5 = 2^{11}$ 块。
   * 采用 4 路组相联（每组 4 块），故组数 = 总块数 / 4 = $2^{11} / 2^2 = 2^9$ 组。
   * 组号占 **9位**。
4. **分析 Tag 长度：**
   * Tag = 主存地址总长 - 组号长度 - 块内偏移 = 32 - 9 - 5 = **18位**。
5. **结论：** 主存地址划分为：Tag (18位)，Index (9位)，Offset (5位)。

## 八、408 高频坑点与易错题型总结

1. **DRAM 地址线复用陷阱：** 计算 DRAM 芯片引脚数时，如果容量是 $2^{20} \times 8$ 位，地址线不是 20 根，而是**一半**（10 根行地址 + 10 根列地址分时复用）。所以引脚数 = 10(地址) + 8(数据) + 各种控制线。
2. **Cache 容量 vs Cache 总容量计算：**
   * 一般说的 Cache 容量只指**数据区**容量。
   * 如果问 Cache **总容量**，必须加上**标记阵列 (Tag Array)** 的容量！标记阵列包含：Tag 标记位、有效位 (Valid Bit, 1位)、脏位 (Dirty Bit, 写回法独有, 1位)、LRU替换控制位。
3. **TLB vs Cache 区别：** TLB 缓存的是**页表项**（映射关系），Cache 缓存的是**数据/指令本身**。
4. **缺失代价混淆：** Cache 缺失是由硬件自动处理的；而 Page Fault（缺页中断）是由**操作系统软件**（中断处理程序）配合硬件处理的，代价极大。

## 九、核心结论清单

* 层次结构目的：Cache 提速，虚存扩容。
* SRAM 靠双稳态，快但贵，做 Cache；DRAM 靠电容，需刷新，地址复用，做主存。
* 交叉存储器低位交叉才能实现真正流水线并行。
* Cache 映射地址切分公式必须肌肉记忆。
* Cache 总容量 = 数据阵列容量 + 标记阵列容量 (Tag + 有效位 + 脏位 + 替换位)。
* CPU 取指完整流程：逻辑地址 $\xrightarrow{TLB/Page Table}$ 物理地址 $\xrightarrow{Cache}$ 数据。
