## 一、存储系统的多级层次结构（“速度、容量、成本的权衡”）

### 1. 为什么要有存储层次
理想的存储器应该具备：速度极快、容量极大、价格极低。但现实物理限制中，这三者是矛盾的（速度越快通常单位成本越高，容量越小）。
因此，现代计算机采用**多级存储体系**。

### 2. 存储层次的全景图
从快到慢、从小到大、从贵到便宜：
$$CPU内部寄存器 \to L1/L2/L3\ Cache \to 主存(内存) \to 辅存(磁盘/SSD)$$

### 3. 两个核心层次（408常考抽象）
* **Cache - 主存层次：** 主要解决 CPU 和主存**速度不匹配**的问题。由于 Cache 和主存都在主机内，该层次对**所有程序员完全透明**（硬件自动完成）。
* **主存 - 辅存层次（虚拟存储器）：** 主要解决存储系统**容量不够**的问题。该层次对**应用程序员透明**，但对**系统程序员（OS开发者）不透明**。

| 对比项 | 应用程序员 |系统程序员|
|:---:|:---:|:---:|
|面向对象|用户需求、业务功能|计算机系统、底层环境|
|开发内容|应用软件|系统软件|
|常用语言|Java、Python、JavaScript、C#|C、C++、Rust、汇编|
|关注重点|功能、界面、业务逻辑|性能、资源管理、底层机制|
|典型成果|App、网站、管理系统|操作系统、驱动、编译器、数据库内核|

![](assets/第三章%20存储器层次结构/file-20260622.jpg)

### 4. 局部性原理（Cache 存在的灵魂）
* **时间局部性：** 最近被访问过的数据或指令，短时间内很有可能再次被访问（如：循环控制变量、循环体内的指令）。
* **空间局部性：** 某个地址被访问后，其相邻的地址也很可能即将被访问（如：数组的顺序遍历、顺序执行的指令）。

### 5. 存储器的主要性能指标

* **存储容量**：存储器能够存放的二进制信息的总量。通常用“存储单元数 × 每个存储单元的位数（字长）”或直接用字节数（Byte）来表示（如：8GB、16GB）。
* **存取时间（访问时间，Access Time）**：指从启动一次存储器操作（读或写）到完成该操作所经历的时间。主要分为读出时间和写入时间。
* **存取周期（读写周期，Memory Cycle Time）**：指存储器进行连续两次独立的存储器操作（如连续两次读操作）之间所需的最小时间间隔。由于读写操作后存储器内部需要一段恢复时间，因此**存取周期通常略大于存取时间**。
* **数据传输率（存储带宽，Bandwidth）**：指单位时间内存储器存取的信息量，即存储器与外部交换数据的速度。计算公式通常为：`数据传输率 = 数据宽度 / 存取周期`，单位通常为 Byte/s、MB/s 或 GB/s。

### 6. 存储器的分类

存储器可以从不同的维度进行分类，常见的分类方式包括：

* **按在计算机系统中的作用分类**：
  * **高速缓冲存储器（Cache）**：位于CPU和主存之间，速度极快，容量较小，用于解决CPU和主存速度不匹配的问题，存放CPU最常用的指令和数据。
  * **主存储器（主存/内存，Main Memory）**：用于存放计算机运行期间所需的程序和数据，CPU可以直接对其进行随机访问，速度较快，容量适中。
  * **辅助存储器（外存/辅存，Secondary Memory）**：用于存放暂不运行的程序和大量备份数据，CPU不能直接访问，必须先调入主存，速度较慢，但容量极大（如SSD、HDD）。

* **按工作原理/读写特性分类**：
  * **随机存取存储器（RAM, Random Access Memory）**：既能读出也能写入，断电后存储的信息会完全消失（易失性）。
    * **SRAM（静态RAM）**：利用触发器存储信息，速度极快，集成度低，功耗大，常用于Cache。
    * **DRAM（动态RAM）**：利用电容电荷存储信息，需要定期刷新以维持数据，速度较慢，集成度高，常用于主存。
  * **只读存储器（ROM, Read-Only Memory）**：信息一旦写入后通常只能读出，断电后信息不会丢失（非易失性），常用于存放系统引导程序（如BIOS）。现代ROM（如Flash闪存）已演变为支持电擦写。

* **按存取方式分类**：
  * **随机存取（Random Access）**：存取时间与存储单元的物理位置无关，任何单元均可直接访问（如RAM、ROM）。
  * **顺序存取（Sequential Access）**：存取时间与存储单元的物理位置密切相关，必须按照物理位置顺序查找（如磁带）。
  * **直接存取（Direct Access / 半随机存取）**：介于上述两者之间，先直接定位到某个小区域，再在该区域内进行顺序查找（如机械硬盘的磁头寻道与扇区读取）。
  * **相联存储器（Associative Memory）**：不根据地址而是**根据内容**进行检索和访问（如用于地址映射的快表 TLB）。

* **按断电后信息是否消失（数据易失性）分类**：
  * **易失性存储器（Volatile Memory）**：电源切断后，存储的信息立即消失，如RAM。
  * **非易失性存储器（Non-volatile Memory）**：电源切断后，信息仍能长期保存，如ROM、硬盘、闪存（Flash）。

* **按存储介质分类**：
  * **半导体存储器**：以半导体器件（如MOS管、双极型晶体管）作为存储元，如内存、Cache、U盘、固态硬盘（SSD）。
  * **磁表面存储器**：在金属或塑料基片表面涂覆一层磁性材料来记录信息，如机械硬盘（HDD）、磁带。
  * **光存储器**：利用激光束在记录介质上引起的物理或化学变化来记录和读写信息，如CD-ROM、DVD。

## 二、主存储器与半导体存储器

### 1. RAM (随机存取存储器) - 易失性
断电后数据丢失，主要分两类（核心对比考点）：

| 对比维度 | SRAM (静态 RAM) | DRAM (动态 RAM) |
| :--- | :--- | :--- |
| **存储原理** | 触发器 (双稳态电路) | 电容充放电 (有电为1，没电为0) |
| **运行速度** | 快 | 慢 |
| **集成度/容量**| 低 (体积大) | 高 (体积小，适合做大容量主存) |
| **发热/功耗** | 大 | 小 |
| **是否需刷新** | **不需要** | **需要** (电容会漏电) |
| **破坏性读出** | 否 | **是** (读出后需重写/再生) |
| **地址引脚** | 正常引脚数 | **地址线复用** (引脚数减半，分行/列两次传送) |
| **主要用途** | Cache | 主存 (内存条) |

#### 1.1 DRAM-地址引脚复用技术

* **背景与目的**：DRAM（动态RAM）通常具有极高的集成度，容量巨大。如果采用传统的寻址方式，地址线数量会非常多，导致芯片引脚过多、体积增大、成本上升。
* **核心原理**：采用**地址线复用技术**。将完整的存储单元地址拆分为两部分：**行地址**和**列地址**。
* **工作方式**：
  * 芯片上的地址引脚数量直接**减半**。
  * 寻址时，同一组地址引脚分**两次**传送地址信号：先传送行地址（由行选通信号锁定），后传送列地址（由列选通信号锁定）。
* **优缺点**：大大减少了芯片的引脚数，减小了芯片封装体积；但因为地址是分两次传输的，稍微增加了寻址的控制复杂度和时间。

#### 1.2 DRAM-刷新机制和阵列设计优化

##### 1. 为什么需要刷新？（刷新原因）
* **电容漏电**：DRAM 利用电容充放电来表示逻辑 1 和 0。电容上的电荷会随时间逐渐泄漏，如果不及时补充电荷，数据就会丢失。
* **破坏性读出**：DRAM 的读操作是破坏性的，读出数据后原电容的电荷状态会被破坏。因此读出后必须进行重写（即**再生**）。

##### 2. 阵列设计优化与刷新单位
* **刷新单位是“行”**。DRAM 内部的存储单元被设计成二维阵列（行 × 列）。
* **设计优势**：刷新操作本质上是一次“只读不输出数据”的假读操作。以行为单位进行刷新，可以一次性恢复一整行所有电容的电荷，极大地提高了刷新效率（这也是为什么在计算地址时，行、列地址通常各占一半）。

#### 2. DRAM的刷新方式（重点考点）
为了保证在规定的时间（刷新周期，通常为 2ms~64ms）内，所有行都能被刷新一遍，有以下三种策略：

* **① 集中刷新 (Burst Refresh)**
  * **机制**：在一个完整的刷新周期内，集中安排一段时间，连续刷新所有行。
  * **特点**：存在**“死区”**（Dead Time）。在集中刷新的这段时间内，DRAM 拒绝读写请求，CPU 无法访问存储器。
* **② 分散刷新 (Distributed Refresh)**
  * **机制**：将刷新操作分散到每个读写周期中。即每次正常的读写操作后，紧接着安排刷新一行。
  * **特点**：**无死区**。但由于每次访存都附带了刷新操作，大大增加了系统的整体存取周期，降低了系统速度。
* **③ 异步刷新 (Asynchronous Refresh) —— 最常用**
  * **机制**：综合了前两者的优点。将刷新周期平均分配到每一行，每隔一段时间（例如：刷新周期 / 总行数）产生一次刷新请求。
  * **特点**：不仅避免了长时间的“死区”，也没有过分拉长每一次的存取周期，是目前主存最常用的刷新方式。

![](assets/第三章%20存储器层次结构/file-20260622%201.jpg)

### 2. ROM (只读存储器) - 非易失性
断电后数据不丢失。
* **MROM (掩膜 ROM)：** 厂家写好，不可更改。
* **PROM (可编程 ROM)：** 用户只能写一次。
* **EPROM (可擦除可编程 ROM)：** 可用紫外线(UVEPROM)或电(EEPROM)擦除并重写。
* **Flash Memory (闪存)：** 如 U盘、SSD。在 EEPROM 基础上发展而来，**按块擦除，按字节写**。由于闪存写之前必须擦除，故**写速度比读速度慢很多**。

## 三、主存容量的扩展与并行主存（高频计算）

### 1. 主存容量扩展（芯片拼接）
单块存储芯片容量有限，需组合使用：
* **位扩展法（加宽数据线）：** 将多片芯片的数据线并联。例如，用 8 片 $8K \times 1$ 位的芯片组成 $8K \times 8$ 位的存储器。所有芯片的片选信号 $\overline{CS}$ 连接在一起。
* **字扩展法（加宽地址线）：** 增加存储单元数量。例如，用 4 片 $16K \times 8$ 位的芯片组成 $64K \times 8$ 位的存储器。需要使用**译码器**将高位地址转化为各个芯片的片选信号 $\overline{CS}$。
* **字位同时扩展：** 先进行位扩展构成模块，再用字扩展将模块组合。

### 2. 双端口 RAM 与多模块交叉存储器

为了提高主存的带宽和吞吐率（解决 CPU 速度远高于存储器的问题），除了寻找使用更快的芯片外，还可以通过改变存储器的架构来实现。**多模块存储器**（空间并行技术）便是其中的核心方案。

根据模块间地址分配方式的不同，多模块存储器主要分为两类：

#### 2.1 高位交叉编址（顺序方式）
* **编址原理**：**高位地址为模块号（体号），低位地址为模块内地址。**
* **特点**：连续的地址分布在**同一个**存储体中。
* **工作过程**：CPU 访问一段连续的地址时，总是先在一个模块内连续访问，直到该模块访问完后才转到下一个模块。由于各模块不能并行访问，这种结构本质上仍属于顺序存储器。
* **结论**：**无法提高单次连续访问的带宽和吞吐率**，其主要用于**存储器容量扩展**。

![](assets/第三章%20存储器层次结构/file-20260622%202.jpg)

#### 2.2 低位交叉编址（交叉方式）—— 核心考点
* **编址原理**：**低位地址用作模块号（体号），高位地址作模块内地址。**（假设有 $m$ 个模块，则模块号 = 单元地址 $\% m$）
* **特点**：连续的地址被依次分散（交叉分布）到**相邻的不同存储体**中。
* **工作过程**：由于程序或数据在物理上是“交叉存放”的，采用此方式可以在访问连续地址时，让多个结构完全相同的存储模块**并行工作**，显著提高存储器的吞吐率。

![](assets/第三章%20存储器层次结构/file-20260622%203.jpg)

低位交叉存储器主要有两种启动方式：

**轮流启动方式（流水线方式存取）**
当每个模块一次读/写的位数正好等于数据总线位数时，采用轮流启动。
* **模块数量要求**：设单个存储模块的存取周期为 $T$，总线传输周期（即相邻两次启动的时间间隔）为 $\tau$。为了实现流水线不中断（即启动某模块后，经过 $m\tau$ 的时间再次启动该模块时，其上一次存取已完成），存储器交叉模块数 $m$ 必须满足：
  $$m \ge T / \tau$$
* **耗时计算（重点计算）**：连续读取 $n$ 个字（数据）所需的总耗时 $t$ 计算公式为：
  $$t = T + (n - 1)\tau$$
  *(对比分析：如果是采用顺序方式连续读取 $n$ 个字，耗时为 $nT$。可见交叉存储器的带宽得到了大大提高。)*

![](assets/第三章%20存储器层次结构/file-20260622%204.jpg)

**同时启动方式**
当所有存储模块一次并行读/写的总位数恰好等于存储器数据总线宽度时，可采用同时启动。
* 每次总线操作可以同时读取所有模块的数据，例如利用 8 个 8位 芯片同步工作，一次性提供 64位 数据以匹配 64位 的总线宽度。
* **数据对齐**：并行访问是以总线的字宽为单位进行的，读取的数据必须来自**起始地址对齐**的块。若访问的数据（如一个跨越对齐边界的 int 型变量）未对齐，则需要进行两次访存。这也是内存访问要求数据对齐的根本原因。

#### 2.3 交叉存储器的访存冲突分析
在理想状态下，$m$ 体交叉存储器每隔 $\tau$ 时间即可读/写一个数据。但如果在程序的实际运行过程中，相邻的 $m$ 次访存请求里，出现了**访问地址落在同一个模块内**的情况（即根据地址计算出的低位模块号相同），就会发生**访存冲突**。此时系统必须延迟发生冲突的后续访问请求。

## 四、Cache 工作原理与映射方式（核心大题）

### 1. Cache 的基本单位与命中率
* Cache 与主存的数据交换是以**块 (Block / Line)** 为单位的（利用空间局部性）。
* **命中率 (H)：** $H = N_c / (N_c + N_m)$，其中 $N_c$ 为命中次数，$N_m$ 为未命中次数。
* **平均访问时间 (AMAT)：** $T = H \times t_c + (1-H) \times t_m$ （如果未命中时是同时访问 Cache 和主存，则公式如此；如果未命中时是先查 Cache 再查主存，则 $T = t_c + (1-H) \times t_m$）。

### 2. Cache 映射方式与地址拆分（408 必考重灾区）
主存地址被划分为几个字段，取决于映射方式。假设主存块大小为 $2^b$ 字节，Cache 有 $2^c$ 行，主存地址总位数为 $A$。

* **直接映射 (Direct Mapping)：** * 主存块只能存放在固定的 Cache 行中：`Cache行号 = 主存块号 % Cache总行数`。
  * 优点：查找速度最快；缺点：冲突率最高，空间利用率低。
  * **主存地址划分：** `[ 主存字块标记 Tag | Cache 行号 Index (c位) | 块内偏移 Offset (b位) ]`

* **全相联映射 (Fully Associative)：**
  * 主存块可以放在 Cache 的任意一行。
  * 优点：冲突率最低，空间利用率高；缺点：查找需用相联存储器比较所有 Tag，硬件复杂，速度慢。
  * **主存地址划分：** `[ 主存字块标记 Tag (A-b位) | 块内偏移 Offset (b位) ]`

* **组相联映射 (Set Associative)：**
  * 将 Cache 分为 $2^q$ 组，每组包含 $r$ 行（称为 $r$ 路组相联）。主存块固定映射到某一组，但在组内可以随便放。
  * `组号 = 主存块号 % 组数`。是直接映射和全相联的折中。
  * **主存地址划分：** `[ 主存字块标记 Tag | 组号 Index (q位) | 块内偏移 Offset (b位) ]`

## 五、Cache 替换算法与写策略

### 1. 替换算法 (全相联和组相联适用)
* **RAND (随机替换)：** 随便换，未利用局部性。
* **FIFO (先进先出)：** 替换最早调入的块。未利用局部性，可能出现 Belady 异常。
* **LRU (最近最少使用)：** 替换最久未被访问的块。基于局部性原理，**命中率最高**。
  * *硬件实现考点：* 每行设置一个计数器。命中时，命中行清零，比它小的计数器加 1；未命中时，替换计数器最大（最旧）的行，其余加 1。
* **LFU (最不经常使用)：** 替换访问次数最少的块。

### 2. Cache 写策略 (一致性问题)
* **命中时的写策略：**
  * **全写法 (Write-Through)：** 写命中时，同时写入 Cache 和主存。一般配合**写缓冲 (Write Buffer)** 使用。
  * **写回法 (Write-Back)：** 写命中时，只修改 Cache 不修改主存，并设置**脏位 (Dirty Bit/修改位)**。只有当该块被替换出 Cache 时，才写回主存。
* **未命中时的写策略：**
  * **写分配法 (Write-Allocate)：** 未命中时，将主存块调入 Cache 再修改。通常搭配**写回法**。
  * **非写分配法 (Not-Write-Allocate)：** 未命中时，直接写入主存，不调入 Cache。通常搭配**全写法**。

## 六、虚拟存储器 (大题究极考点)

### 1. 基本思想与实现
利用辅存（磁盘）扩展主存。CPU 发出的是**逻辑地址（虚拟地址）**，需要通过硬件（MMU）转化为**物理地址**后才能访问主存。

### 2. 虚拟存储器的三种组织方式
* **页式虚拟存储器：**
  * 将虚存和主存划分为大小相等的**页 (Page)**。
  * 虚拟地址 = `[ 虚页号 | 页内偏移 ]`。物理地址 = `[ 物理页框号 | 页内偏移 ]`。
  * 通过**页表**将虚页号映射为物理页框号。存在**内部碎片**。
* **段式虚拟存储器：**
  * 按程序的逻辑结构划分段，每段大小可变。
  * 虚拟地址 = `[ 段号 | 段内偏移 ]`。存在**外部碎片**。
* **段页式虚拟存储器：**
  * 先分段，段内再分页。虚拟地址 = `[ 段号 | 段内页号 | 页内偏移 ]`。

### 3. TLB (Translation Lookaside Buffer / 快表)
* 页表存放在主存中，每次地址转换都要访问一次主存，太慢。
* TLB 是位于 CPU 内部的专用 Cache（常采用全相联或组相联），用来存放**最近访问过的页表项**。
* **黄金逻辑链条：**
  * CPU 生成虚拟地址 -> 查 TLB。
  * 如果 TLB 命中，直接得到物理页框号，拼接偏移量访存。**（此时页表一定命中，因为 TLB 是页表的子集）**
  * 如果 TLB 未命中 -> 查主存中的页表（慢表）。
  * 拿到物理地址后 -> 去查 Cache。如果 Cache 也未命中 -> 查主存。

## 七、经典大题模型：地址计算与容量拆解

### 题目模型
某 32 位计算机，按字节编址。主存容量为 4GB。Cache 容量为 64KB，采用 4 路组相联映射，块大小为 32B。求主存地址字段的划分。

### 解答拆解
1. **分析地址总长度：** 4GB = $2^{32}$B，按字节编址，故主存地址为 **32位**。
2. **分析块内偏移 (Offset)：** 块大小为 32B = $2^5$B，故块内偏移占 **5位**。
3. **分析 Cache 组号 (Index)：**
   * Cache 总块数（行数） = Cache容量 / 块大小 = 64KB / 32B = $2^{16} / 2^5 = 2^{11}$ 块。
   * 采用 4 路组相联（每组 4 块），故组数 = 总块数 / 4 = $2^{11} / 2^2 = 2^9$ 组。
   * 组号占 **9位**。
4. **分析 Tag 长度：**
   * Tag = 主存地址总长 - 组号长度 - 块内偏移 = 32 - 9 - 5 = **18位**。
5. **结论：** 主存地址划分为：Tag (18位)，Index (9位)，Offset (5位)。

## 八、408 高频坑点与易错题型总结

1. **DRAM 地址线复用陷阱：** 计算 DRAM 芯片引脚数时，如果容量是 $2^{20} \times 8$ 位，地址线不是 20 根，而是**一半**（10 根行地址 + 10 根列地址分时复用）。所以引脚数 = 10(地址) + 8(数据) + 各种控制线。
2. **Cache 容量 vs Cache 总容量计算：**
   * 一般说的 Cache 容量只指**数据区**容量。
   * 如果问 Cache **总容量**，必须加上**标记阵列 (Tag Array)** 的容量！标记阵列包含：Tag 标记位、有效位 (Valid Bit, 1位)、脏位 (Dirty Bit, 写回法独有, 1位)、LRU替换控制位。
3. **TLB vs Cache 区别：** TLB 缓存的是**页表项**（映射关系），Cache 缓存的是**数据/指令本身**。
4. **缺失代价混淆：** Cache 缺失是由硬件自动处理的；而 Page Fault（缺页中断）是由**操作系统软件**（中断处理程序）配合硬件处理的，代价极大。

## 九、核心结论清单

* 层次结构目的：Cache 提速，虚存扩容。
* SRAM 靠双稳态，快但贵，做 Cache；DRAM 靠电容，需刷新，地址复用，做主存。
* 交叉存储器低位交叉才能实现真正流水线并行。
* Cache 映射地址切分公式必须肌肉记忆。
* Cache 总容量 = 数据阵列容量 + 标记阵列容量 (Tag + 有效位 + 脏位 + 替换位)。
* CPU 取指完整流程：逻辑地址 $\xrightarrow{TLB/Page Table}$ 物理地址 $\xrightarrow{Cache}$ 数据。
