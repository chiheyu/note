## 一、查找的基本概念与核心指标

### 1. 查找表与核心概念
* **查找表 (Search Table)：** 由同一类型的数据元素（或记录）构成的集合。
* **关键字 (Key)：** 数据元素中唯一标识该元素的某个数据项的值。
* **静态查找：** 仅查询某特定的数据元素是否在查找表中，或检索其属性。适用于**数据稳定、不频繁改动**的场景。
* **动态查找：** 在查找过程中，同时伴随插入或删除操作。表结构会动态变化。

### 2. 平均查找长度 (ASL - 408 计算大项)
ASL 是衡量查找算法效率的最核心指标，指查找过程中**关键字比较次数的期望值**。

$$ASL = \sum_{i=1}^{n} p_i c_i$$
* $n$：查找表长度。
* $p_i$：查找第 $i$ 个元素的概率（通常假设等概率 $p_i = 1/n$）。
* $c_i$：找到第 $i$ 个元素所需的比较次数。

**注意：** 408 考试中，ASL 严格分为 **查找成功时的 $ASL_{succ}$** 和 **查找失败时的 $ASL_{fail}$**，两者的计算路径和分母通常不同！

## 二、线性结构的查找

### 1. 顺序查找 (Sequential Search)
* **适用条件：** 既适用于顺序表，也适用于链表；既可以是有序表，也可以是无序表。
* **带哨兵的优化：**
  将数组的第 0 个位置 `A[0]` 留空，存入待查找的关键字。从后往前扫描。
  *优点：* 免去了每次循环检查指针是否越界的判断，对于数据量大时，能略微提升常数级效率。
* **ASL 计算（等概率下）：**
  * **查找成功：** $ASL_{succ} = \frac{1+2+\dots+n}{n} = \frac{n+1}{2}$
  * **查找失败：** $ASL_{fail} = n + 1$ （如果带哨兵，比较到哨兵才结束）。

### 2. 折半查找 (Binary Search - 二分查找)
* **严苛前提：** 必须是**顺序存储**，且必须**关键字有序**。链表绝对不能用折半查找！
* **核心代码逻辑：**
  ```c
  int low = 0, high = n - 1, mid;
  while (low <= high) {
      mid = (low + high) / 2; // 向下取整
      if (A[mid] == key) return mid;
      else if (A[mid] > key) high = mid - 1;
      else low = mid + 1;
  }
  return -1;
  ```
- **判定树（408重难点）：**
    折半查找的过程可以用一棵二叉树来描述。
    1. 判定树必定是一棵**平衡二叉树**。
    2. 若 $n$ 为偶数，则 `mid` 偏向左侧，右子树结点数比左子树多 1。
    3. 若 $n$ 为奇数，则左右子树结点数相等。
    4. 树的高度 $h = \lceil \log_2(n+1) \rceil$。
    5. 查找成功的 ASL $\approx \log_2(n+1) - 1$，时间复杂度 $O(\log n)$。
    6. 查找失败的 ASL：等于走到判定树所有的**外部空结点（方形叶子）** 的路径长度的平均值。

### 3. 分块查找 (Block Search / 索引顺序查找)

- **基本思想：** 将查找表分为若干子块。**块间有序**（第 $i$ 块所有元素均小于第 $i+1$ 块），**块内无序**。
- **索引表：** 其中的每个元素包含对应块的最大关键字和该块的起始地址，且索引表按最大关键字有序排列。
- **查找过程：**
    1. 在索引表中**顺序或折半**查找，确定目标所在的块。
    2. 在确定的块内进行**顺序查找**。
- **最佳块长与 ASL：**
    若表长为 $n$，均匀分为 $b$ 块，每块 $s$ 个元素（$n=bs$）。
    若在索引表和块内均用顺序查找，则 $ASL = ASL_{索引} + ASL_{块内} = \frac{b+1}{2} + \frac{s+1}{2}$。
    当 $s = \sqrt{n}$ 时，ASL 取得极小值 $\sqrt{n} + 1$。

## 三、二叉树结构的查找（动态查找表）

### 1. 二叉搜索(排序)树 (BST - Binary Search Tree)
- **定义性质：** 左子树所有结点 $<$ 根 $<$ 右子树所有结点。
- **中序遍历性质：** 对 BST 进行中序遍历，必然得到一个**严格单调递增**的序列。
- **插入与删除：**
    - _插入：_ 新结点一定是作为**叶子结点**插入的，不会改变原有结点的相对结构。
    - _删除（三种情况）：_
        1. 若是叶子：直接删。
        2. 若只有一个孩子：让孩子顶替自己的位置。
        3. 若有两个孩子：找中序遍历下的**直接前驱（左子树最右下结点）**或**直接后继（右子树最左下结点）**顶替自己，然后转化为删除那个前驱/后继结点。

### 2. 平衡二叉树 (AVL 树)
为了防止 BST 退化成单链表（$O(n)$），引入平衡机制。
- **定义：** 树上任一结点的左子树和右子树的高度差（平衡因子 $BF$）的绝对值不超过 1。即 $BF \in \{-1, 0, 1\}$。
- **高度与最少结点数公式（常考）：**
    深度为 $h$ 的 AVL 树所需的最少结点数 $N_h$ 满足：
    $$N_h = N_{h-1} + N_{h-2} + 1 \quad (N_0=0, N_1=1, N_2=2)$$
- **四种旋转调整（找最小不平衡子树）：**
    1. **LL 型（右单旋）：** 在 A 的左孩子的左子树插入导致 A 失衡。A 向右下旋转。
    2. **RR 型（左单旋）：** 在 A 的右孩子的右子树插入导致 A 失衡。A 向左下旋转。
    3. **LR 型（先左后右双旋）：** 在 A 的左孩子 (B) 的右子树 (C) 插入。先将 C 左旋上去代替 B，再将 C 右旋上去代替 A。
    4. **RL 型（先右后左双旋）：** 在 A 的右孩子的左子树插入。类似 LR。

### 3. 红黑树 (Red-Black Tree) - 408 新贵
AVL 树维持平衡的代价太高，红黑树允许局部不平衡，以换取插入/删除时更少的旋转次数。
- **五条根本法则（口诀：左根右，根叶黑，不红红，黑路同）：**
    1. 每个结点或是红色，或是黑色。
    2. **根结点是黑色**。
    3. 叶结点（虚构的外部 NULL 结点）是黑色。
    4. **不存在两个相邻的红结点**（红结点的父子必为黑）。
    5. 对每个结点，从该结点到任一叶结点的简单路径上，**包含的黑结点数目相同**（黑高相等）。
- **性能：** 红黑树的最坏树高不超过 $2 \log_2(n+1)$，查找、插入、删除的时间复杂度均为 $O(\log n)$。

## 四、多路平衡查找树（外存索引核心）
### 1. B 树 (B-Tree)
B 树是所有结点的平衡因子均为 0 的多路查找树。常用于数据库和文件系统的**磁盘索引**。
- **一棵 $m$ 阶 B 树的核心规则（数字极值必背）：**
    1. 根结点子树数：$[2, m]$ （除非是只有根的孤树）。
    2. 非根内部结点的子树数：$[\lceil m/2 \rceil, m]$。
    3. 每个结点的关键字个数：$n = 子树数 - 1$。所以非根内部结点关键字范围是 $[\lceil m/2 \rceil - 1, m - 1]$。
    4. 所有叶子结点（表示查找失败的外部结点）都出现在**同一层**。
- **插入操作：**
    插入必然在最底层的终端结点进行。如果插入后关键字数量 $> m-1$，则发生**分裂**。分裂把中间关键字上抛给父结点，左右两边分裂为两个新结点。若父结点因接受该关键字而超出上限，则对父结点递归执行分裂操作，若根结点也被分裂，则B树高度加1。
- **删除操作：**
	删除 B 树中的节点分为两种核心情况：**删除非叶子节点** 和 **删除叶子节点**。无论哪种情况，最终都会转化为对叶子节点的处理。
	1. 如果删除的是【非叶子节点】（核心思想：转化为叶子节点删除）
	 在非叶子节点中删除关键字时，**绝对不能直接把那个位置空出来**，而是要找一个“替身”来顶替它的位置。
	 * **找替身（前驱或后继）：**
	   * **直接前驱：** 找到该关键字**左子树**中一直向右走到底的那个关键字（即左子树中的最大值，一定在叶子节点上）。
	   * **直接后继：** 找到该关键字**右子树**中一直向左走到底的那个关键字（即右子树中的最小值，一定在叶子节点上）。
	 * **替换并转移目标：** 将“前驱”或“后继”的关键字复制到要删除的非叶子节点位置，然后把原本要删除的任务，**转移为去删除那个位于叶子节点上的“前驱”或“后继”关键字**。
	2. 如果删除的是【叶子节点】
	 直接在叶子节点上删除目标关键字。删除后，需要检查该节点剩余的关键字数量，判断是否满足 B 树的特性（关键字数量 $\ge \lceil m/2 \rceil - 1$）。
	 * **情况 A：删除后关键字数量 $\ge \lceil m/2 \rceil - 1$**
	   * 节点依然合法，直接删除即可，无需任何后续调整。
	 * **情况 B：删除后关键字数量 < $\lceil m/2 \rceil - 1$（发生下溢，需要借用或合并）**
	   * **① 兄弟够借（发生借用/旋转）：**
	     * 先看相邻的左/右兄弟节点是否“富裕”（即兄弟的关键字数量 $\ge \lceil m/2 \rceil$）。
	     * 如果左（或右）兄弟够借：**父节点下来，兄弟上去**。
	     * *(具体操作：把父节点中夹在两者之间的关键字挪到当前节点，再把兄弟节点中最大（或最小）的关键字挪到父节点中填补空缺)*。
	   * **② 兄弟不够借（发生合并）：**
	     * 如果相邻的兄弟节点也很穷（即关键字数量刚好等于 $\lceil m/2 \rceil - 1$），借不了。
	     * 此时只能**合并**：将当前节点、相邻的兄弟节点、以及夹在两者之间的**父节点关键字**，三者合并成一个新的节点。
	     * *(注意：合并操作会消耗掉父节点中的一个关键字，这可能会导致父节点也发生“下溢”。如果父节点下溢，则对父节点递归执行上述的“借用或合并”规则，最极端的情况会一直合并到根节点，导致树的高度减 1)*。
	
>**学习建议：** 在做 408 统考题时，遇到非叶子结点的删除，优先找“直接前驱”或“直接后继”来替换，这两种做法在考试中都是公认正确的，具体用哪一个可以根据哪个借起来更容易（不触发合并）来决定。
* 最小高度：$h\ge log_m(n+1)$
* 最大高度：$h \le log_ {\lceil m/2 \rceil}((n+1)/2)+1$
* 对于包含$n$个关键字的B树，其外部叶结点数量恒为$n+1$
    * 假设 B 树中总共有 n 个关键字（无论它们怎么分布在各个结点里）。
    * 如果把这 n 个关键字按从小到大的顺序铺在一条数轴上，这 n 个点会把整个数轴切分成多少个**查找区间**？
    * 答案显然是 **n+1** 个区间。

>在 B 树中，**这 n+1 个查找区间，完美对应了当查找不到具体关键字时，最终会掉入的 n+1 个空指针（也就是叶结点）**。

### 2. B+ 树 (B+ Tree)
B 树的变体，现代关系型数据库（如 MySQL InnoDB）的标准索引结构。
- **与 B 树的核心差异：**
    1. 非叶子结点**仅起到索引作用**，不包含实际记录的数据！所有记录的数据和关键字的真实面貌都在**叶子结点**。
    2. 结点的子树个数与关键字个数**相等**（而在 B 树中是子树数 = 关键字数 + 1）。
    3. 所有叶子结点被串联成一个**有序单链表**，极其方便范围查询和顺序查找。
    4. B+ 树的查找无论成功与否，**必须走到最底层的叶子结点**。查找性能非常稳定。

## 五、散列表 (Hash Table)
散列表利用空间换时间的思想，通过**散列函数**将关键字直接映射到存储地址。
### 1. 散列函数的构造
- **除留余数法（最常用、必考）：** $H(key) = key \% p$。
    为尽可能减少冲突，$p$ 应该选取一个**不大于散列表长 $m$ 的最大质数（素数）**。
### 2. 冲突处理方法（冲突不可避免）
**（1）开放定址法：** 冲突了就去表里找下一个空位。
- **线性探测法：** $d_i = (H(key) + i) \% m$。挨个往后找。
    _致命缺点：_ 容易引起**堆积（聚集）现象**，不仅拖慢当前元素的插入，还会连累无关元素的查找。
- **平方探测法（二次探测法）：** $d_i = (H(key) + 1^2), (H(key) - 1^2), (H(key) + 2^2), \dots$。可以避免同义词聚集。
- **双散列法：** $d_i = (H(key) + i \times H_2(key)) \% m$。用第二个哈希函数决定步长

**（2）拉链法（链地址法）：**
把所有映射到同一个地址的同义词用一个单链表连接起来。这种方法**完全没有堆积现象**，且由于结点动态分配，装填因子可以 $> 1$。

### 3. 装填因子 $\alpha$

$$\alpha = \frac{表中已填入的记录数}{散列表的长度}$$

$\alpha$ 越大，表越满，发生冲突的可能性越大。散列表的 ASL 是 $\alpha$ 的函数，而**不直接依赖于数据量 $n$**。

## 六、字符串的模式匹配（KMP 算法）
在主串 $S$ 中寻找是否包含子串 $T$ 的过程。
### 1. 朴素模式匹配 (Brute-Force)

主串指针 $i$ 与子串指针 $j$ 逐个比较。一旦失配，$i$ 会退回到上次匹配起点的下一个位置，$j$ 回退到 $1$。
- 最坏时间复杂度：$O(nm)$。

### 2. KMP 算法
- **核心思想：** 利用模式串 $T$ 自身内部的重复结构（相同的前缀和后缀），使得在匹配失败时，**主串指针 $i$ 永远不回退**，只有模式串指针 $j$ 回退到 $next[j]$ 的位置。
- **时间复杂度：** $O(n + m)$。
- **`next` 数组的手工求解法则（必考大题/选择）：**
    1. `next[1] = 0`，`next[2] = 1`（硬性规定，针对考研大纲下标从 1 开始）。
    2. 针对 $j \ge 3$，截取模式串 $1 \sim (j-1)$ 的子串。
    3. 寻找该子串中，**相等的最长前缀和最长后缀**。
    4. `next[j] = 最长相等前后缀长度 + 1`。
- **`nextval` 优化数组：**
    解决 KMP 中无效重复比较的缺陷。
    若 $T[j] == T[next[j]]$，则 `nextval[j] = nextval[next[j]]`；
    否则 `nextval[j] = next[j]`。

## 七、408 高频易错点扫雷（首轮警戒线）

1. **ASL 的分母陷阱：** 计算拉链法的失败 ASL 时，分母不是链表节点总数，而是**散列函数的模数 $p$**！即计算散列到 $0 \sim p-1$ 每个槽位的链表比较次数之和，再除以 $p$。
2. **折半查找判定树形态：** 给定序列长度，折半查找判定树的形态是**唯一**的。如果题目让画判定树，严格按照 `(low+high)/2` 向下取整的规则手推。
3. **AVL 与红黑树对比：** AVL 树追求绝对平衡，查找最快，但插入/删除时旋转代价极大；红黑树追求局部平衡，查找略逊于 AVL，但插入/删除的常数时间极佳，适合 `C++ STL map/set`。
4. **B+ 树的特有性质：** B+ 树的非叶节点仅仅是索引，不存数据。所以在 B+ 树中，无论查找的目标在不在索引层中，都**必须向下走到叶子结点**才算找到真身。
5. **KMP 的 $O(n+m)$ 解释：** 求 `next` 数组的时间复杂度为 $O(m)$，利用 `next` 数组进行主串匹配时间复杂度为 $O(n)$。
