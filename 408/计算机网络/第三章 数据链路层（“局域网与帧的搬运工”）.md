## 一、数据链路层解决什么问题与基本功能

#### 1. 核心概念
* **结点：** 主机、路由器。
* **链路 (Link)：** 网络中两个结点之间的**物理通道**（无源的点到点物理线路段）。
* **数据链路 (Data Link)：** 网络中两个结点之间的**逻辑通道**，把实现控制数据传输的**协议的硬件和软件**加到链路上就构成了数据链路。
* **传输单位：** 帧 (Frame)。
* **本质任务：** 将物理层提供的可能出错的物理连接改造为逻辑上无差错的数据链路。

#### 2. 三个基本问题（数据链路层必备功能）
1. **封装成帧：** 将网络层交下来的 IP 数据报添加首部和尾部，封装成帧。首部和尾部包含重要的控制信息。
2. **透明传输：** 不管所传数据是什么样的比特组合，都应当能在链路上传送。如果数据中出现了与帧定界符相同的比特串，必须采取措施屏蔽（字符填充/比特填充）。
3. **差错检测：** 接收方必须能检测出帧在传输过程中是否出现了比特差错（1变0，0变1）。

## 二、组帧 (Framing) 技术

组帧的目的是让接收方能从比特流中准确划分出帧的起始和终止。

### 1. 字符计数法
* 在帧头部使用一个计数字段，标明帧内字符数(*包括计数字段自身占用的1B*)。
* **致命缺点：** 一旦计数字段出错，接收方将无法正确划分后续所有帧，导致**灾难性失去同步**。
* ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260908.png)

### 2. 字符填充法（面向字节）
* 使用特定的控制字符（如 `SOH` 表示首，`EOT` 表示尾）作为定界符。
* 当数据部分出现 `EOT` 或 `SOH` 时，在其前面插入转义字符 `ESC`。
* ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260908%201.png)

### 3. 零比特填充法（面向比特，重中之重）
* **规则：** 使用 `01111110` 作为帧定界符。
* **发送方（“5 个 1 塞 1 个 0”）：** 只要发现数据流中有连续 5 个 1，就立即插入一个 0。
* **接收方（“5 个 1 删 1 个 0”）：** 只要发现连续 5 个 1，就把其后的一个 0 删除。
* **优点：** 硬件实现容易，适用任意长度比特流，是**目前最常用的方法**（如 HDLC 协议）。
* ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260908%202.png)

### 4. 违规编码法
* 利用物理层编码的违规状态来定界。例如曼彻斯特编码中，只用“高-低”和“低-高”，可以把“高-高”或“低-低”作为定界符。局域网标准常用。

## 三、差错控制 (Error Control)

实际通信链路并非理想，传输中可能产生**比特差错**（1 变 0 或 0 变 1）。通常采用编码技术进行差错控制：
- **检错编码**：接收方仅能检测出差错，通知发送方重传（**数据链路层只提供检错，丢弃错误帧，通常不提供纠错**，部分无线网络除外）。
- **纠错编码**：接收方不仅能发现差错，还能直接确定错误位置并予以纠正。

### 1. 码距（海明距离）与差错控制理论（高频考点）

- **码距概念**：指两个等长码字在对应位上取值不同的比特数量。
  - **计算方法**：对两个码字进行**按位异或 (XOR)** 运算，结果中 **“1” 的个数** 即为两者的码距。
    > 例如：$0110 \oplus 0011 = 0101$，结果中有两个 1，故两码字的码距为 2。
  - **编码集的码距 ($l$)**：一个编码集中，**任意两个有效码字之间码距的最小值**。
    > 例如：编码集 $\{10011, 01011, 11110, 00001\}$ 中，两两最小码距为 2，则该编码集的码距 $l = 2$。
- **码距 $l$ 与检错/纠错能力的关系公式**：
  - **仅检错**：若要检测 $d$ 位错误，编码方案的码距至少为：
    $$l \ge d + 1$$
    （确保任何有效码字发生 $\le d$ 位跳变后，绝不可能变成另一个有效码字）。
  - **仅纠错**：若要纠正 $c$ 位错误，编码方案的码距至少为：
    $$l \ge 2c + 1$$
    （即使发生 $\le c$ 位跳变，受损码字距离原正确码字仍然最近，可唯一确定）。
  - **同时检错与纠错**：若要纠正 $c$ 位错误的同时再检测出 $d$ 位错误（满足 $d \ge c$）：
    $$l \ge d + c + 1$$
- **核心结论**：纠错能力恒不超过检错能力（$c \le d$），**能纠错必然能检错**。

### 2. 检错编码：奇偶校验码

- **基本思想**：由 $n-1$ 位信息元和 1 位校验元组成。
  - **奇校验**：整个码字中“1”的个数为奇数。
  - **偶校验**：整个码字中“1”的个数为偶数。
- **性能与局限**：编码方案码距 $l = 2$。**只能检测出奇数个比特错误**，无法检测偶数个错误，也**无法定位和纠正**错误。

### 3. 检错编码：循环冗余校验 (CRC)（必考计算题理论）

- **基本思想**：发送方和接收方约定一个生成多项式 $G(x)$(*最高位和最低位必须为1*)。发送方用数据比特流去除以 $G(x)$，将得到的余数作为**帧检验序列 (FCS)** 附加在数据帧后面。接收方收到后，用带有 FCS 的帧去除以 $G(x)$，若余数为 0，则认为无差错。
- **模 2 运算**：加减法不进位、不借位，完全等价于**按位异或 (XOR)** 运算（相同为 0，不同为 1）。
- **FCS 位数**：等于生成多项式 $G(x)$ 的**最高阶数 $r$**（在数据末尾补 $r$ 个 0 再做模 2 除法）。
- **408 高频提醒**：CRC 只能做到**“无差错接受”**（凡是接收下来的帧都认为没有差错），但它**不是“可靠传输”**。可靠传输还需要确认和重传机制。

### 4. 纠错编码：海明码 (Hamming Code)（计网/计组核心考点）

- **基本思想**：在有效数据位中插入若干校验位，每个校验位对应一个**校验组**（通常采用**偶校验**），用于校验海明码中的若干信息位。当某一位出错时，会引发其所属的多个校验组同时出错，通过指误字不仅能发现错误，还能精确确定出错位置并取反纠正（实现**单比特纠错**）。

---

#### 构造与纠错全过程（以信息位 $D = 1010$ 为例）

##### (1) 确定海明码的总位数
- **不等式约束**：设信息位有 $n$ 位，校验位有 $k$ 位。$k$ 个校验位能提供 $2^k$ 种状态，需覆盖 $n+k$ 种单比特出错位置以及 1 种无错状态，需满足：
  $$2^k \ge n + k + 1$$
- **求解**：本例中 $n = 4$。
  - 尝试 $k = 3$：$2^3 = 8 \ge 4 + 3 + 1 = 8$（不等式刚好成立）。
  - 取 $k = 3$，海明码总长为 $n + k = 7$ 位。
  - 记信息位为 $D_4 D_3 D_2 D_1 = 1010$，校验位为 $P_3 P_2 P_1$，海明码从左至右记为 $H_7 H_6 H_5 H_4 H_3 H_2 H_1$。

##### (2) 确定校验位的分布
- **分布规则**：校验位 $P_i$ 必须放置在海明码位号为 $2^{i-1}$ 的位置上，其余位置顺次放入信息位：
  - $P_1$ 位于 $2^{1-1} = 2^0 = 1$，即 $H_1$
  - $P_2$ 位于 $2^{2-1} = 2^1 = 2$，即 $H_2$
  - $P_3$ 位于 $2^{3-1} = 2^2 = 4$，即 $H_4$
- **分布对应关系**：
- 
  | 海明码位号 | $H_7$ | $H_6$ | $H_5$ | $H_4$ | $H_3$ | $H_2$ | $H_1$ |
  | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
  | **对应数据** | $D_4$ | $D_3$ | $D_2$ | $P_3$ | $D_1$ | $P_2$ | $P_1$ |

##### (3) 分组以形成校验关系
- **分组规则**：每个信息位由多个校验位共同校验。**信息位所在的二进制位号 = 其所参与的所有校验位的位号之和**（校验位自身不再被校验）：
  - $D_1$ 位于 $H_3$：$3 = (011)_2 = 2 + 1 \implies$ 由 $H_2(P_2)$ 和 $H_1(P_1)$ 校验
  - $D_2$ 位于 $H_5$：$5 = (101)_2 = 4 + 1 \implies$ 由 $H_4(P_3)$ 和 $H_1(P_1)$ 校验
  - $D_3$ 位于 $H_6$：$6 = (110)_2 = 4 + 2 \implies$ 由 $H_4(P_3)$ 和 $H_2(P_2)$ 校验
  - $D_4$ 位于 $H_7$：$7 = (111)_2 = 4 + 2 + 1 \implies$ 由 $H_4(P_3)$、$H_2(P_2)$ 和 $H_1(P_1)$ 校验

##### (4) 计算校验位的取值（偶校验）
- 各校验位 $P_i$ 的值为其校验组中所有信息位的**异或 (XOR)** 结果：
  - $P_1$ 校验 $D_1, D_2, D_4 \implies P_1 = D_1 \oplus D_2 \oplus D_4 = 0 \oplus 1 \oplus 1 = \mathbf{0}$
  - $P_2$ 校验 $D_1, D_3, D_4 \implies P_2 = D_1 \oplus D_3 \oplus D_4 = 0 \oplus 0 \oplus 1 = \mathbf{1}$
  - $P_3$ 校验 $D_2, D_3, D_4 \implies P_3 = D_2 \oplus D_3 \oplus D_4 = 1 \oplus 0 \oplus 1 = \mathbf{0}$
- 将校验位代入，得到 $1010$ 的海明码为：$\mathbf{101}\underline{\mathbf{0}}\mathbf{0}\underline{\mathbf{1}}\underline{\mathbf{0}}$（下划线为校验位）。

##### (5) 海明码的检错与纠错原理
- **构建指误字（伴随式方程组）**：接收端用偶校验核对每个校验组：
  $$\begin{cases} S_1 = P_1 \oplus D_1 \oplus D_2 \oplus D_4 \\ S_2 = P_2 \oplus D_1 \oplus D_3 \oplus D_4 \\ S_3 = P_3 \oplus D_2 \oplus D_3 \oplus D_4 \end{cases}$$
- **判定与纠错**：
  - 若 $S_3 S_2 S_1 = 000$，说明传输无差错。
  - 若 $S_3 S_2 S_1 \ne 000$，***其十进制数值直接对应出错位的位置编号*** 。
    > 例如：若 $S_3 S_2 S_1 = 011$，十进制为 $3$，表明第 3 位（$H_3 / D_1$）出错，将其直接取反（$0 \to 1$ 或 $1 \to 0$）即可纠正。

## 四、流量控制与可靠传输机制（核心重中之重）

* 数据链路层和传输层均具备流量控制的功能，且都采用了**滑动窗口**的思想，但二者存在明显区别，主要体现在以下两方面。
  * 1）数据链路层控制的是**相邻节点之间**的流量，而传输层控制的是**端到端的流量**。
  * 2）数据链路层的控制手段是：当接收方无法接收时，不返回确认帧；而传输层的控制手段是：接收方在确认报文段中携带窗口字段值，动态调整发送方的发送窗口大小。

### 1. 停止-等待协议 (Stop-and-Wait)
* **机制：** 发送方每次仅允许发送一帧，且必须等待接收方的确认应答（ACK）才能发送下一帧。
* **特点：** 窗口大小：发送窗口 $W_T = 1$，接收窗口 $W_R = 1$。
* **缺点：** 信道利用率极低（大部分时间在等待传播时延）。

### 2. 后退 N 帧协议 (GBN, Go-Back-N)
* **机制：** 发送方可以连续发送多个帧。接收方只**按序接收**，并采用**累积确认**（发送 ACK n，表示 n 号及之前的帧已全部正确收到）。
* **出错处理：** 如果丢失了第 $n$ 帧，即使接收方收到了 $n+1, n+2$ 帧，也会丢弃它们。发送方超时后，必须**重传第 $n$ 帧及其后面的所有帧**。
* **窗口限制：** 若采用 $n$ 个比特对帧编号，则发送窗口大小必须满足：**$1 < W_T \le 2^n - 1$**。接收窗口 $W_R = 1$。
* **优点：** 提高了信道利用率。
* **缺点：** 重传代价大，适用于信道质量好的网络。

### 3. 选择重传协议 (SR, Selective Repeat)
* **机制：** 发送方连续发送多个帧。接收方有**缓存**，可接收**失序但正确**的帧，并采用**单独确认**（收到哪个就确认哪个）。
* **出错处理：** 发送方只重传没有收到确认的帧。
* **窗口限制：** 发送窗口通常小于等于接收窗口，且必须满足：**$W_T + W_R \le 2^n$ 且 $W_T = W_R \le 2^{n-1}$**。
* **优点：** 减少了无谓的重传，效率最高，适用于信道质量较差的网络。

| 协议       | 发送窗口$W_T$ | 接收窗口$W_R$ |
| :--------: | :---------: | :---------: |
| 停止‑等待协议  | $W_T=1$   | $W_R=1$   |
| 后退$N$帧协议 | $W_T>1$   | $W_R=1$   |
| 选择重传协议   | $W_T>1$   | $W_R>1$   |

## 五、介质访问控制 (MAC 子层)

决定广播信道中信道分配的协议。

### 1. 静态划分信道（信道复用）
* **频分 FDM / 时分 TDM / 波分 WDM / 码分 CDM**[[408/计算机网络/第二章 物理层（“比特传输的基石”）## 五、信道复用技术（408核心考点）|信道复用]]（通常放在物理层讨论，但本质是介质访问控制）。不会发生冲突。

### 2. 动态分配信道 —— 随机访问介质访问控制（核心）

用户随机发送数据，占用信道时既不预留时间，也不独占频段，实质上是将广播信道动态转化为点到点信道。所有站点共享信道，极易产生冲突。

#### 2.1 ALOHA 协议

- **纯 ALOHA 协议 (Pure ALOHA)**：
  - **基本思想**：想发就发，不进行任何信道检测。若在一段时间内未收到确认，则认为发生了冲突；站点等待一段随机时间后重传，直至成功。
  - **易冲突期（危险时间）**：$2T_0$（$T_0$ 为帧的发送时延。在某帧发送前 $T_0$ 到发送后 $T_0$ 期间，只要有其他站点发帧，就会发生碰撞）。
  - **吞吐量性能**：吞吐量极低，最大信道利用率仅为 $S_{\max} = \frac{1}{2e} \approx 18.4\%$。

- **时隙 ALOHA 协议 (Slotted ALOHA)**：
  - **基本思想**：把时间划分为若干等长的**时隙 (Slot)**，并要求**全网站点时钟严格同步**。站点只能在**时隙起始时刻**发送数据，且帧长对应的发送时间必须 $\le$ 一个时隙。
  - **机制改进**：消除了时隙中间随时发送的随意性。一个时隙内若有两个及以上的帧到达，则在该时隙初同时发送导致冲突，等待随机时间后再选时隙重传。
  - **易冲突期（危险时间）**：缩短为 $T_0$（仅当前时隙内重叠才会碰撞）。
  - **吞吐量性能**：吞吐量比纯 ALOHA 提高了一倍，最大信道利用率 $S_{\max} = \frac{1}{e} \approx 36.8\%$。

---

#### 2.2 CSMA 协议 (载波监听多路访问, Carrier Sense Multiple Access)

- **核心演进思想**：“**先听后发**”。ALOHA 协议站点完全盲发；CSMA 在其基础上引入了**载波监听**机制（利用硬件检测总线上是否有其他信号在传输），信道空闲才发送，大幅降低碰撞几率。
- **三种监听与退避策略**：
  - **1-坚持 CSMA (1-Persistent)**：
    - **规则**：监听到信道**空闲**，立即以**概率 1** 发送；若监听到信道**忙**，则**持续监听**，一旦变为空闲立即发送。
    - **优缺点**：信道空闲能被立刻利用；但若两个及以上站点同时在持续监听，信道一旦空闲它们会**同时发送**，导致 **100% 发生冲突**。
  - **非坚持 CSMA (Non-Persistent)**：
    - **规则**：监听到信道**空闲**，立即发送；若监听到信道**忙**，则**放弃监听，等待一个随机时间后重新尝试监听**。
    - **优缺点**：有效避免了多个站点在信道变空闲时扎堆发送；但随机退避期间信道可能已经空闲却无人使用，**增加了信道空闲率和平均传输时延**。
  - **$p$-坚持 CSMA ($p$-Persistent)**：
    - **规则**（专用于时隙化信道）：在时隙起点监听。若信道**空闲**，以**概率 $p$** 立即发送，以**概率 $1-p$** 推迟到下一个时隙再监听；若信道**忙**，则**推迟到下一个时隙继续监听**。
    - **优缺点**：1-坚持与非坚持的折中方案。既通过概率延迟减少了冲突爆发，又通过时隙级持续监听避免了过长的随机等待延迟。

##### 表 3.1 三种 CSMA 协议对比（408 高频必背）

| 协议类型 | 对信道“空闲”的处理 | 对信道“忙”的处理 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **1-坚持 CSMA** | **立即发送**（概率为 1） | **持续监听**直至空闲 | 及时利用信道，无空闲等待时延 | 多个站点同时等待时**极易发生冲突** |
| **非坚持 CSMA** | **立即发送** | **放弃监听**，随机等待后再听 | 降低了信道变空闲时的冲突概率 | 站点随机退避使信道闲置，**平均时延大** |
| **$p$-坚持 CSMA** | **概率 $p$ 发送**，概率 $1-p$ 推到下个时隙 | **持续监听**（推迟到下个时隙再听） | 冲突率与信道利用率折中平衡 | 仅适用于时隙化系统，实现复杂度高 |

- **向下一代协议过渡**：
  - CSMA 虽然能“先听”，但由于**电磁波在总线上传播存在时延**，站点听到的“空闲”不代表整条总线没有信号（存在脆弱期），仍可能冲突。
  - 致命缺陷：**发前虽听，边发不听**。一旦发生碰撞，站点仍会坚持将无用的错误帧发送完毕，严重浪费总线带宽。
  - **改进方案**：
    - 有线总线网 $\to$ 增加“边发边听、碰撞即停”机制，演进为 **CSMA/CD**。
    - 无线局域网 $\to$ 因隐蔽站问题及硬件无法实现边发边听，转为“主动预约规避”，演进为 **CSMA/CA**。

#### 3. CSMA/CD 协议（载波监听多路访问/碰撞检测 —— 802.3 传统以太网）
* **工作过程：** “先听后发，边发边听，冲突停发，随机重发”。
* **争用期 (冲突窗口)：** 端到端传播时延 $\tau$ 的两倍，即 **$2\tau$**。发送方如果在发送数据的前 $2\tau$ 时间内没有检测到碰撞，那么这次发送就不会发生碰撞。
* **最小帧长公式（必考重点）：**
  $$最小帧长 = 争用期 \times 数据传输速率 = 2\tau \times 带宽$$
  如果发送的帧小于最小帧长，必须进行填充。以太网规定最小帧长为 **64 字节**。
* **截断二进制指数退避算法：** 发生冲突后，重传前退避的时间随机取自 $\{0, 1, \dots, 2^k - 1\} \times 2\tau$，其中 $k = \min(\text{重传次数}, 10)$。重传 16 次仍失败则报错丢弃。

#### 4. CSMA/CA 协议（载波监听多路访问/碰撞避免 —— 802.11 无线局域网）

- **为什么不采用 CSMA/CD**：
  - **硬件无法实现碰撞检测**：无线电波衰减剧烈，接收信号强度远小于发送信号强度（动态范围极大），适配器无法在发送时同时检测微弱的碰撞信号。
  - **隐蔽站问题 (Hidden Terminal)**：各站点无线覆盖范围有限，站点 A 和 B 同时在 AP 覆盖范围内但彼此无法侦听对方。若两站同时向 AP 发送数据，将在 AP 处发生冲突，普通载波监听无法察觉。
  - ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910%201.png)

- **MAC 层协调功能**：
  - **分布式协调功能 (DCF)**：争用信道机制，每个站点通过竞争独立获取信道访问权（**802.11 必须实现的核心方式**）。
  - **点协调功能 (PCF)**：集中轮询机制，由 AP 集中轮询各站点分配信道（可选方式，极少使用）。

- **帧间间隔 (IFS, InterFrame Space)**：
  - **SIFS (短帧间间隔)**：最短的 IFS，优先级最高。用于高优先级的即时响应帧，如 ACK 帧、CTS 帧、分片响应帧。
  - **PIFS (点协调 IFS)**：中等长度，在 PCF 轮询方式中使用。
  - **DIFS (分布式协调 IFS)**：最长的 IFS，优先级最低。用于 DCF 方式下普通数据帧和管理帧的发送。

- **退避机制与算法细节**：
  - **必须启动退避的 3 种情形**：
    1. 发送第一个数据帧之前检测到信道忙；
    2. 未收到 ACK 确认，需要重传数据帧；
    3. 每次成功发送后，发送下一个连续数据帧（强制退避以保障其他站点的公平性）。
  - **退避算法规则**：
    - 退避时间取自 $[0, 2^{4+k} - 1]$ 个时隙（$k$ 为重传次数，最大退避至 1023 个时隙，即重传 6 次后不再增加）。
    - **推迟接入 vs 退避**：信道忙时，退避计时器**冻结（暂停倒减）**，此阶段称为推迟接入；只有当信道变为空闲且**持续经过一个 DIFS** 后，才进入争用期，计时器才开始按时隙**倒计时**。计时器归零时立即发送。
- ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910%202.png)

- **信道预约与虚拟载波监听 (解决隐蔽站)**：
  - **RTS / CTS 握手控制机制**：
    1. 源站 A 监听信道空闲并等待 DIFS 后，广播 **RTS (请求发送)** 短帧，首部写入占用信道总时长。
    2. AP 收到 RTS 且信道空闲，等待 SIFS 后广播 **CTS (允许发送)** 短帧，不仅授权源站发送，也通知其覆盖的所有隐蔽站。
    3. 源站 A 收到 CTS，等待 SIFS 后发送数据帧 **DATA**；AP 正确接收后，等待 SIFS 发送 **ACK 确认帧**。
  - **虚拟载波监听 (NAV, Network Allocation Vector)**：
    - 其他站点（如隐蔽站 B）只要收到 RTS、CTS 或 DATA 中的任意一帧，提取首部中的**持续期 (Duration)**，将该时长写入自身的 **NAV**。
    - 在 NAV 倒计时未归零前，即使物理侦听信道为空闲，也**绝对不发送任何信号**，从逻辑上彻底避免隐蔽站干扰。

- **停止-等待确认机制 (ACK)**：
  - 无线信道误码率极高，802.11 在数据链路层采用停止-等待式 ARQ。发送方每发完一帧，必须收到接收方的 ACK 确认帧才算发送成功，超时未确认则执行二进制指数退避重传。

- **CSMA/CD 与 CSMA/CA 核心对比**：
- 
  | 维度 | CSMA/CD | CSMA/CA |
  | :--- | :--- | :--- |
  | **传输介质** | 有线总线以太网 | 无线局域网 (802.11) |
  | **核心思想** | **边发边听，撞了就停** | **先打招呼，再发数据** |
  | **冲突处理** | 能实时检测冲突，立即终止发送 | 无法实时检测冲突，重在主动预约降低冲突率 |
  | **链路层确认** | 无确认帧（由上层 TCP 处理可靠性） | 必须依赖 ACK 确认（停等式重传） |

#### 5. 802.11 局域网的 MAC 帧

- **帧结构组成（共 3 部分）**：
  - **MAC 首部（共 30 字节）**：
    - **帧控制字段 (2B)**：包含协议版本、类型与子类型（数据帧、控制帧如 RTS/CTS/ACK、管理帧）、去往 AP (**To DS**)、来自 AP (**From DS**)、更多分片、重传标志、功率管理等。
    - **持续期 / ID (2B)**：用于设置 NAV 虚拟载波监听的时间（微秒）。
    - **4 个地址字段（各 6B，共 24B）**：地址 1、地址 2、地址 3、地址 4（地址 4 仅用于无线自组网/网桥间转发）。
    - **序号控制字段 (2B)**：包含片段号与序号，用于分片和重组。
  - **帧主体 (Data)**：数据载荷，长度为 $0 \sim 2312\text{ B}$（远大于以太网的 $1500\text{ B}$）。
  - **MAC 尾部 (FCS, 4B)**：循环冗余校验序列。
- ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910%203.png)


- **核心四地址字段含义（408 必考大题/选择题）**：
  - 地址含义由帧控制字段中的 **To DS**（去往 AP）和 **From DS**（来自 AP）共同决定：
  
  | To DS | From DS | 地址 1（直接接收端） | 地址 2（直接发送端） | 地址 3（终点或起点） | 地址 4 | 应用场景 |
  | :---: | :---: | :--- | :--- | :--- | :---: | :--- |
  | **0** | **1** | **目的站地址 (B)** | **AP 地址** | **源站地址 (A)** | — | **AP $\to$ 终端站 (下行)** |
  | **1** | **0** | **AP 地址** | **源站地址 (A)** | **目的站地址 (B / 网关)** | — | **终端站 $\to$ AP (上行)** |

- **通信过程中的帧转换与路由（跨网段传输全景）**：
  - **阶段一：终端 A $\to$ AP1（无线信道）**：
    - 封装为 802.11 帧：`To DS=1, From DS=0`；
    - `地址 1 = AP1 的 MAC`，`地址 2 = A 的 MAC`，`地址 3 = 默认网关路由器接口 L1 的 MAC`。
  - **阶段二：AP1 $\to$ 路由器 R（有线以太网信道）**：
    - AP1 剥离 802.11 首部，转换为 **802.3 以太网帧**（仅含 2 个 MAC 地址）：`目的 MAC = L1 的 MAC`，`源 MAC = A 的 MAC`。
  - **阶段三：路由器 R 转发至子网 2（有线以太网信道）**：
    - 路由器网络层根据目标 IP 查路由表，将数据报转发至接口 L2，封装为以太网帧送往 AP2：`目的 MAC = AP2 的 MAC`，`源 MAC = L2 的 MAC`。
  - **阶段四：AP2 $\to$ 终端 B（无线信道）**：
    - AP2 重新封装为 802.11 帧：`To DS=0, From DS=1`；
    - `地址 1 = B 的 MAC`，`地址 2 = AP2 的 MAC`，`地址 3 = 路由器接口 L2 的 MAC`。

#### 6. 动态分配信道 —— 轮询访问介质访问控制
* **令牌传递协议：** 令牌（一个特殊的控制帧）在环形网中按顺序传递。拿到令牌的站才能发送数据。适合**负载重**、通信量大的网络，不会发生冲突（如令牌环网）。

## 六、局域网与以太网 (Ethernet)

### 1. 局域网基本特性
* **拓扑结构：** 星型、总线型、环型。
* **IEEE 802 标准：** 将数据链路层拆分为两个子层：
  * **LLC (逻辑链路控制) 子层：** 向上层提供服务，与传输媒体无关。
  * **MAC (介质访问控制) 子层：** 与物理媒体直接相关，负责帧的组装和介质访问控制。

### 2. MAC 地址
* 硬件地址，固化在网卡 (NIC) 的 ROM 中。共 **48 位 (6 字节)**。
* 局域网内数据传输的最终寻址依据。

### 3. 以太网的 V2 帧格式（高频考点）
* **前导码：** 8字节。其中7字节为前同步码（实现时钟同步），1字节为帧开始定界符（10101011）。**前导码不计算在帧长内！**
* **目的 MAC (6B) + 源 MAC (6B) + 类型 (2B) + 数据 (46B~1500B) + FCS (4B)。**
* **最小帧长：** 64B。故数据部分最小为 $64 - 18 = 46\text{B}$。不足则填充。
* **最大帧长：** 1518B（即最大数据载荷 MTU 为 1500B）。
* ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910.png)

### 4. 虚拟局域网 (VLAN)
* **本质：** VLAN 是一个逻辑上的广播域。它可以将局域网内的设备从逻辑上划分成一个个网段。
* **作用：** **隔离广播域**，提高安全性，简化网络管理。
* **802.1Q 帧：** 在以太网 V2 帧的源 MAC 地址和类型字段之间，插入了 **4 字节的 VLAN 标签**。
* ![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910%204.png)

## 七、广域网与数据链路层设备

### 1. PPP 协议 (Point-to-Point Protocol)

#### (1) 基本概念与应用场景
- <mark>应用场景</mark>：目前应用最广泛的**点对点**数据链路层协议。主要用于主机接入因特网时与 ISP 之间的点对点通信，以及路由器之间通过专用点对点租用线路直连。
- <u>PPPoE (PPP over Ethernet)</u>：将 PPP 帧封装在以太网帧中传输的扩展技术，使以太网具备身份鉴别与计费能力（如典型的 ADSL 宽带拨号上网）。

#### (2) PPP 的三大组成部分
1. <code>成帧方法</code>：规定如何将 IP 数据报封装为帧，明确界定帧的起始与结束，且受外存/网卡 MTU 限制。
2. <code>LCP (链路控制协议, Link Control Protocol)</code>：用于**建立、配置和测试**底层物理数据链路连接，并在协商阶段商定配置选项（如最大传输单元 MRU、鉴别协议等）。
3. <code>NCP (网络控制协议, Network Control Protocol)</code>：用于为不同的网络层协议建立和配置逻辑连接。每种网络层协议对应一个专属 NCP（例如通过 <u>IPCP</u> 动态协商和分配 IP 地址，支持 IP、IPX 等多种协议共存）。

#### (3) PPP 帧格式与字段解析

![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910%205.png)

| 字段位置 | 字段名称 | 占用长度 | 固定取值 / 典型编码 | 核心含义与功能解析 |
| :--- | :--- | :---: | :--- | :--- |
| **首部** | 标志字段 (F) | `1 字节` | `0x7E` (`01111110`) | 帧定界符，标识帧的开始 |
| **首部** | 地址字段 (A) | `1 字节` | `0xFF` | 预留字段，目前暂无实际寻址定义 |
| **首部** | 控制字段 (C) | `1 字节` | `0x03` | 预留字段，目前暂无实际控制定义 |
| **首部** | 协议字段 | `2 字节` | `0x0021` / `0xC021` / `0x8021` | 指明信息字段类型（`0x0021` 为 IP 数据报；`0xC021` 为 LCP 分组；`0x8021` 为 NCP 分组） |
| **载荷** | 信息字段 (Data) | `0 ~ 1500 字节` | 上层数据分组 | 存放 IP 数据报等有效载荷，受 MTU 限制 |
| **尾部** | 帧校验序列 (FCS) | `2 字节` | CRC 校验冗余码 | 循环冗余校验码，接收端检错失败直接丢弃 |
| **尾部** | 标志字段 (F) | `1 字节` | `0x7E` (`01111110`) | 帧定界符，标识帧的结束 |

> [!warning] 408 核心考点：无最小帧长限制
> PPP 运行于独占信道的**点对点链路**上，不存在信道争用与冲突问题，因此**不需要使用 CSMA/CD 协议，完全没有最小帧长限制**（信息段长度最小可为 `0 字节`；对比之下，以太网帧因碰撞检测要求，数据载荷最少必须达到 `46 字节`）。

#### (4) 透明传输机制
为了防止信息字段中出现与帧定界标志符 `0x7E` 相同的比特序列导致“假定界”，根据物理链路类型的不同采用两种处理策略：
- <mark>异步传输（逐字节传输）</mark> $\to$ <u>字节填充法</u>：
  - 将信息段中出现的每一个 `0x7E` 替换为双字节序列 `(0x7D, 0x5E)`；
  - 若信息段出现转义符 `0x7D`，则替换为 `(0x7D, 0x5D)`；
  - 若出现小于 `0x20` 的 ASCII 控制字符，同样在其前面插入 `0x7D` 进行转义。
- <mark>同步传输（连续比特流）</mark> $\to$ <u>零比特填充法（5 个 1 填入 1 个 0）</u>：
  - 发送端硬件扫描比特流，只要发现连续 5 个 `1`，立即在后面强制插入 1 个 `0`；
  - 接收端硬件检测到连续 5 个 `1` 后面跟着 1 个 `0` 时，自动将其删除以还原原始数据。

#### (5) 链路工作过程与状态机流转

![](assets/第三章%20数据链路层（“局域网与帧的搬运工”）/file-20260910%206.png)

1. *链路静止 (Dead)*：通信起始与终止态，此时用户与网络之间尚无物理连接。
2. *链路建立 (Establish)*：检测到物理载波信号后，双方通过发送 `LCP 分组` 协商链路配置（如配置最大接收单元 MRU、协商鉴别方式）。协商失败退回静止态；成功则进入鉴别态。
3. *身份鉴别 (Authenticate)*：若协商需要鉴别，则执行身份验证机制（如明文验证 <u>PAP</u> 或加盐加密散列验证 <u>CHAP</u>）；验证失败直接进入链路终止态。
4. *网络层协议协商 (Network)*：鉴别成功后，双方调用特定 `NCP 分组` 协商网络层参数（如 IPCP 动态下发 IP 地址、DNS 服务器等）。
5. *链路打开 (Open)*：配置完成，进入正常数据通信状态，全双工传输用户数据报。
6. *链路终止 (Terminate)*：数据传输完毕（或链路异常断开），一方发送 LCP 终止请求分组，确认后释放链路资源，最终回到*链路静止*。

#### (6) PPP 的核心特性归纳
- <u>点对点与全双工</u>：只支持全双工点对点物理链路，不支持多点共享链路（无广播/组播机制，无需 MAC 寻址）。
- <u>不可靠服务</u>：虽然在 LCP 协商阶段有确认响应机制，但在常规数据通信阶段**仅提供无差错接收**（仅靠 CRC 丢弃坏帧），**不提供帧序号与确认重传机制**，属于不可靠传输（传输可靠性由上层传输层保障）。
- <u>面向字节 (Byte-oriented)</u>：所有字段和帧长度均以**整数字节**为单位。


### 2. 以太网交换机 (Switch)
* **本质：** 多端口网桥。工作在数据链路层。
* **工作原理：** 根据以太网帧的**目的 MAC 地址**对帧进行转发。
* **交换方式：**
  * **直通式：** 只检查帧的目的 MAC 地址（前 6 字节）就立即转发，延迟小，缺乏检错。
  * **存储转发式：** 将整个帧缓存并进行 CRC 校验，正确再转发，延迟大，可靠性高。
* **自学习算法（核心）：**
  1. 交换机收到一帧，首先提取**源 MAC 地址**和进入的端口，写入交换表（MAC 地址表）。
  2. 提取**目的 MAC 地址**，在交换表中查找：
     * 若找到对应端口：如果端口与源端口相同，丢弃；如果不同，转发到对应端口。
     * 若找不到对应端口：向除源端口外的**所有端口广播（泛洪 flood）**。

### 3. 共享式以太网 (Shared Ethernet)

#### (1) 基本概念与核心特征
- <mark>体系结构</mark>：以 <u>集线器 (Hub)</u> 为中心连接设备构建的星形物理拓扑局域网。所有主机通过双绞线接入集线器，共享同一物理传输介质和总带宽；逻辑上等价于单条总线型网络。
- <code>工作在物理层</code>：集线器本质是一个多端口中继器，仅对衰减的电信号进行**整形、放大与再生**。它不具备帧解析能力，无法识别 MAC 地址，更没有任何智能寻址、路由或过滤功能。
- <code>半双工与 CSMA/CD</code>：由于物理介质共享，任意时刻网络中只能有一对主机成功通信。多节点并发发送必然引发信号叠加冲突，因此必须依赖 <u>CSMA/CD 协议</u> 展开碰撞检测与退避重传。
- <code>单冲突域与单广播域</code>：所有连接到同一集线器上的主机，逻辑上均处于同一个**冲突域 (Collision Domain)** 和同一个**广播域 (Broadcast Domain)**。
- <code>带宽共享机制</code>：系统总带宽由所有连接站点平均分摊。若网络总带宽为 $C$，接入 $N$ 台主机，则每台主机能获得的平均有效带宽仅为：
  $$\text{平均带宽} = \frac{C}{N}$$
- <code>盲目广播与安全性低</code>：从某一端口接收到的电信号会被集线器**无差别泛洪转发至所有其他端口**。各网卡需自行在数据链路层比对目的 MAC 地址决定是否丢弃，极易被混杂模式网卡嗅探，存在严重的通信泄露风险。

#### (2) 共享式 vs 交换式以太网转发行为对比

| 业务场景 | 共享式以太网（Hub 为中心） | 交换式以太网（Switch 为中心） |
| :--- | :--- | :--- |
| **主机发送单播帧** | 集线器将信号盲目广播到除接收端口外的**所有端口**；非目标网卡自行在数据链路层过滤丢弃。 | 交换机查 MAC 地址表，**点对点精准转发**至目标端口；其他主机完全无感知。 |
| **主机发送广播帧** | 转发到除接收端口外的所有端口；各网卡识别广播 MAC 后接收。<br>*(本质：物理层盲目电气复制)* | 识别出全 `F` 广播 MAC 地址，执行泛洪 (Flood) 转发到其他端口。<br>*(本质：数据链路层有意识转发)* |
| **多对主机并发通信** | 信号在线路上重叠造成**冲突 (Collision)**，通信中断并触发退避重传。 | 内部交换矩阵支持多端口**并行无阻塞传输**，各对通信互不影响。 |

#### (3) 核心特性横向对比（408 极高频必背）

| 对比维度 | 共享式以太网 (Hub) | 交换式以太网 (Switch) |
| :--- | :---: | :---: |
| **工作层次** | `物理层` (L1) | `数据链路层` (L2) |
| **通信模式** | <u>半双工 (Half-Duplex)</u> | <u>全双工 (Full-Duplex)</u> |
| **带宽分配方式** | 共享带宽（每台平均 $C/N$） | 独占带宽（每个端口独占 $C$） |
| **是否依赖 CSMA/CD** | **是**（必须采用） | **否**（全双工点对点链路无冲突） |
| **硬件转发依据** | 无（比特流盲发） | MAC 地址转发表（自学习建立） |
| **安全与隔离度** | 差（易被窃听抓包） | 较好（端口数据相互隔离） |

> [!tip] 核心考点：各网络设备的隔离能力
> - **集线器 (Hub) / 中继器 (Repeater)**：既**不隔离冲突域**，也**不隔离广播域**。
> - **以太网交换机 (Switch) / 网桥 (Bridge)**：**隔离冲突域**，但**不隔离广播域**。
> - **路由器 (Router)**：既**隔离冲突域**，又**隔离广播域**。

## 八、408 经典计算与概念辨析例题

### 题目 1：滑动窗口极限参数计算
主机甲和主机乙之间采用后退 N 帧协议 (GBN) 传输数据，帧序号占用 3 个比特。若发送窗口尺寸为 $W_T$，接收窗口尺寸为 $W_R$，求 $W_T$ 的最大可能值。
**解答：**
* 帧序号占 3 比特，故序号范围是 $0 \sim 2^3-1$ (即 $0 \sim 7$)。
* GBN 的规定是 $W_R = 1$，且 $W_T \le 2^n - 1$。
* 故 $W_T \le 2^3 - 1 = 7$。因此最大值为 **7**。
*(注：如果是 SR 协议，发送和接收窗口一般相等，且最大为 $2^{3-1} = 4$)*。

### 题目 2：最小帧长计算
在一个以太网中，传输介质长度为 $1000\text{ m}$，信号传播速率为 $2 \times 10^8\text{ m/s}$，网络数据传输速率为 $1\text{ Gbps}$，求该网络能支持的最小数据帧长度。
**解答步骤：**
1. **求单向传播时延 $\tau$：**
   $$\tau = \frac{1000\text{ m}}{2 \times 10^8\text{ m/s}} = 5 \times 10^{-6}\text{ s} = 5\text{ \mu s}$$
2. **求争用期 $2\tau$：**
   $$2\tau = 10\text{ \mu s}$$
3. **求最小帧长：**
   $$L_{min} = 2\tau \times \text{带宽} = (10 \times 10^{-6}\text{ s}) \times (10^9\text{ bps}) = 10^4\text{ bit}$$
4. **转换为字节：** $10000 / 8 = \mathbf{1250\text{ 字节}}$。

## 九、首轮复习高频考法与陷阱防范

1. **陷阱：物理层设备 vs 链路层设备 vs 网络层设备**
   * **集线器/中继器（物理层）：** 既不隔离冲突域，也不隔离广播域。
   * **网桥/交换机（链路层）：** 隔离**冲突域**，但**不隔离广播域**。（VLAN 是逻辑隔离广播域，而非交换机的硬件本能）。
   * **路由器（网络层）：** 隔离**冲突域**，也隔离**广播域**。
2. **概念辨析：CSMA/CD 的“检测碰撞”**
   * CSMA/CD 只能用于有线网。因为检测碰撞需要发送方监听信道上信号电压的异常变化，无线信道衰减过大无法实现。
3. **陷阱：GBN 和 SR 的确认机制区别**
   * GBN 是**累积确认**（捎带确认）。收到 ACK n，说明 n 及 n 以前的都收到了。
   * SR 是**单独确认**。收到 ACK n，仅代表 n 号帧收到了。
4. **细节：以太网帧的填充**
   * 计算最小帧长时，是以**MAC 帧的总长度（目的 MAC + 源 MAC + 类型 + 数据 + FCS）**为准的（即数据链路层 PDU）。前导码不算在内。最小 64B 是以太网的硬规定，遇到具体链路参数计算出来的可能大于 64B。

## 十、第三章核心结论清单总结

* **三大基本问题：** 封装成帧、透明传输、差错检测。
* **零比特填充法：** 见 5 个 1 就塞 0，保证透明传输。
* **差错检测不等于可靠传输：** 数据链路层主要只管检错丢弃，纠错和重传是可靠传输协议干的活。
* **滑动窗口三大协议：** 停止-等待（1,1），GBN（>1, 1，累积确认），SR（>1, >1，单独确认）。
* **CSMA/CD 铁律：** 最小帧长 $= 2\tau \times$ 带宽。争用期 $= 2\tau$。
* **交换机自学习：** 查源 MAC 建表，查目的 MAC 转发（找不到就泛洪）。
* **网络设备隔离原则：** 交换机切冲突域不切广播域，路由器切广播域。
