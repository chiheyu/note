## 一、应用层解决什么问题与网络应用模型

应用层是计算机网络体系结构的最顶层，直接为用户的**应用进程**提供服务。它规定了应用进程在通信时所遵循的协议。

#### 1. 客户/服务器模型 (C/S 模型)
* **工作机制：** 服务器长期处于运行状态，被动等待客户端发起请求。客户端主动向服务器发出请求，并接收服务。
* **特点：** 客户机之间**不直接通信**。服务器是整个网络的瓶颈，一旦服务器崩溃，服务全面停止。随着用户量增加，服务器性能会急剧下降。
* **常见应用：** Web (HTTP)、文件传输 (FTP)、电子邮件 (SMTP/POP3)。

#### 2. P2P 模型 (Peer-to-Peer 对等模型)
* **工作机制：** 网络中的各个结点既是客户端也是服务器。任何两个结点之间都可以直接通信。
* **特点：** 极大地减轻了中心服务器的压力，**可扩展性好**。用户越多，提供的资源反而越多，下载速度越快。
* **常见应用：** P2P 文件共享（如 BitTorrent）、迅雷下载。

## 二、域名系统 (DNS)

DNS 是互联网使用的命名系统，用于把人类可读的**域名**解析为机器可读的 **IP 地址**。
**408高频考点：** DNS 主要基于 **UDP**，端口号为 **53**。（在进行区域传送或报文过长时会使用 TCP）。

### 1. 域名层次结构
采用树状结构的命名空间。从右向左，级别由高到低：
* **根域：** 无名，通常省略。
* **顶级域 (TLD)：** 如 `.com`, `.cn`, `.edu`, `.org`。
* **二级域：** 如 `baidu.com`, `tsinghua.edu.cn`。
* **三级域/主机名：** 如 `www`, `mail`。

### 2. 四类域名服务器
1. **根域名服务器：** 知道所有顶级域名服务器的 IP 地址。当本地域名服务器解析不了时，**首先**求助根服务器。
2. **顶级域名服务器：** 负责管理在该顶级域名服务器注册的所有二级域名。
3. **权威域名服务器（授权域名服务器）：** 负责一个区的域名服务器，总是能将其管辖的主机名转换为 IP 地址。
4. **本地域名服务器：** **严格来说不属于 DNS 层次结构。** 当主机发出 DNS 查询时，请求首先发给本地域名服务器（作为代理角色）。

### 3. DNS 查询方式（核心重难点）
* **递归查询（“甩锅”）：** 主机向本地域名服务器的查询通常是递归的。如果本地域名服务器不知道，它会**代替**主机去向上级查询，最后把结果直接返回给主机。
* **迭代查询（“指路”）：** 本地域名服务器向外查询通常是迭代的。本地域名服务器问根服务器，根服务器不直接去查，而是**告诉**本地域名服务器“你应该去问哪个顶级域名服务器”，让本地服务器自己去问下一步。

### 4. 高速缓存
为了提高解析效率，主机和本地域名服务器中都广泛使用了**高速缓存 (Cache)**，存放最近查询过的域名及其 IP 映射，并设有生存时间 (TTL)。

## 三、文件传输协议 (FTP)

FTP 是互联网上使用最广泛的文件传输协议。
**408高频考点：** FTP 是基于 **TCP** 的，并且是应用层中少有的**使用两条 TCP 连接**的协议。这种将控制信息和数据信息分开传送的方式称为**带外控制 (Out-of-band)**。

### 1. 两条 TCP 连接
* **控制连接（端口 21）：** 客户端主动向服务器的 21 端口建立连接。用于传输控制命令（如登录、目录切换、传输请求）。在整个 FTP 会话期间**一直保持打开**。
* **数据连接（端口 20 或随机）：** 用于实际传输文件。每次传输文件时建立，传输完毕后立即关闭。

### 2. FTP 的两种工作模式
* **主动模式 (PORT)：** 客户端开放一个随机端口，通过控制连接告诉服务器；**服务器主动**从自己的 **20 端口**向客户端的那个随机端口发起 TCP 连接。
* **被动模式 (PASV)：** 客户端通过控制连接告诉服务器“我需要文件”；服务器开放一个随机端口并告诉客户端；**客户端主动**向服务器的这个随机端口发起 TCP 数据连接。（常用于客户端在防火墙/NAT之后的场景）。

## 四、电子邮件系统

### 1. 系统的三个核心组件
* **用户代理 (UA)：** 如 Outlook, Foxmail，供用户书写、阅读和管理邮件。
* **邮件服务器：** 负责发送和接收邮件，同时还要向发信人报告邮件传送的情况。24小时不间断运行。
* **邮件协议：** 包括发送协议（SMTP）和读取协议（POP3 / IMAP）。

### 2. 核心协议对比与工作路径
**标准邮件发送路径：**
发件人 UA $\xrightarrow{SMTP}$ 发件方邮件服务器 $\xrightarrow{SMTP}$ 收件方邮件服务器 $\xrightarrow{POP3/IMAP}$ 收件人 UA

* **SMTP (简单邮件传输协议)：**
  * 基于 **TCP**，端口 **25**。
  * 采用“推 (Push)”的方式，只能传送 ASCII 码文本。
* **POP3 (邮局协议第3版)：**
  * 基于 **TCP**，端口 **110**。
  * 采用“拉 (Pull)”的方式。工作方式有“下载并保留”和“下载并删除”。
* **IMAP (网际报文存取协议)：**
  * 基于 **TCP**，端口 **143**。
  * 是一个联机协议。允许用户在自己的 PC 上操纵邮件服务器中的邮箱（如创建文件夹、移动邮件），相当于远程控制，非常适合多设备同步。
* **MIME (多用途网际邮件扩充)：**
  * SMTP 的补丁。它将非 ASCII 码的数据（如中文、图片、视频、附件）转换为 ASCII 码，然后再交由 SMTP 传送。

**408陷阱：基于万维网的电子邮件 (Webmail)**
当我们使用浏览器（如网页版 QQ 邮箱）收发邮件时，用户代理与邮件服务器之间的交互使用的是 **HTTP** 协议；只有在邮件服务器之间转发时，才使用 **SMTP** 协议。

## 五、万维网 (WWW) 与 HTTP 协议

### 1. 万维网三大组件
* **URL (统一资源定位符)：** `协议://主机(域名或IP):端口/路径`。用来唯一标识互联网上的资源。
* **HTML (超文本标记语言)：** 解决页面排版和结构问题。
* **HTTP (超文本传输协议)：** 解决网页文件如何在互联网上传输的问题。

### 2. HTTP 协议特点
* **基于 TCP：** 端口号 **80**（HTTPS 为 443）。HTTP 本身是无连接的（不维持连接状态，交由底层的 TCP 维持连接）。
* **无状态 (Stateless)：** HTTP 服务器不记得之前的请求。为了实现购物车、登录等功能，引入了 **Cookie** 和 **Session** 技术在客户端和服务器之间保持状态。

### 3. HTTP 的连接方式（必考计算题核心）
* **HTTP/1.0 (非持久连接)：**
  * 每次请求一个网页元素（如一张图片）都要重新建立一次 TCP 连接。
  * **时间开销：** 请求一个文档需要 2 个 RTT。
    $$总时间 = \text{TCP建立握手(1个RTT)} + \text{HTTP请求与响应(1个RTT)} + \text{文档传输时间}$$
* **HTTP/1.1 (持久连接 Persistent Connection)：**
  * 默认使用 `Connection: keep-alive`。服务器发完响应后仍然保持 TCP 连接。
  * **非流水线方式：** 客户收到前一个响应后才能发下一个请求。（浪费了等待时间）。
  * **流水线方式 (Pipelining)：** 客户可以连续发送多个请求，不必等响应。极大减少了网络延迟。

### 4. HTTP 报文结构
分为**请求报文**和**响应报文**。报文由面向文本的 ASCII 码组成。
* **请求报文结构：** 请求行（方法、URL、版本） + 首部行 + 空行 + 实体主体。
  * 常见方法：`GET`（请求读取，数据在 URL 中）、`POST`（请求处理，数据在实体主体中）。
* **响应报文结构：** 状态行（版本、状态码、短语） + 首部行 + 空行 + 实体主体。

### 5. HTTP 常见状态码
* **1xx (信息)：** 请求已接收，继续处理。
* **2xx (成功)：** `200 OK` 最常见。
* **3xx (重定向)：** `301` 永久重定向，`302` 临时重定向，`304` 资源未修改（可直接使用本地缓存）。
* **4xx (客户端错误)：** `400` 报文语法错误，`403` 服务器拒绝访问（无权限），`404` 资源不存在。
* **5xx (服务器错误)：** `500` 服务器内部错误，`502` 网关错误。

## 六、408 经典综合场景例题（“输入 URL 会发生什么？”）

### 题目
假设主机 A 刚刚接入局域网，用户在浏览器中输入 `http://www.tsinghua.edu.cn` 并敲击回车，直到页面显示，请简述整个过程中涉及的关键协议及其作用。（假设本地无任何缓存）

### 解答梳理（必须烂熟于心）
1. **配置 IP (DHCP)：** 主机 A 发送 DHCP Discover 报文，通过 UDP 广播，向 DHCP 服务器获取 IP 地址、子网掩码、默认网关和 DNS 服务器的 IP。
2. **解析 MAC 地址 (ARP)：** 主机 A 知道默认网关（路由器）的 IP 后，发送 ARP 广播报文，获取默认网关的 MAC 地址，以便将后续数据报发往路由器。
3. **域名解析 (DNS)：** 主机 A 构造 DNS 查询报文，通过 UDP 发往 DNS 服务器，逐级（本地、根、顶级、权威）查询 `www.tsinghua.edu.cn` 的 IP 地址。
4. **建立 TCP 连接 (TCP)：** 得到目标 Web 服务器的 IP 后，浏览器随机开启一个端口，向目标 IP 的 80 端口发起 TCP 三次握手建立连接。
5. **发送 HTTP 请求 (HTTP)：** TCP 连接建立后，浏览器向服务器发送 HTTP GET 请求报文。此报文在传输层封装为 TCP 报文段，在网络层封装为 IP 数据报，最终发向目标。
6. **接收 HTTP 响应 (HTTP)：** Web 服务器处理请求并返回包含 HTML 页面的 HTTP 响应报文。
7. **渲染页面：** 浏览器解析 HTML、CSS 等资源，渲染并展示页面。如有额外图片资源，可通过持久连接继续请求。最后四次挥手释放 TCP 连接。

## 七、高频易错点与核心结论清单总结

1. **陷阱：协议的底层依托归属**
   * 基于 **TCP**：HTTP, FTP, SMTP, POP3, IMAP, BGP。
   * 基于 **UDP**：DNS, DHCP, TFTP, RIP, SNMP。
   * *(口诀助记：网页文件发邮件找TCP；解析配置轻量管理找UDP)*
2. **陷阱：FTP 的数据连接由谁发起？**
   * **不一定！** 主动模式(PORT)下是服务器主动发起；被动模式(PASV)下是客户端主动发起。但**控制连接永远是客户端主动发起**。
3. **陷阱：发送邮件和接收邮件的区别**
   * 发邮件（从客户端到服务器，或服务器之间）**必须用 SMTP**。
   * 收邮件（从服务器到客户端）用 POP3 或 IMAP。SMTP 绝不用于把邮件从服务器推给收件人本地电脑！
4. **陷阱：HTTP 无状态 vs 持久连接**
   * **无状态**是指 HTTP 协议本身不记录过往的请求历史（它不认识你是谁）。
   * **持久连接**是指底层的 TCP 连接不断开。两者不冲突。Cookie 才是解决无状态的手段。
5. **DNS 查询的默认行为**
   * 主机问本地服务器：**递归**（主机很懒，只要结果）。
   * 本地服务器问外网服务器：**迭代**（外网服务器很忙，只负责指路不负责代劳）。
