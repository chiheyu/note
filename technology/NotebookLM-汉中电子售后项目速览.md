# 汉中电子售后项目 NotebookLM 速览

## 1. 项目一句话概述

汉中电子售后项目是一个面向电子产品售后服务场景的全栈系统，覆盖后端业务服务、Web 端和小程序端，核心目标是打通“用户售后申请、配件商城、商家处理”这条完整业务链路。

## 2. 项目背景与业务价值

这个项目面向的是电子产品售后业务场景，重点解决以下问题：

- 普通用户在线提交售后申请、查看处理进度、购买配件
- 商家在线管理配件、处理订单、跟进售后流程
- 从业务价值上看，这个项目把传统线下、分散的售后处理流程，整合成了一套统一的线上业务系统，让用户和商家都能在同一套平台上协同工作。

## 3. 项目整体组成

项目主要由 3 个核心部分组成。

### 3.1 后端

目录：`Hanzhong-Elec-Aftersales-Back-end/`

后端基于若依 `RuoYi-Vue 3.9.0` 改造，使用多模块 Maven 结构，承担整个系统的业务核心。

主要职责：

- 提供 Web 端与小程序端通用接口
- 实现用户、商家、配件、订单、售后等核心业务逻辑
- 提供认证、数据访问与业务支撑能力

核心模块：

- `ruoyi-admin`：启动入口、控制器、运行配置
- `ruoyi-framework`：安全、配置、拦截器、基础框架能力
- `ruoyi-system`：核心业务领域、Mapper、Service
- `ruoyi-common`：通用工具与基础能力
- `ruoyi-quartz`：定时任务
- `ruoyi-generator`：代码生成模块

### 3.2 Web 前端

目录：`Hanzhong-Elec-AfterSale-Web/`

这是项目的网页前端，主要面向浏览器使用场景。

主要职责：

- 普通用户商城浏览与下单
- 购物车与地址管理
- 售后申请与订单查看
- 商家工作台与配件管理

### 3.3 小程序端

目录：`Hanzhong-Elec-AfterSale-Mini/`

这是项目的 Uni-app 小程序端，面向移动端场景，复用同一套后端接口。

主要职责：

- 提供普通用户移动端入口
- 提供商家移动端入口
- 支持在移动端完成配件浏览、下单、售后申请、订单跟踪等流程

## 5. 系统角色

系统中主要有两类核心角色。

### 5.1 普通用户

普通用户主要使用商城和售后功能，包括：

- 浏览配件商品
- 加入购物车
- 提交订单
- 提交售后申请
- 查看售后和订单进度

### 5.2 商家用户

商家用户主要负责经营与履约，包括：

- 管理配件商品
- 处理用户订单
- 跟进售后单
- 维护商家信息

## 6. 核心业务模块

从业务角度看，这个项目可以拆成以下几个核心模块。

### 6.1 售后申请模块

这是项目最核心的业务模块之一。

主要流程：

1. 用户提交售后申请
2. 系统生成售后单
3. 商家处理售后流程
4. 用户查看处理进度和结果

### 6.2 配件商城模块

这是项目的重要交易模块。

主要流程：

1. 用户浏览配件商品
2. 用户加入购物车
3. 用户结算并生成订单
4. 商家查看并处理订单
5. 用户查看订单状态

### 6.3 商家运营模块

商家端主要围绕经营和履约展开。

主要内容：

- 商品管理
- 订单处理
- 售后协同
- 商家资料维护

## 7. 项目架构特点

这个项目的特点不是单纯的“前后端分离”，而是“多端共用一套后端业务能力”。

主要特点：

- 后端统一承载 Web 端和小程序端接口
- Web 与小程序共用核心业务逻辑
- 系统同时覆盖普通用户端和商家端
- 业务围绕售后与配件交易两个主线展开
- 在若依框架基础上做了业务化改造，而不是停留在通用模板层面

## 8. 项目的工程化亮点

### 8.1 多角色、多端统一

项目不是单一商城页面，而是把用户端、商家端放进了一套统一系统中，形成完整业务闭环。

### 8.2 基于成熟框架做业务改造

后端基于若依框架改造，继承了认证、安全和基础工程能力，从而把更多精力放在售后、商城、订单和商家业务实现上。

### 8.3 前后端职责清晰

- 后端负责认证、业务逻辑和数据访问
- Web 前端负责浏览器交互体验
- 小程序端负责移动端业务触达

这种拆分方式使系统扩展性和维护性更好。

## 9. 近期已解决的典型问题

这些内容适合作为演讲里的“项目落地问题与优化”部分。

- 修复了 H2 与 MySQL 语法差异导致的 SQL 兼容问题
- 修复了普通用户购物车在同一浏览器下多账号串数据的问题
- 修复了普通用户商城商品显示异常、订单结算异常等问题
- 梳理了项目目录、README 和打包链路中的路径引用问题

这些问题说明项目不只是一个静态展示系统，而是真正经历了联调、测试、兼容和交付打磨的业务项目。

## 10. 项目开发方式

### 10.1 后端开发

```powershell
cd E:\Backstage-Management-System\Hanzhong-Elec-Aftersales-Back-end
mvn -pl ruoyi-admin -am spring-boot:run
```

### 10.2 Web 前端开发

```powershell
cd E:\Backstage-Management-System\Hanzhong-Elec-AfterSale-Web
npm install
npm run dev
```

- 使用 HBuilderX 打开 `Hanzhong-Elec-AfterSale-Mini`
- 在 `config.js` 中配置后端接口地址
