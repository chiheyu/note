## 1. 产品概述

### 1.1 产品名称

智慧实验室设备预约与耗材管理系统

### 1.2 产品定位

本系统是一个面向单实验室场景的实验室资源管理平台，主要用于解决实验室设备预约、耗材领用、库存维护、资源审批和数据统计等问题。

系统面向学生、教师、实验室管理员和系统管理员四类用户，支持设备预约、耗材申请、教师等级审批、实验室管理员业务确认、库存预警、公告发布和基础数据统计。

### 1.3 产品核心特色

本系统不仅提供基础的设备和耗材管理能力，还引入基于资源等级和教师等级的审批机制：

| 核心规则    | 说明                         |
| ------- | -------------------------- |
| 设备等级规则  | 普通设备可由学生直接申请，贵重设备需要教师审批    |
| 耗材额度规则  | 普通额度内耗材可正常申请，特殊耗材申请需要教师审批  |
| 教师等级规则  | 教师等级越高，可审批的设备等级和耗材的额度与等级越高 |
| 管理员确认规则 | 实验室管理员负责最终资源排期、库存扣减和业务确认   |

## 2. 产品背景

当前实验室在设备预约和耗材管理上通常依赖线下登记、微信群沟通或 Excel 表格维护，容易出现以下问题：

1. 设备预约冲突，无法准确判断设备空闲时间。
2. 耗材库存不透明，库存数量容易不准确。
3. 贵重设备和大量耗材缺少审批约束。
4. 审批流程不清晰，申请记录难以追踪。
5. 管理员需要手动统计设备使用情况和耗材消耗情况。
6. 实验室公告和规则变动缺少统一发布入口。

因此，需要建设一个轻量化、可扩展、适合单实验室使用的管理系统，实现实验室资源申请、审批、使用、出库和统计的数字化管理。

## 3. 产品目标

### 3.1 业务目标

1. 实现实验室设备预约线上化。
2. 实现耗材库存和领用流程数字化。
3. 减少设备预约冲突。
4. 降低实验室管理员人工统计成本。
5. 通过角色等级机制限制贵重设备和特殊耗材的申请。
6. 提供设备使用率和耗材消耗数据支撑。
7. 为实验室公告、维护通知、预约规则提供统一发布入口。

### 3.2 用户目标

| 用户角色   | 用户目标                              |
| ------ | --------------------------------- |
| 学生     | 快速查看可预约设备和可申请耗材，提交预约或领用申请，并查看审批状态 |
| 教师     | 根据自身等级可审批学生申请贵重设备预约和特殊耗材申请        |
| 实验室管理员 | 维护设备、耗材、库存、公告，并处理实验室业务审批和确认       |
| 系统管理员  | 管理用户账号、角色权限、教师等级、设置角色与等级规则和系统基础字典 |

## 5. 用户角色与职责

### 5.1 学生

学生是实验室资源申请者，对应等级2。

学生可以：

1. 登录系统。
2. 查看设备列表。
3. 查看设备详情和可预约时间。
4. 提交设备预约申请。
5. 查看个人设备预约记录。
6. 取消未开始且未完成审批的预约申请。
7. 查看耗材列表。
8. 查看耗材库存和可申请额度。
9. 提交耗材领用申请。
10. 查看个人耗材领用记录。
11. 查看申请审批状态和驳回原因。
12. 查看实验室公告。

学生不可以：

1. 审批申请。
2. 修改设备信息。
3. 修改耗材库存。
4. 修改用户权限。
5. 修改教师等级。

---

### 5.2 教师

教师是高价值资源和特殊资源申请的审批者。

教师分为三个等级：

1. 讲师，对应等级3。
2. 副教授，对应等级4。
3. 教授，对应等级5。

教师可以：

1. 登录系统。
2. 查看自身教师等级。
3. 查看自身可审批的设备等级。
4. 查看自身可审批的耗材申请额度范围。
5. 查看学生提交的待审批申请。
6. 审批或驳回需要教师审批的贵重设备、核心设备预约申请。
7. 审批或驳回需要教师审批的特殊耗材领用申请。
8. 查看自己处理过的审批记录。
9. 查看实验室公告。

教师不可以：

1. 直接修改设备基础信息。
2. 直接修改耗材库存。
3. 直接扣减库存。
4. 修改用户角色。
5. 修改教师等级。
6. 发布实验室公告。

---

### 5.3 实验室管理员

实验室管理员是实验室业务管理者，负责实验室中的设备、耗材、预约、库存和公告，对应等级1。

实验室管理员可以：

1. 登录系统。
2. 维护实验室基础信息。
3. 新增、编辑、停用设备。
4. 设置设备状态。
5. 设置设备等级和预约规则。
6. 查看所有设备预约记录。
7. 审批普通设备预约。
8. 确认教师审批通过后的贵重设备和核心设备预约。
9. 新增、编辑、停用耗材。
10. 设置耗材危险等级。
11. 调整耗材库存。
12. 设置耗材库存预警值。
13. 审批普通耗材领用申请。
14. 确认教师审批通过后的特殊耗材领用申请。
15. 扣减耗材库存并生成出库记录。
16. 发布、编辑、下架实验室公告。
17. 查看实验室业务数据统计。
18. 查看设备使用记录和耗材出入库记录。

实验室管理员不可以：

1. 修改系统管理员账号。
2. 修改用户角色权限。
3. 修改教师等级。
4. 修改系统权限配置。
5. 进行设备预约和耗材申请。

---

### 5.4 系统管理员

系统管理员是平台级管理者，负责用户、角色、权限、教师等级、额度设置和系统基础配置，对应等级0。

系统管理员可以：

1. 登录系统。
2. 新增、编辑、禁用用户账号。
3. 为用户分配角色。
4. 为教师用户设置教师等级，并维护角色等级与申请规则。
5. 管理角色权限。
6. 维护系统基础字典。
7. 启用或禁用异常账号。
8. 设置不同等级角色的耗材可用额度百分比、可申请/可审批的最高设备等级和最高耗材危险等级。

系统管理员不可以：

1. 直接审批设备预约。
2. 直接审批耗材领用。
3. 直接修改设备库存。
4. 直接发布实验室公告。
5. 直接参与实验室业务出库确认。
6. 进行设备预约和耗材申请。

## 6. 核心业务规则

普通设备预约和普通耗材申请由实验室管理员审批；贵重 / 核心设备预约、特殊耗材申请先由符合等级要求的教师审批，再由实验室管理员最终确认。系统管理员只负责用户、角色、等级和申请规则配置，不参与具体业务审批。

### 6.1 设备等级规则

设备分为以下等级：

| 设备等级 | 说明             | 审批规则                   |
| ---- | -------------- | ---------------------- |
| 普通设备 | 常规实验设备，风险和价值较低 | 学生申请后由实验室管理员审批         |
| 贵重设备 | 价值较高或操作要求较高的设备 | 需要教师审批后，再由实验室管理员确认     |
| 核心设备 | 高价值、高风险或重点管理设备 | 需要较高等级教师审批后，再由实验室管理员确认 |

### 6.2 教师等级审批规则

| 教师等级     | 可审批设备范围 | 可审批耗材范围                     |
| -------- | ------- | --------------------------- |
| 讲师（等级3）  | 贵重设备 | 最高可审批该耗材当前库存5%的申请量，不可审批危险耗材 |
| 副教授（等级4） | 贵重设备 | 最高可审批该耗材当前库存7%的申请量，可以审批危险耗材 |
| 教授（等级5）  | 贵重设备、核心设备 | 最高可审批该耗材当前库存10%的申请量，可以审批危险耗材 |

审批上限由系统管理员在角色等级与申请规则模块中统一配置。

### 6.3 耗材额度规则

耗材申请分为普通申请和特殊申请，在学生提交申请时由系统自行判断。

| 申请类型   | 判断条件          | 审批规则                     |
| ------ | ------------- | ------------------------ |
| 普通耗材申请 | 非危险耗材 且 未超额   | 实验室管理员审批                 |
| 特殊耗材申请 | 申请数量超额或者为危险耗材 | 进入教师审批流程，审批通过后实验室管理员确认出库 |
额度上限 = 当前申请耗材的 current_stock × 对应等级的 max_material_percentage，计算结果向下取整。
若计算结果小于 1，则普通申请额度按 1 个单位处理；当 current_stock 为 0 时，不允许提交申请。
当 apply_quantity 小于等于额度上限时，判定为未超额；当 apply_quantity 大于额度上限时，判定为超额。

### 6.4 教师审批人筛选规则

设备预约需要教师审批时，系统根据设备等级、设备 required_teacher_level 和教师等级筛选可审批教师。

耗材申请需要教师审批时，系统根据耗材 dangerous_level、申请数量、申请人等级和教师等级筛选可审批教师。
前端教师选择框只展示符合审批条件的教师，后端仍需对 teacher_approver_id 进行二次权限校验。

所有进入教师审批阶段的申请，后端提交时必须再次校验 teacher_approver_id 是否具备对应审批权限。

### 6.5 设备预约冲突规则

同一设备在同一时间段内只能存在一条已通过或待确认的预约记录。

系统需要校验：

1. 预约开始时间必须早于结束时间。
2. 预约时间不能与已有预约冲突。
3. 维护中或停用设备不可预约。
4. 已取消或已驳回的预约不参与冲突判断。
5. 用户只能取消未开始的预约。

### 6.6 设备状态规则

设备基础状态包括：

1. 可预约。
2. 维护中。
3. 停用。

“使用中”不作为手动维护状态，而是由系统根据当前时间和已通过预约记录动态判断。

### 6.7 库存扣减规则

耗材库存只在申请最终通过后扣减。

普通耗材申请流程：

1. 学生提交申请。
2. 实验室管理员审批。
3. 审批通过后系统扣减库存。
4. 系统生成出库记录。

特殊耗材申请流程：

1. 学生提交申请。
2. 系统判断为特殊申请。
3. 申请进入教师审批阶段。
4. 如果教师或实验室管理员驳回，申请状态变为 REJECTED，并记录驳回原因。
5. 教师审批通过后，申请进入实验室管理员确认阶段。
6. 实验室管理员确认库存充足后，系统扣减库存。
7. 系统生成出库记录。

## 7. 核心业务流程

### 7.1 设备预约流程

1. 用户登录系统。
2. 用户进入设备列表。
3. 用户选择设备并查看设备详情。
4. 系统判断设备状态是否可预约。
5. 用户填写预约时间和使用目的。
6. 系统校验预约时间是否合法。
7. 系统校验同一设备是否存在时间冲突。
8. 系统判断设备等级。
9. 如果是普通设备，申请进入实验室管理员审批。
10. 如果是贵重设备或核心设备，申请进入教师审批阶段。
11. 系统根据设备等级和 required_teacher_level 筛选可审批教师，学生从候选教师列表中选择审批人，并补充申请说明。
12. 如果教师或实验室管理员驳回，申请状态变为 REJECTED，并记录驳回原因。
13. 教师审批通过后，申请进入实验室管理员确认。
14. 实验室管理员确认后，预约正式生效。
15. 用户按照预约时间使用设备。
16. 使用结束后生成设备使用记录。

---

### 7.2 耗材领用流程

1. 用户登录系统。
2. 用户进入耗材列表。
3. 用户选择需要领用的耗材。
4. 系统展示当前库存、单位、预警值、危险程度和申请限制。
5. 用户填写申请数量和申请用途。
6. 系统校验库存是否充足。
7. 系统判断耗材申请类型是普通耗材申请还是特殊耗材申请。
8. 如果普通耗材申请，申请进入实验室管理员审批。
9. 如果特殊耗材申请，申请进入教师审批。
10. 学生从候选教师列表中选择审批人，并补充申请说明。
11. 教师审批通过后，申请进入实验室管理员确认。
12. 如果教师驳回，申请状态变为 REJECTED，并记录驳回原因。
13. 如果实验室管理员驳回，申请状态变为 REJECTED，并记录驳回原因。
14. 实验室管理员最终确认出库前，系统再次校验库存是否充足。
15. 如果库存不足，则禁止确认出库，并提示库存不足。
16. 如果库存充足，实验室管理员确认后系统扣减库存。
17. 系统生成耗材出库记录。
18. 如果库存低于预警值，系统标记库存预警。

---

### 7.3 公告发布流程

1. 实验室管理员登录系统。
2. 进入公告管理页面。
3. 新增公告。
4. 填写公告标题、公告内容和发布状态。
5. 发布公告。
6. 学生和教师在首页查看公告。

| max_dangerous_level     | 该等级可申请或可审批的最高耗材危险等级 |
| description             | 规则说明         |
| update_time             | 更新时间         |
学生等级默认 max_material_percentage 为 0.02，即单次申请数量不得超过该耗材当前库存的 2%；具体比例可由系统管理员在角色等级与申请规则模块中配置。教师审批额度参考教师等级审批规则。实验室管理员和系统管理员不参与耗材申请额度计算。

## 9. 审批状态设计

### 9.1 统一审批状态

| 状态               | 说明              |
| ---------------- | --------------- |
| PENDING_ADMIN    | 待实验室管理员审批       |
| PENDING_TEACHER  | 待教师审批           |
| TEACHER_APPROVED | 教师已通过，待实验室管理员确认 |
| APPROVED | 实验室管理员最终确认通过，申请正式生效 |
| REJECTED | 申请已被教师或实验室管理员驳回 |
| CANCELLED        | 用户已取消           |
| FINISHED         | 已完成             |

### 9.2 设备预约状态流转

普通设备：

1. PENDING_ADMIN
2. APPROVED / REJECTED
3. FINISHED

贵重设备或核心设备：

1. PENDING_TEACHER
2. TEACHER_APPROVED / REJECTED
3. APPROVED / REJECTED
4. FINISHED

### 9.3 耗材申请状态流转

普通耗材申请：

1. PENDING_ADMIN
2. APPROVED / REJECTED

特殊耗材申请：

1. PENDING_TEACHER
2. TEACHER_APPROVED / REJECTED
3. APPROVED / REJECTED

说明：TEACHER_APPROVED 仅表示教师预审批通过，不代表申请最终生效；只有状态变为 APPROVED 时，才表示实验室管理员已最终确认。

## 10. 非功能需求

### 10.1 性能要求

1. 普通列表查询响应时间控制在 1 秒以内。
2. 分页查询默认每页 10 或 20 条。
3. 数据看板统计接口响应时间控制在 3 秒以内。
4. 系统支持基础并发访问，满足课程项目或小型实验室使用场景。

### 10.2 安全要求

1. 密码必须加密存储。
2. 所有业务接口必须进行登录鉴权。
3. 用户只能访问自己角色允许的页面和接口。
4. 学生不能访问后台管理接口。
5. 教师不能修改库存和设备信息。
6. 实验室管理员不能修改教师等级。
7. 系统管理员不参与实验室业务审批。
8. 操作日志仅允许系统管理员查看，实验室管理员只能查看业务记录、设备使用记录和库存流水。

### 10.3 可维护性要求

1. 前后端接口结构清晰。
2. 后端按照 Controller、Service、Mapper 分层。
3. 数据库表设计规范。
4. 业务状态枚举统一管理。
5. 角色权限判断逻辑集中处理。
6. 支持后续扩展通知、导出、扫码签到、多实验室等功能。

## 11. MVP 验收标准

### 11.1 登录与权限

1. 用户可以使用账号密码登录系统。
2. 不同角色登录后进入不同首页。
3. 不同角色只能访问自己有权限的菜单。
4. 未登录用户无法访问业务页面。

### 11.2 系统管理员功能

1. 系统管理员可以新增、编辑、禁用用户。
2. 系统管理员可以为用户分配角色。
3. 系统管理员可以为教师用户设置教师等级。
4. 系统管理员可以设置与等级对应的最高耗材申请 / 审批额度，以及可申请 / 可审批的最高设备等级。

### 11.3 设备管理与预约

1. 实验室管理员可以新增、编辑、停用设备。
2. 实验室管理员可以设置设备等级。
3. 学生可以查看设备列表和设备详情。
4. 学生可以提交设备预约申请。
5. 系统可以校验预约时间冲突。
6. 普通设备预约由实验室管理员审批。
7. 贵重设备和核心设备预约需要教师审批后，再由实验室管理员确认。
8. 用户可以查看个人预约状态。
9. 系统可以避免同一设备同一时间段重复预约。

### 11.4 耗材管理与领用

1. 实验室管理员可以新增、编辑、停用耗材。
2. 实验室管理员可以调整耗材库存。
3. 实验室管理员可以设置耗材危险等级。
4. 实验室管理员可以设置库存预警值。
5. 学生可以查看耗材列表和库存。
6. 学生可以提交耗材领用申请。
7. 普通耗材申请由实验室管理员审批。
8. 特殊耗材申请需要教师审批后，再由实验室管理员确认。
9. 普通耗材经实验室管理员审批通过后扣减库存；特殊耗材经教师审批并由实验室管理员确认后扣减库存。
10. 特殊耗材在实验室管理员最终确认出库前，系统需要再次校验库存是否充足。
11. 系统可以生成耗材出库记录。
12. 系统可以显示低库存预警。

### 11.5 公告与数据统计

1. 实验室管理员可以发布公告。
2. 学生和教师可以查看公告。
3. 实验室管理员可以查看基础数据看板。
4. 数据看板可以展示预约数量、待审批数量、库存预警数量和耗材消耗情况。
