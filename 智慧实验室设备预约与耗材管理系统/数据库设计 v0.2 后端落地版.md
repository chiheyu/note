# 1. 设计目标

本数据库设计面向“单实验室版本”的智慧实验室设备预约与耗材管理系统。

当前版本默认系统只管理一个实验室，不做多实验室数据隔离。后续如需扩展多实验室，可在用户、设备、耗材、预约、申请等核心业务表中增加 `lab_id` 字段。

v0.2 的核心目标是让数据库设计可以直接支撑后端开发，包括：

1. 支持学生、教师、实验室管理员、系统管理员四类用户。
    
2. 支持用户角色、用户等级、等级规则配置。
    
3. 支持普通设备、贵重设备、核心设备的预约与审批。
    
4. 支持普通耗材、特殊耗材的申请与审批。
    
5. 支持耗材库存扣减、库存流水、库存预警。
    
6. 支持公告发布、编辑、下架。
    
7. 支持系统级操作日志，仅系统管理员可查看。
    
8. 支持后端事务控制、并发控制和状态机约束。
    
9. 支持历史审批记录的规则快照保存。
    
10. 支持后续扩展通知、导出、扫码签到、多实验室等能力。

# 5. 审批状态机设计

后端禁止通过通用 `updateStatus` 接口直接修改审批状态。

必须通过明确的业务动作驱动状态流转，例如：

- 提交预约
    
- 教师通过
    
- 教师驳回
    
- 管理员通过
    
- 管理员驳回
    
- 用户取消
    
- 标记完成
    

---

## 5.1 普通设备预约状态流转

普通设备不需要教师审批，直接进入实验室管理员审批。

```text
PENDING_ADMIN -> APPROVED
PENDING_ADMIN -> REJECTED
PENDING_ADMIN -> CANCELLED
APPROVED -> FINISHED
```

不允许出现：

```text
PENDING_ADMIN -> TEACHER_APPROVED
PENDING_ADMIN -> PENDING_TEACHER
REJECTED -> APPROVED
FINISHED -> CANCELLED
```

---

## 5.2 贵重 / 核心设备预约状态流转

贵重设备和核心设备需要教师审批。

```text
PENDING_TEACHER -> TEACHER_APPROVED
PENDING_TEACHER -> REJECTED
PENDING_TEACHER -> CANCELLED
TEACHER_APPROVED -> APPROVED
TEACHER_APPROVED -> REJECTED
APPROVED -> FINISHED
```

不允许出现：

```text
PENDING_TEACHER -> APPROVED
REJECTED -> TEACHER_APPROVED
REJECTED -> APPROVED
CANCELLED -> APPROVED
FINISHED -> CANCELLED
```

---

## 5.3 普通耗材申请状态流转

普通耗材申请不需要教师审批。

```text
PENDING_ADMIN -> APPROVED
PENDING_ADMIN -> REJECTED
PENDING_ADMIN -> CANCELLED
APPROVED -> FINISHED
```

说明：

普通耗材申请在管理员确认通过时扣减库存。

---

## 5.4 特殊耗材申请状态流转

特殊耗材申请需要教师审批。

```text
PENDING_TEACHER -> TEACHER_APPROVED
PENDING_TEACHER -> REJECTED
PENDING_TEACHER -> CANCELLED
TEACHER_APPROVED -> APPROVED
TEACHER_APPROVED -> REJECTED
APPROVED -> FINISHED
```

说明：

特殊耗材申请在教师审批通过后，仍需要实验室管理员最终确认。最终确认通过时扣减库存。

# 6.1 角色等级与申请规则表：sys_level_rule

## 表说明

存储不同等级对应的设备申请范围、设备审批资格、耗材申请比例和危险耗材权限。

## 字段设计

|字段名|类型|约束|说明|
|---|---|---|---|
|id|BIGINT|PK, AUTO_INCREMENT|规则 ID|
|level|TINYINT|NOT NULL, UNIQUE|等级|
|level_name|VARCHAR(50)|NOT NULL|等级名称|
|role|TINYINT|NOT NULL|对应角色|
|max_device_level|TINYINT|NULL|该等级可申请或可审批的最高设备等级|
|max_material_percentage|DECIMAL(5,4)|NULL|最大耗材比例，例如 0.0200 表示 2%|
|max_dangerous_level|TINYINT|NULL|最高耗材危险等级|
|description|VARCHAR(255)|NULL|规则说明|
|deleted|TINYINT|NOT NULL DEFAULT 0|逻辑删除：0未删除，1已删除|
|create_by|BIGINT|NULL|创建人 ID|
|update_by|BIGINT|NULL|更新人 ID|
|create_time|DATETIME|NOT NULL|创建时间|
|update_time|DATETIME|NOT NULL|更新时间|

## 默认规则建议

|level|level_name|role|max_device_level|max_material_percentage|max_dangerous_level|
|---|---|---|---|---|---|
|0|系统管理员|0|NULL|NULL|NULL|
|1|实验室管理员|1|NULL|NULL|NULL|
|2|学生|2|0|0.0200|0|
|3|讲师|3|1|0.0500|0|
|4|副教授|3|1|0.0700|1|
|5|教授|3|2|0.1000|1|

## 业务规则

1. 学生等级规则用于判断是否可直接申请。
    
2. 教师等级规则用于判断是否具备审批资格。
    
3. 系统管理员和实验室管理员不参与预约和耗材额度计算。
    
4. 耗材百分比额度公式：
    

```text
quota = floor(material.current_stock × max_material_percentage)
```

5. 如果 `quota < 1`，普通申请额度按 1 个单位处理。
    
6. 如果库存为 0，不允许申请。
    
7. 规则变更后，不影响历史申请记录，因为历史申请会保存规则快照。
    

## 建议索引

|索引名|字段|
|---|---|
|uk_level|level|
|idx_role|role|
|idx_deleted|deleted|

# 6.5 设备预约表：device_reservation

## 表说明

存储设备预约申请、教师审批、实验室管理员确认和最终状态。

## 字段设计

|字段名|类型|约束|说明|
|---|---|---|---|
|id|BIGINT|PK, AUTO_INCREMENT|预约 ID|
|reservation_no|VARCHAR(50)|NOT NULL, UNIQUE|预约编号|
|user_id|BIGINT|NOT NULL, FK|申请人 ID|
|device_id|BIGINT|NOT NULL, FK|设备 ID|
|start_time|DATETIME|NOT NULL|预约开始时间|
|end_time|DATETIME|NOT NULL|预约结束时间|
|purpose|VARCHAR(255)|NOT NULL|使用目的|
|description|TEXT|NULL|申请说明|
|status|TINYINT|NOT NULL|审批状态|
|applicant_role|TINYINT|NOT NULL|申请时用户角色快照|
|applicant_level|TINYINT|NOT NULL|申请时用户等级快照|
|device_level_snapshot|TINYINT|NOT NULL|申请时设备等级快照|
|required_teacher_level_snapshot|TINYINT|NULL|申请时最低教师等级快照|
|teacher_approver_id|BIGINT|NULL, FK|教师审批人 ID|
|admin_approver_id|BIGINT|NULL, FK|实验室管理员审批人 ID|
|teacher_approve_opinion|VARCHAR(255)|NULL|教师审批意见|
|teacher_approve_time|DATETIME|NULL|教师审批时间|
|admin_approve_opinion|VARCHAR(255)|NULL|实验室管理员审批意见|
|admin_approve_time|DATETIME|NULL|实验室管理员审批时间|
|reject_reason|VARCHAR(255)|NULL|驳回原因|
|cancel_time|DATETIME|NULL|取消时间|
|finish_time|DATETIME|NULL|完成时间|
|create_time|DATETIME|NOT NULL|创建时间|
|update_time|DATETIME|NOT NULL|更新时间|

## 业务规则

1. 普通设备预约进入 `PENDING_ADMIN`。
    
2. 贵重设备和核心设备预约进入 `PENDING_TEACHER`。
    
3. 教师通过后，状态变为 `TEACHER_APPROVED`。
    
4. 实验室管理员最终确认后，状态变为 `APPROVED`。
    
5. 用户取消后，状态变为 `CANCELLED`。
    
6. 使用结束后，状态变为 `FINISHED`。
    
7. 普通设备预约无需填写 `teacher_approver_id`。
    
8. 贵重设备和核心设备预约必须填写 `teacher_approver_id`。
    
9. 申请时必须保存用户等级和设备等级快照，避免后续规则变更影响历史记录。
    
10. 预约记录不做逻辑删除，作为历史业务凭证长期保留。
    

## 设备预约冲突判断

同一设备在同一时间段内不能存在冲突预约。

冲突判断条件：

```text
device_id 相同
AND status IN (PENDING_ADMIN, PENDING_TEACHER, TEACHER_APPROVED, APPROVED)
AND start_time < 新预约结束时间
AND end_time > 新预约开始时间
```

说明：

1. `REJECTED`、`CANCELLED`、`FINISHED` 不参与新预约冲突判断。
    
2. `PENDING_ADMIN`、`PENDING_TEACHER`、`TEACHER_APPROVED` 建议参与冲突判断，避免多个待审批申请竞争同一时段。
    
3. 后端必须在事务中执行冲突校验和预约插入。
    

## 并发控制规则

设备预约提交时，后端建议先锁定设备行：

```sql
SELECT *
FROM lab_device
WHERE id = ?
FOR UPDATE;
```

然后在同一个事务中执行：

1. 校验设备存在。
    
2. 校验设备状态为可预约。
    
3. 校验预约时间合法。
    
4. 校验预约时长合法。
    
5. 校验预约冲突。
    
6. 插入预约记录。
    

后端事务伪代码：

```java
@Transactional
public void createReservation(CreateReservationDTO dto) {
```

## 业务规则

1. 普通耗材申请进入 `PENDING_ADMIN`。
    
2. 特殊耗材申请进入 `PENDING_TEACHER`。
    
3. 教师审批通过后，状态变为 `TEACHER_APPROVED`。
    
4. 实验室管理员确认通过后，状态变为 `APPROVED`，并扣减库存。
    
5. 驳回后，状态变为 `REJECTED`。
    
6. 普通耗材申请无需填写 `teacher_approver_id`。
    
7. 特殊耗材申请必须填写 `teacher_approver_id`。
    
8. 实验室管理员最终确认前，需要再次校验库存是否充足。
    
9. 申请记录必须保存申请时的库存、比例和额度快照。
    
10. 耗材申请记录不做逻辑删除，作为历史业务凭证长期保留。
    

## 百分比额度判断

系统根据申请人等级对应的 `max_material_percentage` 判断是否超额：

```text
quota = floor(material.current_stock × applicant_level_rule.max_material_percentage)
```

规则：

1. 如果 `current_stock = 0`，不允许提交申请。
    
2. 如果 `quota < 1`，普通申请额度按 1 个单位处理。
    
3. 如果 `apply_quantity <= quota` 且 `dangerous_level = 0`，则为普通申请。
    
4. 如果 `apply_quantity > quota` 或 `dangerous_level = 1`，则为特殊申请。
    
5. 申请提交时保存 `stock_at_apply`、`quota_at_apply`、`percentage_at_apply`。
    
6. 后续规则变更不影响历史申请记录。
    

## 耗材审批资格判断

教师审批资格判断基于申请提交时的快照：

```text
teacher.level 对应的 max_material_percentage 能覆盖 apply_quantity
AND teacher.level 对应的 max_dangerous_level >= material_dangerous_level_snapshot
```

其中“能覆盖申请数量”建议使用申请时库存快照计算：

```text
teacher_quota = floor(stock_at_apply × teacher_level_rule.max_material_percentage)
```

如果 `teacher_quota < 1`，按 1 处理。

# 6.8 耗材库存流水表：material_stock_record

## 字段设计

|字段名|类型|约束|说明|

|id|BIGINT|PK, AUTO_INCREMENT|流水 ID|

# 9. 关键业务校验规则

## 9.1 登录与权限

1. 用户必须登录后才能访问业务接口。
    
2. 学生只能访问个人申请、设备列表、耗材列表和公告。
    
3. 教师只能审批分配给自己的申请。
    
4. 实验室管理员负责设备、耗材、公告和业务确认。
    
5. 系统管理员负责用户、角色、等级规则和操作日志。
    
6. 实验室管理员不允许查看系统操作日志。
    

---

## 9.2 设备预约提交校验

提交设备预约时需要校验：

1. 设备存在。
    
2. 设备未逻辑删除。
    
3. 设备状态为可预约。
    
4. 当前预约时间在设备开放时间内。
    
5. 开始时间早于结束时间。
    
6. 预约时长不小于 `min_reserve_duration`。
    
7. 预约时长不超过 `max_reserve_duration`。
    
8. 同一设备同一时间段不存在冲突预约。
    
9. 如果设备为贵重或核心设备，需要选择具备审批资格的教师。
    
10. 保存申请人角色、申请人等级、设备等级、教师等级要求快照。
    

---

## 9.3 设备预约教师审批资格校验

```text
teacher.role = TEACHER
AND teacher.status = 启用
AND teacher.level >= required_teacher_level_snapshot
```

说明：

1. 使用预约提交时保存的 `required_teacher_level_snapshot`。
    
2. 不使用设备表当前值重新判断历史申请。
    
3. 教师只能审批分配给自己的预约。
    

---

## 9.4 耗材申请提交校验

提交耗材申请时需要校验：

1. 耗材存在。
    
2. 耗材未逻辑删除。
    
3. 耗材状态为正常。
    
4. 当前库存大于 0。
    
5. 申请数量大于 0。
    
6. 根据申请人等级计算普通申请额度。
    
7. 根据耗材危险等级和申请数量判断申请类型。
    
8. 普通申请进入 `PENDING_ADMIN`。
    
9. 特殊申请进入 `PENDING_TEACHER`。
    
10. 保存库存、比例、额度、危险等级快照。
    

---

## 9.5 耗材申请类型判断

```text
quota = floor(material.current_stock × applicant_level_rule.max_material_percentage)
```

判断规则：

1. `current_stock = 0`：不允许申请。
    
2. `quota < 1`：普通申请额度按 1 计算。
    
3. `dangerous_level = 0` 且 `apply_quantity <= quota`：普通申请。
    
4. `dangerous_level = 1` 或 `apply_quantity > quota`：特殊申请。
    

---

## 9.6 耗材教师审批资格校验

```text
teacher.role = TEACHER
AND teacher.status = 启用
AND teacher_level_rule.max_dangerous_level >= material_dangerous_level_snapshot
AND teacher_quota >= apply_quantity
```

其中：

```text
teacher_quota = floor(stock_at_apply × teacher_level_rule.max_material_percentage)
```

如果 `teacher_quota < 1`，按 1 计算。

---

## 9.7 耗材出库校验

实验室管理员最终确认出库前需要再次校验：

1. 耗材仍然存在。
    
2. 耗材未逻辑删除。
    
3. 耗材状态为正常。
    
4. 当前库存大于等于申请数量。
    
5. 审批状态符合确认条件。
    
6. 确认后扣减库存。
    
7. 扣减后生成库存流水。
    
8. 如果库存低于或等于预警值，则触发库存预警。

## 10.3 耗材最终确认事务

耗材最终确认必须使用事务。

推荐流程：

```text
开启事务
锁定申请记录
校验申请状态
原子扣减库存
更新申请状态
插入库存流水
提交事务
```

推荐原子扣减 SQL：

```sql
UPDATE lab_material
SET current_stock = current_stock - ?
WHERE id = ?
  AND current_stock >= ?
  AND status = 1
  AND deleted = 0;
```

后端必须判断影响行数：

```java
if (affectedRows == 0) {
    throw new BusinessException("库存不足或耗材不可用");
}
```

本版解决了 v0.1 中的主要风险：

1. 增加了设备预约并发控制方案。
    
2. 增加了耗材库存原子扣减方案。

6. 增加了操作日志追踪字段。
    
7. 优化了核心查询索引。
    
8. 明确了实验室管理员不能查看操作日志。
    
9. 明确了业务表不删除、流水表不修改的审计原则。

因此，本版本可以作为后续生成 MySQL 建表 SQL 的直接依据。
